# BELTFED 참고 HUD 시안 적용 계획

작성: 2026-09-27. 대상은 원본 프로젝트의 `StartRegionSandbox`와 같은 `OpenWorldHud`를 쓰는 오픈월드 씬이다. 이 문서는 **구현 지침**이며 현재 적용·검증 완료 보고가 아니다. 게임 빌드나 실제 Unity UI 변경은 이 문서 작성 범위에 없다.

시각 기준: [일반·미니맵 상단](References/BELTFED_UI_시안_v2.png), [건물 선택·강화](References/BELTFED_UI_시안_v3_강화패널.png), [수정·설치 홀로그램](References/BELTFED_UI_시안_v4_설치.png). 각 그림의 자원·전력·시간·성능 숫자는 배치 예시다. 정확한 셀 수·비용·성장 규칙의 근거로 쓰지 않는다. [시안 설명](References/BELTFED_UI_시안.md)과 [BELTFED 공식 화면](https://store.steampowered.com/app/4879420/BELTFED__Roguelike_Factory_Defense/)을 참고하되 원작의 에셋, UI 형태, 컨베이어·탄약·카드 규칙을 복제하지 않는다.

## 1. 이 작업에서 확정할 범위

- 기존 기능을 새 HUD에 연결한다: 낮/밤 시계, 자원, **선택 기지의 전력**, 메인 기지 체력, 미니맵, 건물 카탈로그, 수정·확정·취소, 선택 건물 정보·강화, 맵 에너지·오브 제작, 안전 저장·이어하기·새 게임, 개발자 제어.
- 미니맵을 테스트 패널에서 분리해 우측 상단 독립 패널로 둔다. 미니맵 아래에는 선택한 건물이 있을 때만 상세 패널을 연다.
- 수정 중 기존 중립 월드 격자는 옅게 유지하고, **가동 범위**에 한해 푸른 셀 홀로그램을 표시한다. 배치 미리보기·예약·불가 사유는 별도로 표시한다.
- 현재 상단·하단 접기/펼치기, 기존 카메라·배치 입력 차단, 배치/회수 트랜잭션과 저장 가능 시점은 유지한다. 게임 규칙을 UI 재배치 때문에 바꾸지 않는다.
- 게임 UI는 Unity UI Toolkit(UXML/USS)으로 저작하고 지형 위 셀 홀로그램은 월드 메시/머티리얼로 그린다. UI Toolkit 사각 요소를 지형에 투영하지 않는다.

현재 `OpenWorldHud`의 `upgrade` 버튼은 선택 건물이 `IUpgradeControl`을 제공할 때 활성화되고, 강화 명령은 `UpgradePurchase`가 처리한다. 이 명령을 상세 패널로 옮겨도 저장 요청과 실패 메시지 처리를 보존해야 한다. 현재 비용 정책은 `VerificationFreeUpgrade`다. 비용표 미설정을 무료로 해석하지 않는다.

## 3. 화면 상태와 표시 규칙

| 상태 | 항상 보이는 정보 | 조건부 정보·명령 |
|---|---|---|
| 일반/낮·밤 | 메인 기지 체력, 기존 반원형 시계, 날짜·전환까지 시간, 선택 기지 전력, 주요 자원, 우상단 미니맵, 하단 카탈로그의 접기 손잡이 | 카탈로그에서 건물을 누르면 지금처럼 수정 진입 안내를 한다. 전투/패배 상태는 현재 진행 제어기가 정한 가능 명령만 활성화한다. |
| 일반/건물 선택 | 위 항목 | 미니맵 아래에 이름·레벨·체력·가동/비작동 사유·해당 모듈의 실제 성능·소속 기지·전력 연결을 표시한다. 공격 건물의 사거리 원은 현재처럼 이때만 보인다. 선택 해제/파괴/회수 완료 시 닫는다. |
| 일반/강화 가능 | 선택 상세 | `현재 Lv → 다음 Lv`, 현재 `검증용 무료`, 강화 버튼을 표시한다. 실제 강화 명령만 상태를 바꾸고 성공 후 표시·자동 저장 요청을 갱신한다. |
| 일반/강화 불가 | 선택 상세 | 최대 레벨, 메인 레벨 제한, 비활성·파괴, 패배·복원 차단, 향후 비용 부족 등 **읽기 전용 판정 사유**를 문장으로 보이고 버튼을 비활성화한다. 판정 확인용으로 `TryUpgrade()`를 호출하지 않는다. |
| 수정/도구 미선택 | 시계·자원·지도·카탈로그 | 중립 격자, 푸른 가동 영역, `수정 중`, 임시 작업 개수, `확정`·`취소`. 강화 패널은 숨긴다. |
| 수정/건물 선택·미리보기 | 위 수정 상태 | 점유할 칸 전체와 설치 결과를 표시한다. `가동 가능`, `설치 가능 · 비작동`, `설치 불가: 사유`를 색과 문장/패턴으로 함께 구분한다. 방벽 시작·끝 두 번 클릭과 사각 회수 드래그 규칙을 유지한다. |
| 수정/예약·회수 예정 | 위 수정 상태 | 임시 설치와 회수 예정의 외형을 구별한다. 확정 전 기존 건물의 점유·기능은 유지한다. 확정 실패 시 예약/선택을 보존하고 이유를 보여준다. |
| 패배·복원 일시정지 | 현재 진행 상태 | 저장/강화/편집 차단 이유와 가능한 `계속 진행` 또는 `새 게임`을 명확히 보여준다. 패배 진행의 이어하기를 노출하지 않는다. |

시안의 `-` 성능 값은 실제 화면에서 그대로 남기지 않는다. `WeaponRuntime`이 있으면 피해·사거리·간격, `ITurretRotation`이 있으면 회전 속도, `HealthModule`이 있으면 체력처럼 **존재하는 기능만 행으로 생성**한다. 기능 없는 건물은 빈 통계 영역 없이 배치/회수/선택이 가능해야 한다. 화면의 기지 전력은 선택 기지 또는 현재 연결 기지를 명시해 여러 기지의 잔고를 하나로 오해하지 않게 한다.

## 4. HUD 배치와 기존 기능 보존

1. 좌상단에 메인 기지 체력과 반원형 낮/밤 시계를 둔다. 상단 중앙에는 날짜·낮/밤·남은 시간만 놓아 시계 진행률을 중복하지 않는다. 시계·상단 상태는 접을 수 있다.
2. 상단에는 선택 기지의 전력 잔량/용량과 생산·요청·실제 소비를 공간에 맞게 요약한다. 상세 수치는 펼쳤을 때 확인한다. 자원 목록은 카탈로그의 자원 ID/표시명을 읽고 주요 항목만 기본 노출한다. **어떤 자원을 기본 노출할지는 미정**이므로 설정 가능한 표시 우선순위를 두고, 미설정이면 전체 목록에 접근할 수 있게 한다. 재고 0만 이유로 자원을 숨기지 않는다.
3. 우상단은 미니맵과 접기 버튼, 그 아래는 조건부 선택 상세·강화 패널이다. 지도는 기존처럼 북쪽·기지/건물/적·카메라 영역과 클릭/드래그 이동을 유지한다. 지도와 상세 패널의 최대 높이는 하단 카탈로그보다 위에서 끝나게 한다.
4. 하단은 카탈로그 데이터로 만든 방어·자원·기타·설치 순서와 기존 접기 상태를 유지한다. 일반 상태에서는 `수정`, 수정 중에는 `확정`·`취소`가 명확히 보인다. 확정/취소 후의 상태 복귀는 현재 `OpenWorldInput` 계약을 따른다. 건설/강화 비용과 아이콘이 없는 항목에 임의 숫자·이미지를 넣지 않는다.
5. 안전 저장·이어하기·확인 후 새 게임, 맵 에너지/오브 제작은 **플레이 기능**이므로 테스트 패널에 묻지 않는다. 상단 진행/메뉴의 접이식 영역에서 기존 명령·저장 불가 이유·마지막 저장 시각에 접근할 수 있게 한다. 개발자 소환, 날짜 강제 전환, 적 초기화, 검증 통계는 별도 접이식 개발자 패널로 옮긴다. 개발자 기능의 빌드 노출 정책은 현재 조건을 유지한다.
6. 시간 조작은 현재 구현된 정지/재개만 노출한다. 시안의 배속 아이콘을 구현 없이 만들지 않는다. 현재 `run`과 `clock-pause`는 서로 다른 경로이므로 실제 플레이 버튼의 상태·명령은 하나의 진행 상태 어댑터에서 결정하고 개발자 전투 실행은 분리한다. 기존 밤/전투·수정 중 동결 동작을 바꾸지 않는다.

패널은 16:9 기준으로 설계하되 고정 픽셀 배치만으로 끝내지 않는다. 1366×768, 1920×1080, 2560×1440 및 넓은 화면에서 겹침·문자 잘림·접은 뒤 재배치를 확인한다. UI Toolkit의 flex와 명시적 USS 클래스를 사용하고 게임 조작 요소의 포커스/포인터 처리는 현재 Input System 규칙에 맞춘다.

## 5. 지형 위 푸른 셀 홀로그램

**의미:** 파란색은 `기지/특수 영역 제공자가 보장하는 가동 영역`이다. 현재 규칙에서는 유효 지면의 범위 밖 설치도 가능하지만 그 건물은 비작동이다. 따라서 파란색을 전역 `설치 허용` 표시로 부르지 않는다. 배치 타당성은 `PlacementSession.Validate`와 기존 지형·점유 검사 결과를 따로 읽는다.

- 메인 기지는 [정면 가장자리부터 앞쪽 11×11셀, 2m 셀, Y축 45°](고정_메인기지_플레이루프_적용결과.md)를 그대로 사용한다. 뒤쪽으로 칠하지 않고, 정확한 121셀 및 홀짝 폭 정렬을 검증한다. 시안 이미지의 투시 표현으로 셀 수를 판정하지 않는다.
- 확정·활성 기지와 영역 제공자만 홀로그램의 근거가 된다. 임시 배치 건물은 확정 전까지 기존 영역을 늘리지 않는다. 회수 예정 기지는 확정 전까지 영역을 유지한다. 파괴·확정 회수·레벨 변화 후에는 영역을 갱신한다.
- 표시 자료는 `IBuildArea`의 `Boundary`/`Contains`와 `IBuildAreaGeometry`의 중심·좌표 변환, `WorldGridGeometry`의 격자 좌표를 사용한다. **시각과 실제 설치/가동 판정을 별도 수식으로 복제하지 않는다.** 여러 영역이 겹치면 셀을 한 번만 그리되 선택 정보에는 소속 기지를 유지한다.
- 각 셀은 낮은 불투명도의 푸른 면과 얇은 청록 선으로, 전체 외곽은 조금 더 밝게 그린다. 지형 높이를 따라 띄우고 절벽/강/맵 밖 등 설치 불가 셀은 푸른 면만으로 `설치 가능`처럼 보이지 않게 차단 패턴 또는 미리보기 오류 사유를 더한다. 물리 충돌과 그림자에는 참여하지 않는다.
- 중립 월드 격자와 홀로그램은 **수정 중에만** 켠다. 확정·취소·패배·씬 종료 시 끄고 관련 메시/머티리얼 리소스를 정리한다. `WorldGridView`의 9개 재사용 청크 원칙을 유지하며 모든 셀마다 GameObject나 `VisualElement`를 만들지 않는다. 보이는 영역/변경된 영역에 대해서만 메시를 재생성하고 카메라가 멈춘 동안에는 상시 할당·재생성을 피한다.
- 현재 `ContentBuildingView.ShowBuildArea`의 청록 외곽선과 새 홀로그램 외곽선이 같은 위치에 겹쳐 두꺼워지지 않게, 수정 중에는 어느 하나만 외곽을 그리는 표시 소유권을 정한다. 일반 상태의 선택 사거리 원과 영역 외곽선도 서로 다른 의미로 유지한다.
- 배치 미리보기는 건물 전체 점유 칸을 강조한다. **파랑/청록 + `가동 가능`**, **주황 + `설치 가능 · 비작동`**, **빨강/빗금 + `설치 불가: 이유`**로 표시한다. 색상에만 의존하지 않는다. 예약 충돌·경사·토대/지면 제한·보스 예약 구역을 실제 검증 이유와 일치시킨다.

확장 규칙은 이 작업에서 정하지 않는다. 기존 메인 영역은 고정, 서브 기지는 현재 콘텐츠 설정의 레벨별 영역, 특수 영역 제공자는 등록된 설정을 그대로 따른다. 이후 성장 수치·상한·새 지역 정책이 확정되면 데이터가 바뀐 결과를 렌더링한다. 영역을 늘리기 위한 새 강화 효과나 경제 비용을 UI 작업 중 임의로 추가하지 않는다.

## 6. 모듈 경계와 구현 순서

1. **읽기 전용 HUD 상태:** 시간, 자원, 선택 기지 전력, 진행, 저장 가능 이유, 선택 건물 성능·강화 상태를 각 기존 소유자에서 수집하는 표시 어댑터를 정리한다. `OpenWorldHud`는 조합·명령 전달만 맡는다. `TryUpgrade`를 호출하지 않고 강화 가능 여부/사유를 조회할 수 있는 읽기 계약을 추가한다. 실제 클릭 때는 기존 `UpgradePurchase.TryUpgrade`가 다시 검증한다.
2. **UXML/USS 재배치:** 기존 `OpenWorldHud`의 요소와 `DayNightDial`, `MinimapElement`를 재사용한다. 중복 시간 표시와 미지원 배속을 없애고, 독립 미니맵·선택 상세·개발자 패널·플레이 메뉴를 저작한다. 접기/펼치기는 작업 상태나 포커스를 임의로 초기화하지 않는다.
3. **입력 연결:** 새 패널의 `worldBound`/포인터 캡처·입력창 포커스를 `OpenWorldHud.Update`의 UI 차단에 포함한다. 지도 위 클릭·드래그·휠은 설치/회수/WASD로 전달되지 않고, 지도 밖 휠은 기존 줌 규칙을 따른다. 패널을 접으면 숨겨진 영역은 차단에서 제외한다.
4. **홀로그램 월드 표현:** 기존 `WorldGridView`는 중립 격자로 두고, 영역 셀 채움/외곽 전용 렌더러를 추가한다. 영역 제공자의 생성·제거·레벨 변경과 수정 상태 전환에서 갱신을 요청한다. 선택한 건물의 배치 결과와 회수 예정 표시는 기존 트랜잭션의 읽기 상태에서 만든다.
5. **회귀 검증과 문서 갱신:** 새 HUD 상태별 화면과 실제 클릭·드래그·저장·강화·건설·회수·일시정지를 검증한다. `README.md`, `Docs/README.md`, 기존 적용 상태 문서는 실제 구현·검증 결과에 맞춰 그때 갱신한다. 이 계획 문서만으로 적용 완료라고 표기하지 않는다.

## 7. 검증 기준

- 메인 기지 영역은 정면 **정확히 121셀**만 홀로그램으로 표시되고 실제 영역 판정과 일치한다. 45° 회전, 절벽/강/경계, 다중 기지 중첩·레벨 변화·기지 파괴/회수에서 누락·잔상이 없다.
- 수정 상태 진입/취소/확정 시 중립 격자와 홀로그램이 함께 보이거나 숨는다. 수정 버튼 재클릭과 명시 취소는 임시 배치·회수 예약을 모두 취소하고 기존 확정 건물은 유지한다. 확정 실패는 예약과 오류를 남긴다.
- 범위 밖 유효 지면은 설치 가능·비작동으로 표시되고, 지형/점유 충돌은 설치 불가로 표시된다. 임시 건물은 영역을 넓히지 않으며 회수 예정 영역 제공자는 확정 전까지 영역을 유지한다.
- 비선택/포탑/내구도만 있는 건물/기지/자원 건물에서 상세 행이 실제 모듈과 일치한다. 선택 건물이 파괴·회수되면 패널과 사거리 표시가 사라진다. 기능 없는 건물도 선택·배치·회수 가능하다.
- 강화 가능/최대 레벨/메인 레벨 제한/편집 중/패배·복원 차단 상태의 버튼과 이유가 실제 `UpgradePurchase` 결과와 일치한다. 실제 콘텐츠는 `검증용 무료`이고, 강화 성공 시 1회만 적용·자동 저장 요청된다. 향후 비용표 미설정은 무료로 보이지 않는다.
- 미니맵을 우상단으로 옮겨도 클릭·드래그 이동, 북쪽, 카메라 범위, 적 밀집 표시, 줌 보존, 접기 시 갱신 생략이 유지된다. 미니맵·상세 패널·하단 탭 위 입력은 월드 배치·회수로 전파되지 않는다.
- 저장 불가 이유와 마지막 저장 시각, 새 게임 확인, 오브 제작, 개발자 소환·날짜 전환은 이동 후에도 접근 가능하다. 기존 저장 포맷·패배 기록·진행 제어는 변경하지 않는다.
- Unity Editor UXML/USS import·컴파일, Play 화면, 현재 `VerifyHudFolds`, `VerifyMinimap`, `VerifyBuildingInventoryUI`, `VerifyWorldGridVisibility`, `VerifyStartLoop`에 해당하는 검사 및 새 홀로그램/강화 상태 검사를 통과한다. 게임 빌드는 별도 요청 전까지 수행하지 않는다.

## 8. 아직 기획이 필요한 항목

- 기본 자원 목록에서 항상 보일 자원의 우선순위와 아이콘 세트.
- 기지/전초 영역의 최종 성장·상한·확장 비용, 영역 중첩 시 플레이어에게 보여줄 소속 설명.
- 최종 건설/강화 비용표와 강화 전후 수치 강조 방식.
- 야간 공세·패배·저장 메뉴의 최종 시각 연출. 현재는 작동 기능과 접근성부터 보존한다.

위 미정 항목이 없어도 **현재 규칙을 그대로 표시하는 HUD 재배치와 홀로그램 1차 구현**은 진행할 수 있다.
