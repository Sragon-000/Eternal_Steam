# 개발일지

## 갱신 기준

작업 단위가 끝날 때 같은 날짜의 일지에 변경 목적·실제 반영 내용·검증 결과·근거 경로·실패 및 해결·남은 작업을 추가한다. 코드 작성, Unity 적용, 실제 실행 검증, GitHub 게시는 서로 구분한다. 미실행 항목을 통과로 기록하지 않는다.

검증 수가 달라지면 이전 결과를 지우지 않고 변경 이유와 최신 결과를 덧붙인다. 게시 시 커밋과 원격 확인 결과를 기록하고, 진행 상태가 바뀌면 연결된 계획·검증 문서도 함께 갱신한다. 데이터 수집이나 실험은 목적과 실제 실행 여부를 명시한다.

진행 중 회차는 날짜별 일지 상단에 마지막 검증 시점을 표시하고, 그 시점의 고정 체크포인트에 연결한다. 실시간 상태 파일은 계속 바뀌므로 완료 증거로 삼지 않는다. 작업마다 코드·문서·검증 자료·일지·GitHub 게시 범위를 대조하며, 게시하지 않은 진행 중 원본과 최종 감사가 남은 항목을 적는다.
