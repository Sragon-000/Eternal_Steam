# 레거시 전투 분리

2026-09-14. 기존 전투의 적 관리·피해 판정·포탑 공격 진행·표현을 분리했다. 기존 세 씬과 공개 HUD 명령, 저장 키, 포탑 수치는 유지한다. 개발 의존성의 분리이며 플레이어에게 모듈 선택 기능을 추가한 것이 아니다.

## 책임과 의존성

| 구현 | 위치 / 역할 |
|---|---|
| `HordeEnemyWorld` | `Code/LegacyDemo/Combat`: 4,000 슬롯 배열, 빈 슬롯 재사용, 고정 시드 생성, 이동·감속, 공간 인덱스, 체력·처치·통과 상태 |
| `HordeAttackResolver` | 같은 Combat 어셈블리: 기존 사선 선택·관통·부채꼴 감속·범위 피해. 시뮬레이션이나 시각 개체를 참조하지 않음 |
| `HordeTowerCombat` | `Code/LegacyDemo/Buildings`: 기존 포탑별 쿨다운·발사 순서·공격 호출을 연결하는 호환 어댑터 |
| `HordeTowerEffects` | 같은 Buildings 어셈블리: 트레이서·범위 연출의 정점과 표시 시간. 포탑 표현 자료형을 소유한 어셈블리에 위치 |
| `HordeEnemyRenderer` | `Code/LegacyDemo/Presentation`: 일반·감속 그룹의 500개 행렬 버퍼와 GPU 인스턴싱, 감속 재질 수명 |
| `HordeSimulation` | 구성 지점, 갱신 순서, 출현 예산·스테이지·보상 연결, 기존 UI 명령 유지 |

`EternalSteam.LegacyCombat`은 프로젝트 내부에서 `EternalSteam.LegacyDefinitions`만 참조한다. Buildings와 Presentation이 Combat을 사용하며, 역방향 참조는 금지한다. 공통 기반의 `EternalSteam.Combat`과 구분한다. 기존 무조건 연사와 공통 기반의 타겟 유지 공격은 서로 다른 규칙이다.

적 배열은 Combat 어셈블리 내부에 한 번 생성하고 조회 측에는 `ref readonly Enemy`를 제공한다. 렌더러가 적 상태를 변경하지 않는다. 피해·감속은 전투 모듈에서 처리한다. 적당 MonoBehaviour, 전역 서비스 탐색, 범용 이벤트 버스를 추가하지 않았다. 패배 통지는 구성 지점에서 구독하고 파괴 시 해제한다.

포탑 공격 어댑터는 아직 기존 `HordeTower`와 enum을 사용한다. 기존 네 공격의 호환 연결을 담당하며 범용 건물 모듈에 이 enum을 확산시키지 않는다. 카탈로그와 데이터 이전은 다음 단계다.

## 보존한 동작

- 준비 중 공격하지 않고, 전투 중에는 적 없이도 연사한다.
- 설치 순서에 따른 최초 지연, 발사 간격, 한 갱신당 최대 한 발, 기존 황금비 기반 산탄 방향을 보존한다.
- 기관총 사선의 먼 경계 제외, 화살 사선의 먼 경계 포함 등 기존 공격별 판정을 그대로 유지한다.
- 냉각포는 피해 없이 2.5초 감속하며 프레임 중 감속 종료 시간을 나눠 이동량을 계산한다.
- 포탄은 첫 사선 대상 위치 또는 최대 사거리 지점에서 반경 3의 피해를 준다.
- 통과는 체력을 1 줄이고 체력 0에서 이동을 중단한다. 리셋은 배치를 유지하며 전투 상태·연출을 초기화한다.
- 실제 적 인덱스와 렌더링은 기존 배열·연결 인덱스·인스턴싱을 사용한다. Reset은 공간 인덱스도 비워 이전 전투의 연결을 남기지 않는다.

기존 CLI 도구의 private 진입점은 얇은 위임 메서드로 유지했다. 배열을 직접 수정하는 역사적 도구 세 개는 소유자가 EnemyWorld로 바뀐 점만 반영했다. 이 진단용 reflection은 제품 코드의 공개 변경 API가 아니다. `VerifyPrototypeLoop`는 출격 뒤 HUD 프레임 갱신을 기다리도록 수정했다.

## 검증과 남은 성능 범위

[검증 결과](Validation/레거시_전투_분리_검증.md)에 테스트와 3회 비교를 기록한다. 제어된 전투 갱신·렌더 제출의 CPU와 GC 비교는 완료했다. 이후 [Editor 실제 프레임 CPU·GC 비교](Validation/Editor_프레임_측정.md)를 빌드 없이 3회씩 완료했다. 10% 초과 악화와 프레임 GC 중앙값 증가는 없었다. GPU 카운터는 유효 샘플이 부족해 미판정이며 Standalone 빌드는 사용자 요청으로 이번 범위에서 제외했다.

다음 개발 순서는 맵·스테이지·포탑 카탈로그와 고정 UI 개수 이전이다. 빌드는 별도 요청 전까지 실행하지 않는다. 콘텐츠 수치나 기존 저장 구조는 그 전에 변경하지 않는다.
