# HUD 시안 2단계: 레이아웃·입력 연결

후속 기준 변경: [Canvas·실제 Hierarchy 이관](2026-09-28-canvas-hierarchy.md)을 우선한다. 이 문서는 이관 이전 단계의 기록이다.

2026-09-28. 원본 프로젝트에 [준비 문서](../BELTFED_UI_실제적용_준비.md)의 P2를 코드로 반영했다. **C# 컴파일·정적 연결 확인 완료, Unity import/Play/해상도별 화면·입력 검증 대기**다. 이번 작업에서 씬·프리팹·콘텐츠·저장 포맷은 바꾸지 않았다. 게임 빌드와 P3 셀 홀로그램은 포함하지 않는다.

## 화면과 데이터 연결

- 기존 `Shared/UI/OpenWorld/OpenWorldHud.uxml/.uss`를 수정했으므로 같은 UIDocument를 쓰는 시작 씬과 오픈월드 씬에 연결된다. 새 씬 생성/교체 도구를 실행할 필요가 없다.
- 좌상단 메인 기지의 실제 현재/최대 체력과 체력 바, 좌측 기존 낮/밤 시계·자원 목록을 배치했다.
- 상단 날짜/전환까지 시간/진행 상태와 기지 전력을 분리했다. 전력은 연결 기지 우선·선택 기지 fallback을 유지하고 이름/식별자를 표시한다. 상세 접기 안에서 생산·요청·실제 소비, 메인 레벨·서브 수/한도·다음 배치 기지를 확인한다.
- 우상단 미니맵을 개발자 패널에서 분리했다. 지도 아래 선택 상세는 일반 상태에서 활성 건물을 선택했을 때만 열린다. 선택 해제·파괴·편집 진입 시 숨긴다.
- `SelectedBuildingView`가 존재하는 체력·무기·회전·영역 모듈만 행으로 표시한다. 없는 기능에 임의 수치나 `-`를 채우지 않는다. 소속·지역과 전력 연결 정보도 기존 소유자에서 읽는다.
- 저장·이어하기·확인 후 새 게임·에너지/오브 제작은 접이식 **진행 · 저장** 메뉴, 소환 수량·적 초기화·통계·날짜 강제 전환은 별도 **개발자** 패널로 옮겼다. 두 메뉴는 기본 접힘 상태다. 기존 `clock-dev` 빌드 노출 조건은 유지했다.
- 시작 씬은 상단 진행 버튼 하나를 표시하고, Assault 없는 검증 씬의 별도 전투 실행 버튼만 개발자 패널에 남겼다.
- 하단 카탈로그의 기존 분류/목록 생성과 접기 시 선택/분류 보존을 유지했다. 수정 중 명시적 **확정·취소**를 표시한다. 취소 버튼은 `OpenWorldInput.Cancel()`을 호출하며 수정 재클릭 취소도 유지한다. 메시지는 카탈로그를 접어도 화면 하단에서 읽을 수 있다.
- 자원 목록은 생산 OutputId 중복을 제거하고 0 재고도 표시한다. `OpenWorldHud.ResourcePriority`에 ID 배열을 설정하면 해당 순서의 주요 자원과 전체 보기 전환을 제공한다. 기본 빈 배열이나 일치하지 않는 설정에서는 전체 목록을 표시한다. 기본 자원 종류·아이콘·비용을 임의로 정하지 않았다.

## 레이아웃·입력 구현

상단/중앙/하단을 flex로 쌓고 중앙은 좌측·빈 월드 공간·우측 열로 나눴다. 우측 지도·상세는 카탈로그 위의 제한된 높이를 공유하고 상세/메뉴/자원 본문에 스크롤을 제공한다. 루트의 논리 크기가 높이 760 미만 또는 폭 1200 미만이면 `compact` 클래스로 지도·시계·카탈로그를 줄인다. 기존 SamplePanel의 기준 해상도는 변경하지 않았다.

`OpenWorldHud.IsPointerOverHud`가 panel.Pick으로 실제 포인터 아래 요소의 `hud-surface` 조상을 확인한다. 숨겨진 패널은 제외하고 배경 없는 레이아웃 컨테이너는 picking을 무시한다. 카탈로그를 접어도 헤더의 수정/확정/취소 입력은 차단한다. 지도 위 WASD/휠과 드래그 캡처도 월드로 전달되지 않게 연결했다. 실제 입력 동작은 아래 Play 검증이 필요하다.

지도는 자체 본문의 표시 상태로 갱신 여부를 결정한다. 개발자 패널 접기에 의존하지 않는다. 지도 접기/분리/Dispose 때 포인터 캡처를 정리하고, 숨긴 상태에서는 건물·적 집계를 생략한다. `ObjectRefreshCount`로 이를 검사할 수 있다. 개발자 패널을 접거나 입력창을 숨기면 수량 편집 포커스도 해제한다.

## 검증 도구 변경과 재개 순서

- `VerifyHudLayout` 신규: 독립 패널 소유/실제 bounds, 선택 메인 상세, 메뉴 입력 차단, 개발자 접기 후 수량 포커스 해제, 카탈로그 접힘 상태의 명시 취소.
- `VerifyHudFolds`: 기본 접힘 여부에 관계없이 6개 접기를 왕복하고 편집 예약 보존 확인.
- `VerifyMinimap`: 개발자 본문이 숨겨져도 지도 갱신, 지도 접기 시 즉시 캡처 해제, 숨김 중 집계 생략 확인 추가. 기존 Main/Input 경로 유지.
- `VerifyBuildingInventoryUI`: 재펼침 시 분류 유지, 실제 카탈로그 기반 기타 분류 개수, 명시 취소의 예약 취소를 검사. 확정/취소가 보이는 편집 상태에서 버튼 순서 검사.
- `VerifyQuantityFocus`, `VerifyOpenWorldCameraInput`: 입력창 검사 전에 개발자 패널을 펼치고 원래 접기 상태를 복원.
- `VerifyResourceStockUI`: 자원 Label의 새로운 스크롤 본문 소속 확인.
- `VerifyBuildingCombatPause`: 분리된 체력 행을 검사.

Editor 실행 환경 복구 후 아래 순서로 실행한다. 제품 저장 대신 [임시 저장 루트](2026-09-24-single-map-save.md)를 사용하고, 씬 구성이 다른 기존 도구를 시작 씬에 무조건 실행하지 않는다.

1. UXML/USS import와 `HudLayoutTests`, `UpgradeQueryTests`, `ArchitectureTests` 실행 결과 XML 확인.
2. StartRegionSandbox 신규 세션에서 `VerifyHudLayout`, `VerifyHudFolds`, `VerifyMinimap.Main/Input` 실행. 레이아웃 도구는 각 목표 해상도에서 반복한다.
3. 도구가 요구하는 기존 검증 씬에서 수량 입력/카메라·카탈로그·생산/전력·전투 체력 회귀 실행.
4. 독립 신규 세션에서 `VerifyStartLoop` 및 저장·강화 회귀 실행. 서로 상태를 변경하는 검사를 같은 오염된 세션에 이어 실행하지 않는다.
5. 각 해상도의 일반/선택/편집/접힘/메뉴 상태를 캡처하고 결과를 이 문서에 보충한다.

다음 구현 단계는 실제 가동 판정과 같은 셀 집합을 사용하는 P3 홀로그램이다. 이번 재배치는 기존 중립 격자·영역 외곽선·배치 미리보기 표현을 그대로 사용한다.
