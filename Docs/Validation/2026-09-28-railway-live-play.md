# 철도 실제 Editor·Play 후속 검증

2026-09-28, Unity 6000.3.14f1. 시작 씬 `StartRegionSandbox`. 기존 비응답 이후 새 Editor 연결에서 실행했다. 사용자 저장 대신 `ETERNAL_STEAM_SAVE_TEST_ROOT`로 `/tmp/eternal-railway-*` 저장소를 사용했다.

검증 도구는 `Tools/VerifyRailwayPlay.cs`, `Tools/VerifyRailwayHud.eval.cs`다. 클래스형 도구는 `Tools/compile_play_check.py`로 Unity 참조와 함께 임시 DLL을 만든 뒤 live eval에서 Main/Reloaded/StoppedReloaded/PrepareMigration/Migrated를 순서대로 실행했다. `.eval.cs`는 명령 본문이므로 eval_file로 실행한다. 테스트 설치 도구가 위치를 찾을 때 기존 지형과 건설 규칙을 사용하며, 게임 콘텐츠를 테스트 목적으로 느슨하게 바꾸지 않았다.

## 발견하고 수정한 부분

- 역을 바꿔도 이전 적재·하역 입력이 남던 문제: 선택 노선/역 변경 때 저장된 값을 입력칸에 표시한다. 사용자가 타이핑한 값은 매 프레임 덮어쓰지 않는다.
- 날짜 패널과 철도 도구막대의 상단 겹침: 실제 Editor에서 두 씬의 도구막대를 y=-84, 상세 패널을 y=-128로 저장했다. 오프라인 저작 도구도 같은 좌표로 맞췄다.
- 정적 검사 도구가 Unity가 정규화한 따옴표 없는 문자열을 거부하던 문제: `rotate` 콜백은 따옴표 유무와 무관하게 확인한다.

## 검증의 한계와 다음 작업

이 결과는 두 기지 핵심 경로의 실제 실행 근거다. 합성 v1은 구버전 계약을 재현한 시험 자료이며 과거 사용자 저장의 모든 변형을 대표하지 않는다. 저장 건물 용량 재구성·손상된 이관 파일 등 추가 이관 사례, 3·4역 순환, 회전 포트, 오류 복구 전체 조합, 키보드/마우스 실제 입력 전수 QA는 남는다. 이번 UI 검사는 명령/콜백과 화면 확인이며 OS 입력 자동화를 수행한 기록은 아니다.

예약 노선 변경(P5), 이동 방어(P6), 최종 비용·아트는 구현 후속이다. P1~P4 인수표의 모든 항목을 완료 처리하거나 전체 4.3/4.4 요구사항 완료로 표시하지 않는다. 멈춤 증상은 이번 실행 중 재발하지 않았으나 원인을 확정하거나 해결했다고 단정하지 않는다.
