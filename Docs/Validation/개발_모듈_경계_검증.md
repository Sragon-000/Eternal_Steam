# 개발 모듈 경계 검증

2026-09-14, Unity 6000.3.14f1, macOS arm64. 원본 Editor와 별도의 임시 프로젝트에서 수행했다.

| 항목 | 결과 |
|---|---|
| Unity 컴파일 | 오류 없음 |
| EditMode | 30/30 통과 — [원시 결과](architecture-editmode.json) |
| PlayMode | 4/4 통과 — [원시 결과](architecture-playmode.json) |
| 공통 기반 의존성 | Runtime의 다른 EternalSteam 어셈블리 참조 없음 |
| 기능 간 의존성 | Combat·Progression·Economy·Movement·Presentation은 각각 Runtime만 참조 |
| 공격 대체 구현 | 강화 없이 독립 IDamageModifier로 피해 배율 적용 |
| 성장 대체 구현 | 독립 ILevelLimit와 IHealthScaling으로 강화 제한·체력 변경 |
| 넥서스 대체 구현 | 기본 HealthModule 없이 IDamageReceiver를 제공하는 모듈로 구성 검사와 실행 성공 |
| 기존 기능 회귀 | 배치·회수·방향·공격·투사체·효과·자원·넥서스·강화·초기화 테스트 유지 |

이동 방벽 소스는 `Code/Placement`에서 `Code/Movement`로 옮기면서 `.meta` GUID를 보존했다. 기존 에셋·씬은 재생성하지 않았다. 테스트는 원래 FoundationSandbox와 ModuleSandbox를 그대로 로드해 수행했다.

이번 변경에서 LegacyDemo 코드·맵·빌드 설정·저장 형식은 수정하지 않았다. 기존 HordeSimulation 분해는 아직 수행하지 않았다. 기존 데모 3개 맵의 수동 회귀와 빌드·대규모 성능 측정은 이번 검증 범위에 포함하지 않는다.
