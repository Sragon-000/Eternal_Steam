# HUD-06A 철도 목록·운행 화면 적용 검증

2026-10-02. 제품 UI 구현·검증이다. 연구 실험은 실행하지 않았다.

## 적용

StartRegionSandbox와 OpenWorldSandbox에 RailwayOverview의 고정 목록 4행, 페이지 이동, 운행 요약, 주요 명령, 기존 상세 화면 진입/복귀 버튼을 저장했다. 모든 버튼은 저장된 영구 콜백을 사용하며 런타임 UI 객체를 생성하지 않는다. 기존 RailwayHud/Network의 운행·결제·예약·저장 규칙을 변경하지 않았다.

1280px 이상은 목록+상세를 함께 표시하고, 그보다 좁으면 목록→상세로 전환한다. 현재/출발 역, 다음 역, 연료, 한글 화물명, 운행 상태, 예약·오류와 비활성 이유를 표시한다. 새 운행 화면의 제목·목록·버튼·안내는 실효 18px로 통일했다. 기존 스프라이트를 사용한다. 긴 안내는 요약 스크롤 영역 안에 둔다.

운행 시작·중지 요청·석탄 보급·예약 취소는 기존 명령에 위임하고 기존 CanExecute 결과를 표시한다. 화물·역 상세, 방어칸, 역 연결 및 노선 편집은 기존 화면으로 연결한다. 기존 상세에는 ‘운행 화면으로’ 복귀를 저장했다. 기존 상세 자체의 전면 재구성은 06B/06C 범위다.

운행 화면을 덮던 선택 상세·첫 회차 안내·일반 메시지는 이 화면이 표시되는 동안 가리고, 좁은 화면에서는 자원 패널도 가린다. 화면 종료 또는 전투 그룹 복귀 시 복원한다. 자원 무한/낮/밤 테스트 버튼은 계속 표시한다.

## 발견·수정 및 검증 한계

초기 저장 테스트는 Legacy CanvasGroup 참조 누락 2건을 발견했다. Unity의 null 비교로 실제 컴포넌트를 추가·저장한 뒤 통과했다. 실패 XML은 `product-tests-before-reference-fix.xml`로 보관했다. 캡처에서 기존 알림이 하단을 가리고 작은 버튼의 세로 여백 때문에 텍스트가 비는 것을 발견해 표시 정책·여백·최대 화면 높이를 수정했다. 예약 객체는 비활성 상태에도 존재하므로 목록 예약 표시는 객체 존재 여부 대신 Network.HasPending을 사용한다.

예약 취소 probe의 최초 실패는 이동을 가정한 시각에 이미 다음 역에 정차한 fixture 조건 때문이었다. 실제 Moving/segmentPaid 상태를 확인한 뒤 검증하도록 도구를 수정했다. 좁은 화면을 활성화한 직후 첫 프레임에 수행한 raycast는 그래픽 등록 전 상태를 읽었다. 후속 프레임에서 실제 버튼이 최상위임을 확인하고 렌더 완료 후 검사하도록 도구를 보정했다.

역 진입 대기와 노선 오류의 표시 검증은 해당 상태 필드를 지정한 UI fixture다. 충돌 경로의 자연 발생까지 검증한 것으로 보지 않는다. 이번 Play 노선은 1개이므로 여러 노선의 페이지 넘김·긴 이름·저장 재로드 통합 인수는 HUD-07에 남긴다. 실제 운행 상태와 명령 검증, 저장 계층 검증, 시각 검증을 구분한다.
