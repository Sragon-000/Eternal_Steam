# Eternal Steam 구조 평가와 성능 최적화

2026년 10월 3일. 사용자가 보고한 전반적인 버벅임을 대상으로 프로젝트 구조, 실제 Unity Editor 프레임, 게임 시뮬레이션, HUD, 건설 격자, 저장 및 콘텐츠 메모리를 점검했다. 가장 큰 확인 원인은 Play 중에도 실행되던 TileWorldCreator의 전체 맵 페인트 Gizmo였다. 이를 제한하고 게임 실행 경로의 반복 작업을 줄였다. 연구 실험은 실행하지 않았다.

## 조사 범위와 구조 평가

프로젝트 C# 197개와 어셈블리 정의 22개를 조사했다. 이 중 테스트 어셈블리는 5개다. 실제 시작 씬은 전체 GameObject 2,390개, Renderer 1,513개, 활성 Renderer 1,137개, Collider 1,462개였다. 수치는 조사 당시 Play 상태이며 기지·철도 생성에 따라 달라진다. 원본 데이터는 `Docs/Measurements/2026-10-03-performance/source-structure.json`, `structure-StartRegionSandbox.json`에 있다.

## 적용 내용

- Play 중 맵 편집용 Gizmo 실행 차단. 게임 테스트 UI `자원 무한`, `낮으로`, `밤으로`는 유지한다.
- `HordeEnemyWorld.ActiveIndices`를 이동, 적 공격 준비, 렌더링, 미니맵 밀도, 소환 간격, 관통 공격에서 사용한다. 표적 탐색 알고리즘 변경이나 연구용 비교 실험은 하지 않았다.
- 공간 인덱스에서 이전 단계에 채운 버킷만 초기화한다. DespawnAll과 Reset은 전체 상태를 명시적으로 초기화한다.
- `WorldGridView`는 기존 저장된 MeshFilter/Renderer를 재사용한다. 런타임 UI·격자 GameObject를 새로 만들지 않는다. 약 3ms는 작업 예산이며 OS 스케줄링·단일 행·메시 업로드 시간을 포함한 절대 상한은 아니다.
- uGUI 구조, 앵커, 글꼴 크기, 원형 미니맵, 150×150 범위, 철도 UI는 유지한다. 카메라·포인터·IME·Tab·Esc 처리를 저빈도로 바꾸지 않는다.

## 측정 방식과 해석

Apple M4 Pro, Unity 6000.3.14f1, StartRegionSandbox, GameView 2560×1440, Scene와 Game을 함께 연 동일 Editor 배치에서 측정했다. 각 화면은 120프레임 준비 후 240프레임을 수집하고 마지막 200개 Profiler 프레임을 분석했다. 자동 저장은 격리 측정 중 껐고 실제 사용자 저장 대신 프로젝트 내부 임시 저장 경로를 사용했다.

최적화 전 전투 화면 중앙값은 82.96ms, 건설 화면은 85.29ms였다. Editor 세부 측정에서 `TileWorldCreatorManager.OnDrawGizmos`의 프레임 평균은 73.78ms였다. Profiler 표의 시간은 부모·자식이 중복된 inclusive 값이므로 항목들을 합산하면 안 된다. 렌더러의 드로 호출 집계 역시 Scene/Game 재그리기 영향을 포함한다.

최종 결과 표와 검증 결과는 아래 완료 기록에 있다. 전체 프레임 개선은 **로컬 macOS Editor**에서 관찰한 결과이며 Standalone 빌드, 다른 GPU/OS, 모든 규모의 월드에 대한 FPS 보장이 아니다. GPU의 독립적인 프레임 시간은 이번 측정으로 확정하지 않았다.

`GC Allocated In Frame`은 Editor를 포함한 프로파일 카운터다. 호출별 보조 측정의 `GC.GetAllocatedBytesForCurrentThread`가 모두 0을 반환했으므로 해당 0을 무할당 증거로 사용하지 않는다. 숨긴 UI의 감소 효과는 실제 Profiler와 실행 경로로 판단한다.

전투 화면 중앙값은 약 90.6% 감소했다. 대부분 Editor 맵 Gizmo 제거 효과이며 실제 게임 로직도 위의 개별 측정만큼 개선됐다. 생존 비트셋은 10만 슬롯에서 약 12.5KB, 사용 버킷 기록은 최대 약 400KB를 추가로 사용한다.

- 최적화 후 기존 검사: EditMode **303/303**, PlayMode **4/4** 통과. 이후 사용자 요청에 따라 테스트를 개편했으며 최종 현행 결과는 **285/285**, 현재 씬 반복 검사 **35/35**다. 두 숫자는 검사 구성 차이이며 기능 18개를 삭제했다는 뜻이 아니다.
- 무작위 3,000회 적 생성/삭제/피해/이동/초기화: 이전 구현과 슬롯 상태·위치·세대·질의 순서 일치(`enemy-parity.json`).
- 기존 9개 격자의 정점/삼각형 배열 완전 일치. 카메라 이동 중 작업 취소·재생성 통과. 해당 호출 최대 3.3392ms(`grid-result.json`).
- 개편 요청 전 수행한 두 씬 × 7해상도 건설창 검증 통과. 메뉴·건설 비용/예약·철도 초안·선택/자원 스크롤·전체 저장 복원 통과. 이는 과거 검사 범위이며 앞으로 두 씬을 자동 순회하지 않는다.
- 최종 적 1,000개 실제 실행 QA는 **현재 OpenWorldSandbox**에서 통과했다. 중앙값 6.89ms, p95 7.83ms, 패배 없음, 시뮬레이션 정지 없음. 캠페인 없는 다른 구성이라 StartRegion 전후 표와 직접 비교하지 않는다.
- 최초 밀집 QA는 측정 후 수동 정리가 늦어 적이 기지를 파괴했다. `superseded-late-cleanup-*`에 실패 기록을 보존했다. 측정 완료 즉시 자동 정리하는 도구로 바꿔 위 최종 결과를 얻었다. 이 QA는 임의 적 생성 fixture로서 정상 생존/밸런스 데이터가 아니다.
- 최종 현재 씬 Play 검사는 Tab 그룹·이징·Esc 입력 차단·150×150 미니맵·테스트 버튼 보존을 통과했다. 화면 3장은 `../Measurements/2026-10-03-test-restructure/play/`에 있다.
- 종료 시 현재 씬 OpenWorldSandbox 유지, Play 종료, dirty=false, 격리 저장 해제, runInBackground=false, Profiler 꺼짐, 테스트 UI 활성 상태다.

## 후속 상태

구조 평가와 이번 병목 최적화는 완료했다. 배포 빌드 GPU/장시간 큰 저장/후반 대규모 적·철도 복합 부하는 미검증이다. 정상 한 회차 로직 감사와 생존·밸런스 기록은 사용자가 새로 요청한 후속 작업이며 아직 완료로 판정하지 않는다. 현재 열린 OpenWorldSandbox에는 캠페인 저장과 시작 기지가 없으므로 정상 캠페인 검사를 통과로 기록하지 않았다.

현재 테스트 운영은 [새 테스트 기준](../Testing/README.md), 날짜별 변경·검증·남은 항목은 [개발일지](../DevelopmentLog/2026-10-03.md)를 따른다.
