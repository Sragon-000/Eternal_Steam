# 개선 후 10공세 정상 생존 — 종료 검증

대상은 `StartRegionSandbox` 한 씬의 `20261003-survival-improved-01`이다. 정상 시간·자원으로 10번째 밤까지 관찰한 뒤 11일차 낮에 오브를 제작했다. 일반 적 2,125명과 보스 1명 전원 처치, 건물 피해·손실 0. **10개 공세 완료는 관측 경계이며 최대 생존 한계는 아니다.** 학술 연구 실험은 시작하지 않았다.

## 실행 조건과 종료

- 제품 소스는 시작 버전 `de9af47`의 199개 C# 해시와 동일하다. 일반 건설/강화 비용 참조가 없는 현행 무료 정책을 유지했다. 무한 자원·낮밤 전환·시간 가속은 사용하지 않았다.
- 카탈로그 24개 정의, 기존 포탑 4종, 토대 1개, 기지 3개, 철도 노선·화물·장착 방어를 구성했다. 설치 완료와 실제 공격 참여는 구분한다.
- 정상 열차 정차·급탄·기지 전력 충전·재출발 각 10회(40개 명령)를 자동 운용했고 개입을 모두 기록했다. 플레이어의 수동 조작 숙련도를 평가한 자료는 아니다.
- 게임 시각 4,800.003초에 11일차 낮, 활성 적/생성 대기 0으로 관찰 경계에 도달했다. 실제 오브 제작으로 Cleared가 된 후 정차·저장에 25.797초를 더 사용했다. 이 후반 시간은 추가 생존 성과에 포함하지 않는다.

## 공세와 방어 해석

공세별 생성/처치는 1일차 101, 이후 125·150·175·200·225·250·275·300·325명으로 모두 일치한다. 6일차 적 6명은 7일차 처치이므로 생성 세대로 원래 공세에 연결했다. [전체 생성 세대 감사](../Measurements/Balance/20261003-survival-improved-01/checkpoints/audit-prefix-000030746.json).

열차는 적 없는 첫 약 269초 동안 충전 200을 보존했다. 동일한 적 없는 첫 60초 비교에서도 기준 회차는 약 40초 만에 소진, 개선 회차는 200 유지였다. 전체 장기 운용은 배치·보급 자동화·길이가 다르므로 순수 코드 수정 효과로 모두 귀속하지 않는다.

**최종 결과에서 배터리 0 표본은 1개다.** 10일차 밤 4,722.623초, 적 130명·정차 요청 상태에서 0이 되었고 다음 표본 4,723.626초에 정상 기지 충전으로 200이 됐다. 앞선 8일차 구간의 0개 결과는 그 구간에서만 유효하다. 20 이하에서 요청하는 정책은 최대 이동 잔여 시간보다 전투 소비 여유가 작을 수 있다. 후속 개선은 잔여 정차 시간과 실제 5/초 소비를 기준으로 보급 여유를 계산하고 별도 회차에서 비교한다. 진행 중 규칙이나 기존 원본을 수정하지 않았다.

테슬라·EMP·벌컨 대공·스카이 플라즈마는 공통 작동 이벤트가 없었다. 기존 기관총·포·냉기·화살 포탑은 별도 실제 누적 발사 카운터도 0이다. 설치만으로 전투 사용을 완료 처리하지 않는다. 자연 공중 적은 첫 보스뿐이며 장거리 무기가 먼저 처치하는 배치가 영향을 준다. 별도 정상 회차에서 단거리/대공을 우선 배치해 확인해야 한다. [최종 보조 사거리/발사 분석](../Measurements/Balance/20261003-survival-improved-01/checkpoints/combat-coverage-prefix-000003118.json).

## 남은 작업

1. 같은 테스트 씬의 별도 정상 콘텐츠 회차에서 미참여 무기 8종의 실제 작동을 확인한다. 임의 적 소환이나 자원 주입 없이 정상 건설·자연 공세를 사용한다.
2. 장기 생존 자료와 콘텐츠 회차를 합쳐 무료 건설 정책, 장거리 우세, 후반 재고 누적, 기차 충전 여유의 밸런스 우선순위를 확정한다. 근거 없이 전체 비용/공세 수치를 일괄 변경하지 않는다.
3. 관측기의 화면 캡처/동적 컴파일/일시정지가 프레임 수치에 섞이므로 이 회차의 최대 frameMs를 제품 성능 벤치마크로 사용하지 않는다. 관측 부하 비교는 별도 검증 항목이다.

최신 전체 제품 회귀는 대기 전력 수정 시 **296/296**이다. 이번 종료 작업은 제품 코드를 변경하지 않아 같은 검사를 반복하지 않았고, 실제 생존·저장 복원·기록 감사로 해당 변경 범위를 검증했다. GitHub 게시 결과는 개발일지에 별도 기록한다.
