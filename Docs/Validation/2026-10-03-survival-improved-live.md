## 장기 운용과 종료 경계

10일차 공세까지를 우선 관찰 범위로 삼는다. 운용기는 석탄 20 미만 또는 장착 방어의 배터리 20 이하에서 정상 정차/보급 명령을 호출한다. 생성·강화·시간·체력을 자동 주입하지 않는다. 10번째 밤을 마친 다음 안전한 낮에는 게임 시계를 일시정지해 검토하며, 제작 전 공세를 임의로 클리어하지 않는다. 이 표본 경계는 게임의 이론적 생존 상한이나 목표 전체 완료를 의미하지 않는다.

무기별 누적 작동 신호를 수집기에 추가했고, 증분 모니터는 이벤트를 읽어 `live-summary.json`을 갱신한다. 모니터는 게임을 조작하지 않는다. 실행 중 상태 판단은 실제 Unity 운용 컴포넌트와 모니터 프로세스의 존재·새 출력으로 확인하며, 상태 파일만 보고 실행을 재시작하지 않는다.

## 5일차 — 기존 포탑 관측 경로 정정

코드를 대조하며 기존 포탑 4종의 공격이 `BuildingInstance.Shot`을 호출하지 않고 `HordeTower.shot`을 직접 증가시키는 것을 확인했다. 따라서 앞선 공통 이벤트 0은 해당 포탑의 비활동 근거가 아니었다. 3일차 고정 원본을 수정하지 않고 이 해석 제한을 추가했다. 감사 도구도 이후 결과에서 기존 포탑을 공통 이벤트 미지원 항목으로 분리한다.

5일차 낮 **1,956.71초**에 읽기 전용 보조 관측기를 시작했다. [첫 실제 표본](../Measurements/Balance/20261003-survival-improved-01/checkpoints/coverage-initial-sample.json)에서 기존 기관총·포·서리·화살 포탑의 누적 발사 카운터는 각각 0, 사거리 22, 운영 가능 상태였다. 네 번째 공세까지 551명이 처치된 상태에서 얻은 누적 카운터이므로 이 시점의 미발사를 직접 확인한다. 개별 과거 발사 시각을 소급 생성하지 않는다.

이후 1초마다 실제 누적 발사·표적 종류·사거리 안 지상/공중 적·운영/전력 조건을 `combat-coverage.jsonl`에 보존한다. 공격 방향 정렬·서리의 기존 둔화 여부·표본 사이 이동까지 연속적으로 측정하는 것은 아니므로 사거리 기회 수를 공격/적중/처치 수로 해석하지 않는다. [실제 146개 표본 누적 확인](../Measurements/Balance/20261003-survival-improved-01/checkpoints/coverage-live-status-command.json), [추가 관측 프로토콜과 도구 해시](../Measurements/Balance/20261003-survival-improved-01/checkpoints/coverage-protocol-extension.json).
