# Esc 메뉴와 입력 정지 상태 적용 기록

HUD-08A/B를 적용했다. 원형 미니맵(HUD-08C), 건설 dock 축소(HUD-08D), 전체 통합 인수(HUD-08E)는 아직 적용하지 않았다. 이번 변경은 Esc 입력 처리와 일시정지·저장 메뉴에 한정한다. 연구 실험은 실행하지 않았다.

## 적용 내용

- 두 씬에 저장된 `PauseMenuOverlay`와 `HudPauseMenu`를 추가했다. 상시 일시정지·저장 버튼은 메뉴 안으로 이동하고 화면 오른쪽 위에는 Esc 안내를 남겼다.
- 메뉴가 열리거나 닫히는 동안 별도 정지 이유를 `SimulationPaused`에 반영한다. 캠페인의 `Clock.Paused`와 건설 편집 정지는 그대로 보존한다. 메뉴를 닫았다는 이유로 기존 정지가 풀리지 않는다.
- 메뉴의 상태 전환 버튼은 ‘복귀 후 정지/진행 · 전환’으로 표시한다. 돌아가기와 상태 변경을 구분한다.
- Esc는 메뉴 처리기가 담당한다. 기존 건설 입력의 Esc 취소와 HUD 입력 종료를 분리하고, 우클릭·명시적 취소는 유지한다. IME 조합 중 Esc는 메뉴를 열지 않으며 다음 Esc로 연다.
- 메뉴 뒤의 월드·카메라·Tab·테스트 명령을 차단한다. 건설 드래그만 중단하고 예약·비용·철도 초안은 유지한다. 수량과 입력 포커스를 복원한다.
- 미확정 건설·철도 작업 중 불러오기는 폐기 확인을 거친다. 확인창과 개발 도구가 열렸을 때 뒤쪽 메뉴도 차단한다. 기존 새 게임 확인은 유지한다.
- `CanSave`에 철도 초안 검사를 추가했다. 기존 낮/전투/편집/투사체 제한은 유지한다. 메뉴 중 자동 저장 타이머도 멈춘다. 저장 포맷은 변경하지 않았다.
- 메뉴는 중앙 앵커, 물리 너비 최대 580px·높이 최대 600px, 화면 여백 16/24px, 실효 글자 18px이다. 길어진 본문은 내부 스크롤로 접근한다. 저장·진행 기능이 없는 씬은 해당 영역의 빈 공간을 제거하고 메뉴 높이를 표시 항목에 맞춰 줄인다. 메뉴 fade는 unscaled 시간 0.18초이다.
- 자원 무한·낮·밤 테스트 바로가기는 상시 유지한다. 기존 개발 도구는 Esc 메뉴의 진입 버튼으로 열고, Esc로 도구를 닫은 뒤 메뉴로 돌아온다.

## 발견·수정한 문제

초기 전체 회귀 283/285의 두 실패는 메뉴 닫기 콜백 소유자가 HUD에서 메뉴 처리기로 변경된 계약을 기존 검사가 반영하지 못한 것이었다. 새 소유자를 명시적으로 검사하도록 갱신했다.

첫 Play에서는 항상 활성화되는 개발 도구 컨테이너를 ‘펼쳐진 도구’로 오인해 Esc가 메뉴를 닫지 못했다. 실제 `developer-body`를 참조하도록 수정했다.

중첩 메뉴 차단용 CanvasGroup을 추가하는 과정에서 Unity 미할당 참조를 `??`로 판정해 씬 참조가 누락되었다. 명시적 Unity null 검사와 AddComponent로 수정하고 씬 저장 후 재오픈 검사를 추가했다. 해당 상태에서의 이전 Play 결과는 최종 통과 근거로 사용하지 않는다. 수정 후 런타임 오류 감시를 포함한 입력 probe를 재실행했다. 메뉴 배율 계산도 Canvas 갱신 후 LateUpdate에서 재적용한다.

## 남은 범위

OS 한글 입력기의 실제 조합은 미검증이다. Input System IME 이벤트 주입과 구분한다. HUD-08 전체 완료를 주장하지 않는다. 다음 순서는 원형 미니맵의 시각·입력 경계 일치, 건설 탐색/배치 UI 분리, 변경 후 통합 인수다.

최종 에디터 복원 결과와 증거 해시는 `final-editor-state.json`, `manifest.json`으로 기록한다. 코드·씬·저작 도구·검증 도구·격리 저장은 모두 Eternal_Steam 안에 남겼다.

소스·문서의 diff 공백 검사는 통과했다. Unity 직렬화 씬의 공백을 정리하기 위해 YAML을 직접 수정하지 않았다.
