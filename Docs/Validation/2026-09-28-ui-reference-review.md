## 판단

현재 구현은 기능 위치를 옮겼지만 레퍼런스의 좁고 분리된 패널 비율과 넓은 중앙 월드 공간을 충분히 반영하지 못했다. 글자만 줄이는 것으로는 해결되지 않는다. 큰 고정 배경, 높이에만 맞추는 배율, 빈 영역 유지가 함께 원인이다.

CanvasScaler는 Scale With Screen Size, referenceResolution 1280×800, matchWidthOrHeight=1이다. 1920×1080에서 배율은 1.35이며 다음 값은 그 설정을 기준으로 계산한 예상 픽셀 크기다. 1080p 실측 캡처와 구분한다.

| 요소 | 실제 저작 크기 | 1080p 환산 | 조정 제안: 1080p 기준 |
|---|---:|---:|---:|
| 상단 바 높이 | 84 | 113px | 56–64px |
| 왼쪽 패널 폭 | 236 | 319px | 220–240px; 자원 목록 190–210px |
| 오른쪽 패널 폭 | 292 | 394px | 260–280px |
| 좌우 패널 높이 | 각각 470 | 각각 635px | 내용별 독립 패널, 빈 배경 제거 |
| 하단 전체 높이 | 206 | 278px | 펼침 190–220px, 접힘 40–48px |
| 일반 텍스트 | 15–16 | 20.3–21.6px | 16–18px |
| 큰 제목 | 20–21 | 27–28.4px | 20–22px |

시안의 이미지 폭/높이에 대한 비율을 대략 비교하면 상단 상태 바는 높이 약 5%, 현재는 약 10.5%다. 시안의 자원 목록 폭은 약 10–11%, 현재 캡처의 왼쪽 전체 패널 폭은 약 20%다. 시안의 지도 패널 폭은 약 14–15%, 현재 오른쪽 전체 패널은 약 25%다. 각 이미지의 화면비가 다르므로 이는 정확한 같은 해상도 대조가 아닌 비율 비교다.

## 우선 수정 방향

1. **상단 바를 절반 수준으로 낮춘다.** 날짜·남은 시간·전력·정지/재개를 짧은 한 줄 영역으로 구성한다. 화면 전체를 덮는 큰 배경 대신 기능별 구획을 사용한다.
2. **좌측 체력/시계와 자원을 분리한다.** 좁은 자원 목록에 이름 좌측·수량 우측 정렬을 적용하고, 조작 안내는 자원 패널 밖의 전용 줄로 옮긴다. 현재 캡처에는 자원과 안내 겹침이 있다. 미정 자원 우선순위를 임의로 정하거나 0 재고를 숨기지 않는다.
3. **우측의 빈 배경을 제거한다.** 지도는 정사각형에 가까운 독립 패널로 줄이고, 상세 패널은 선택 시에만 별도로 표시한다. 지금은 상세가 없어도 큰 RightStatus 배경이 남는다.
4. **하단을 한 줄 카탈로그 중심으로 압축한다.** 큰 명령 행과 범주 행 사이의 여백을 줄이고 수정·확정·취소는 일관된 위치에 둔다. 실제 아이콘 에셋이 없는 항목은 작은 텍스트 버튼으로 처리한다. 시안의 가상 건물 아이콘을 그대로 약속하지 않는다.
5. **배율과 요소 크기를 함께 조정한다.** 1920×1080 기준 및 width/height 균형 배율을 후보로 검증한다. referenceResolution만 바꾸면 시계·글자까지 과소해질 수 있으므로 전체 일괄 축소로 끝내지 않는다. 기존 시계는 이미 시안보다 작게 보이므로 확대/축소를 별도 판단한다.

## 적용 시 검증 기준

수정은 기존 Canvas 자식의 RectTransform·Layout·폰트·배경·표시 상태에 저장한다. 런타임에서 정적 패널을 재생성하지 않는다. UI 축소를 위해 게임 카메라 줌을 바꾸지 않는다.

1366×768, 1920×1080, 2560×1440, 좁은 Editor Game 창에서 일반/선택/수정/접힘 상태를 비교한다. 한글 잘림, 자원 증가, 긴 건물 이름, 스크롤, 숨긴 영역의 입력 차단, 미니맵 클릭·드래그를 검사한다. 완료 기준은 가독성과 기능을 유지하면서 중앙 월드 공간을 회복하는 것이다.
