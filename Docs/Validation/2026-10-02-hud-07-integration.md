# HUD 통합 검증과 반응형 배치 보완

HUD-07 통합 인수를 진행하고 발견한 배치·입력 문제를 두 씬에 반영했다. 전체 완료 판정은 보류한다. OS 한글 입력기의 실제 조합, 맵 경계의 유효 클릭·연속 드래그, 적 밀집 상태의 미니맵 갱신 비용 검증이 남아 있다. 연구 실험은 실행하지 않았다.

## 적용한 변경

- Canvas 기준을 1280×720, 세로 높이 기준 배율로 통일했다. 초광폭에서 가로 폭 때문에 하단 메뉴가 과도하게 커지는 문제를 해소했다.
- 전투 미니맵에서 숨겨진 건설 메뉴·선택 정보의 높이를 차감하지 않는다. 시야 중심과 150×150 월드 범위는 유지한다.
- 자원 패널의 높이 계산에 부모의 상단 여백 84를 포함했다. 전력 요약은 건설 그룹 왼쪽 위에 배치했다.
- 목표 안내문을 여백 12/8의 stretch 앵커로 고정하고 내용에 맞춰 높이를 계산한다.
- 좁은 화면에서는 자원 무한·낮·밤 버튼을 중앙 두 줄로 배치한다. 테스트 UI ON과 기존 콜백은 유지한다.
- 진행·저장/전력 팝업은 글자 크기를 줄이지 않고 패널과 스크롤 viewport를 조정한다. 팝업 글자는 실효 18px이다.
- 화물·방어 요약의 긴 역명을 줄바꿈한다. 철도 서비스·편집 화면의 실효 18px은 유지한다.
- 건설 그룹의 수량 입력에 포커스가 있었으면 Tab 왕복 후 값과 포커스를 복원한다.

모든 정적 UI 참조와 앵커는 두 `.unity` 씬에 Unity Editor API로 저장했다. 런타임에 프레젠테이션을 새로 생성하지 않는다.

## 발견한 실패와 수정

초기 전체 회귀는 278/283, 중간 회귀는 281/283이었다. 이전 기준 해상도 계약과 자원 패널 겹침이 원인이었다. Canvas 계약·높이 예산을 수정한 뒤 최종 283/283을 확인했다.

화면 검토에서 전투 미니맵 축소, 목표 안내문 배경 이탈, 테스트 버튼의 기지 목록 가림, 팝업 스크롤의 고정 높이를 발견해 수정했다. 팝업 검증에는 viewport 경계와 스크롤 후 실제 버튼 raycast 검사를 추가했다. 긴 역명은 자동 글자 축소 대신 줄바꿈한다.

입력 probe와 서비스 probe가 동시에 실행된 한 번의 입력 실패는 검증 간 그룹 전환 충돌이었다. 서비스 probe 완료 후 입력 probe를 단독 실행해 통과했다. 지형 collider만 가정한 최초 입력 probe는 제품의 평면 fallback과 일치하도록 보완했다. 이 실패들을 제품 통과로 오인하지 않았다.

## 남은 인수와 다음 작업

1. OS 한글 입력기의 실제 조합 상태에서 Tab 보류·확정·포커스 복귀를 확인한다. 현재 IME 결과는 Input System 이벤트 주입이며 OS 조합 검증을 대체하지 않는다.
2. 미니맵의 맵 끝 유효 클릭과 연속 드래그 중 투영 유지, 적 밀집 조건의 제품 갱신 비용을 확인한다. 현재 맵 밖 거부·fallback·텍스처 재사용 검증과 구분한다. 연구 실험은 시작하지 않는다.
3. 최종 사용자 조작 점검 후 HUD-01~03과 HUD-07을 인수 완료로 변경한다. 이번 단계에서는 일괄 완료 처리하지 않는다.

검증 도구는 `Tools/VerifyHud07*.cs`, 씬 저작 도구는 `Tools/AuthorHud07.cs`이다. 격리 저장은 이 증거 디렉터리 안에 있으며 사용자 일반 저장을 사용하지 않는다. 최종 에디터 상태는 `final-editor-state.json`에 기록한다.

소스·문서의 `git diff --check`는 통과했다. 전체 diff 검사에는 Unity가 저장한 씬 YAML의 빈 필드 뒤 공백 경고가 있다. 씬 파일을 텍스트로 재작성하지 않았으며 코드 오류로 계산하지 않는다.
