## 실행 결과와 판정

기존에 열린 `StartRegionSandbox` Editor에서 Pipeline 서버만 중지·재시작해 연결을 복구했다. Editor 프로세스를 새로 실행하지 않았다. 테스트 저장 루트를 `/tmp/eternal-qa05-defense`로 격리하고 Play를 진행했다.

| 검사 | 결과 |
|---|---|
| 현행 카탈로그 EditMode | 새 `DefenseCatalogParityTests` 10/10 통과. 9종의 정의·해금·점유·무기 수치/대상·실제 자산 공격·공중 전용의 지상 제외·강화 최대값·모듈 상태 왕복 확인 |
| 현행 씬 Play | 9종 모두 실제 설치. 전력 차단 중 공격 없음, 전력 재공급 뒤 실제 적 피해 또는 EMP 무피해 기절, 첫 강화 수치 변화, 각자의 최대 레벨 초과 거부 확인 |
| 격리 v2 저장·재로드 | 안전 저장 뒤 `ContinueSaved`로 씬을 다시 불러와 9종의 건물 ID·소속·위치·무기/전력 모듈·최대 강화 레벨 유지 확인 |
| 전체 EditMode | 212/212 통과, 실패·건너뜀·미결정 0 |

Play 검사는 [재실행 도구](../../Tools/VerifyQa05Defense.cs)의 런타임 호출을 사용했다. 실제 포인터 클릭, 모든 무기의 연쇄·과열·관통·폭발·화상 세부 시간축과 표시 화면의 전수 검사는 이번 Play 인수에 포함되지 않는다. 기존 공격 계약 검사와 위 신규 검사가 해당 구현을 일부 검증하며, 입력·해상도는 QA-06, 독립 빌드·장시간 전투는 QA-07에 둔다. 검사 후 Play를 종료하고 저장 루트 환경값과 `Application.runInBackground`를 원상복구했다. 씬은 Edit Mode, dirty=false였다.

- **정책 차이:** 원본 표의 테슬라 60°·레이저 30°·레일 대공 15°·레일건 180°는 후속 원형 자동 공격/회전 결정(통합기준 DEC-03)으로 대체되었다. `WeaponRuntime.Angle`은 호환 필드이고 실제 판정은 360°다. 원본 안에서도 테슬라 연쇄 거리는 표 8m·상태 설명 5m로, 포탑 각도는 표와 후속 문장이 충돌한다. 현재의 8m·원형 판정을 임의로 되돌리지 않는다.
- **정책 미정:** 정수 수량 예시 `3×1.3=3.9→4`와 현재 `PerformanceUpgrade.Count`의 내림 결과 3이 충돌한다(DEC-05). 스마트 미사일 최대 강화 Lv.3에서는 현재 3발이 유지된다. 반올림 방식이 결정되기 전 수치 코드를 바꾸지 않는다. 기본 공격력 100, 화상 틱 피해 10, 속도·상태 강도와 최종 비용은 검증용 값이다.
- **B1/B2 핵심 인수 완료:** 위 현행 씬의 9종 공격/EMP·전력·강화·저장 왕복이 통과했다. 확정된 제품 결함은 발견되지 않아 런타임 코드는 바꾸지 않았다. 실제 포인터/화면 QA와 독립 빌드는 각각 QA-06/07이다.

초기에는 기존 Unity Editor 프로세스와 7800 포트가 살아 있어도 `unity status`가 Pipeline 인스턴스를 찾지 못했다. Editor 화면 하단에는 이전 Unity Performance Testing의 `IPostBuildCleanup` 표시가 남아 있었다. Pipeline 서버만 다시 시작한 뒤 위 검사를 완료했다.
