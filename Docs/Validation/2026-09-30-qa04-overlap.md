# QA-04 — 타 기지 영역 중첩과 소속 기지 상실

2026-09-30, 이미 열린 Unity Editor의 `StartRegionSandbox`와 `/tmp/eternal-qa04-overlap` 격리 저장을 사용했다. `Tools/VerifyQa04Overlap.cs`는 메인·서브 기지와 각각의 역이 있는 실제 Play 저장을 불러와 메인 기지 영역에 들어오는 서브 소속 역을 확인한 뒤 서브를 파괴했다.

| 관측 | 결과 |
|---|---|
| 서브 소속 역의 메인 영역 중첩 | 전체 발자국이 메인 영역 안에 있음 |
| 서브 파괴 뒤 영역 가동 | 역의 소속 ID 유지, `Operational=true`, `OperationBlock=None` |
| 재고·철도 | 상실 기지 장부 접근 불가, 철 107 보존, `StationActive=false` |
| 생산 모델 회귀 | 같은 중첩 조건에서 상실 전 철 25→30 생산, 상실 뒤 Tick에도 30 유지 |
| 실제 Canvas 선택 정보 | `영역 내 가동 · 소속 기지 상실`, `원소속 재고 이용 불가 · 생산/역 운송 중단`, `소속 기지 상실` 표시 |

**적용 정책:** 다른 정상 기지 영역이 남으면 건물의 영역 가동 상태는 유지한다. 원래 소속 기지 ID는 자동으로 바꾸지 않는다. 원소속 재고를 필요로 하는 생산과 역 운송은 중단하고, 장부 내용은 향후 복구를 위해 보존한다. 따라서 `가동 중` 하나로 모든 기능을 표현하던 선택 정보만 변경했다. 실제 Canvas 및 레거시 상세 화면은 같은 상태 해석을 사용한다. 원본 `Docs/Source/Attachments/4. 기지.md`의 중첩·기지 파괴 규칙과 통합 기준 §2의 소속 불변 계약을 유지했다.

`BuildAreaCoverageTests`에 소속 상실·중첩·생산 중단·재고 보존·표시 회귀 1건을 추가했다. 관련 **7/7**, 전체 EditMode **199/199** 통과. 실제 Play는 내부 선택 명령으로 역과 Canvas 텍스트를 검증했으며, 생산 Tick은 EditMode 모델에서 확인했다. 물리 포인터 입력·해상도 확인은 QA-06 범위다.
