## 저장 계층과 회귀 검사

두 씬의 `ResourcePanel` 폭은 288, `ResourceBody` 폭은 272다. 이름/수량 TMP 사각형은 각각 104/136 폭으로 배치해 4 단위의 틈을 남겼다. 실행 중 측정한 TMP 선호 폭은 `플라즈마석` 약 92.5, `1,234,567,890` 약 125.5였다. `CanvasHierarchyTests.SavedResourceColumnsFitLongQuantitiesWithoutOverlap`은 두 씬의 실제 TMP 폭과 가로 간격을 검사한다. `SavedRailwayPanelClearsResourcePanel`은 저장 계층에서 자원 패널 오른쪽(16+288=304)과 철도 본문 왼쪽(320)의 16 단위 간격을 검사한다. [EditMode 결과](2026-09-30-qa06-editmode.json)는 새 씬 사례 4/4, 전체 216/216 통과다.

정적 프레젠테이션은 두 씬의 Canvas/uGUI에 저장했고 실행 중 UI 생성 코드는 추가하지 않았다. 격리 저장 경로 `/tmp/eternal-qa06-ui`와 `/tmp/eternal-qa06-ui-final`을 사용해 사용자 저장 슬롯과 분리했다. 두 번째 Play에서는 두 역·노선을 실제 코드로 설치해 저장/재로드한 뒤 노선 상세를 열었다. 이 설치·노선 선택은 프로그램 호출이므로 물리 포인터 검증으로 세지 않는다.

## 실제 키보드 포커스

저장된 개발자 수량 필드를 열어 포커스했을 때 카메라의 `BlockKeyboard`가 켜졌다. 컴퓨터 입력 도구로 숫자 `3`을 전송하자 필드가 `3`을 표시했고 카메라 초점은 움직이지 않았다. Escape 뒤 포커스와 차단이 해제됐다. 두 역·노선을 재로드한 뒤 철도 화물 입력 필드를 포커스하자 같은 차단이 켜졌다. 실제 W 키는 한글 입력기 상태에서 필드에 `ㅈ`으로 들어갔고 카메라 초점은 `(16.97, 0.36, 11.31)`로 유지됐다. Escape 뒤 `Typing=false`, `BlockKeyboard=false`, 선택된 UI 객체 없음이 확인됐다. 필드 진입 자체는 프로그램 호출이었으므로 마우스로 필드를 선택하는 종단 경로는 별개다.

## 아직 완료하지 않은 QA-06

실제 OS 포인터 좌표 클릭은 성공적으로 입력되지 않았다. 열린 Unity 창을 다시 선택하고 전면으로 올려도 컴퓨터 입력 도구가 `noWindowsAvailable`을 반환했다. 따라서 철도 신규/편집·건설·저장 흐름의 물리 클릭, 버튼 클릭으로 필드 진입, 포인터와 키보드가 결합된 종단 검증은 남았다. UI 스크린샷과 프로그램 콜백을 실제 클릭으로 간주하지 않는다.

포인터 입력이 가능해지면 **격리 저장 경로**에서 1280×720과 1920×1080 각각 다음 순서로 확인한다.

1. 화면의 메인 기지를 클릭해 선택 상세가 열리고, 자원/미니맵/UI 클릭이 월드 선택이나 설치 클릭으로 새지 않는지 확인한다.
2. 두 역·노선이 있는 fixture에서 `노선 관리` → 노선 행 → 역 이름/역 행 → 목록 복귀 → 신규/편집/취소를 실제 클릭으로 이동한다. 각 단계에서 선택 역과 상세 제목·입력 필드가 일치해야 한다.
3. 철도 화물/적재/하역 필드를 **클릭해서** 포커스한 뒤 W/A/S/D와 숫자를 입력한다. 입력 중 카메라가 움직이지 않고, Escape 뒤에만 다시 이동해야 한다.
4. `수정` → 건설 목록 → 월드 배치/취소/회수, `진행·저장` → 저장/이어하기를 실제 클릭으로 실행한다. 버튼 위 클릭은 월드 건설 입력으로 전달되지 않아야 하고, 저장은 격리 슬롯에서만 확인한다.

사용자가 이미 연 Unity 창은 있었지만 Pipeline 연결 설명 파일이 없어 CLI에서 찾지 못했다. Unity `Window > Pipeline` 메뉴로 서버를 중지·시작하자 연결이 복구됐다. 검증 후 Play를 종료하고 격리 저장 환경값을 제거했으며 `runInBackground=false`, Game View 크기 인덱스 6(작업 전 4K UHD), 최대화 해제, 활성 씬 dirty=false를 확인했다.
