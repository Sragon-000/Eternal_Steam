# 현재 씬 중심 테스트 기준 — 2026-10-03

이 문서가 이후 테스트 선택과 실행의 기준이다. 이전 날짜의 Validation 문서는 당시 결과이며 반복 실행 목록이 아니다. 사용자 요청에 따라 **현재 열어 둔 씬 안에서만 검사한다. 다른 씬과 Preview Scene을 열지 않는다.**

## 실행 단계와 필요한 항목

| 단계 | 필수 확인 | 실행 시점 | 완료 증거 |
| --- | --- | --- | --- |
| T0 소스·실행 전 | 컴파일, 변경 범위, 한 개의 저장된 씬, 기존 데이터 보존 | 매 변경 | 컴파일 결과·씬 경로·Git diff |
| T1 도메인 회귀 | 건설 예약/취소/점유, 소유 기지 지불·생산·전력, 공격/적 슬롯, 기지 손실, 철도 연결/운행/화물/방어, 저장 마이그레이션, 맵 진행 | 관련 코드 변경, main 업로드 전 전체 | 어셈블리별 NUnit XML |

범위를 넓혀 횟수만 늘리지 않는다. 좁은 화면·기준 화면·초광폭의 경계 검사와 관련 기능의 실동작을 우선한다. 7개 해상도 전체 행렬은 앵커·CanvasScaler 변경 또는 경계 회귀가 있을 때만 실행한다. 철도 화물·전력·피해처럼 서로 다른 불변조건은 중복으로 보지 않는다.

## 명령

Unity가 열린 프로젝트 루트에서 직접 실행한다(RTK 사용 안 함).

```sh
unity command recompile --json
unity command recompile_status --json
unity command run_script --file Tools/Testing/RunCurrentSceneChecks.cs --entry RunCurrentSceneChecks.Main --args '["all"]' --json
```

UI 참조/레이아웃만 바뀌면 마지막 인자를 `["CurrentScene"]`로 좁힌다. 테스트 도중 Unity를 조작하지 않는다. 씬이 수정 중이면 먼저 사용자가 의도한 상태로 저장한다. 실행기는 미저장·여러 씬·Play 상태에서는 시작하지 않는다.

Unity 기본 `run_tests`는 임시 빈 씬을 열기 때문에 이 작업의 기본 실행 경로에서 제외했다. 새 실행기는 설치된 Unity Test Framework의 검사 엔진을 메인 스레드에서 직접 구동한다. NUnit의 TestCaseSource·SetUp/TearDown·Unity 로그 검사를 유지한다. 내부 API를 사용하는 Editor 전용 도구이므로 패키지 업그레이드 시 컴파일과 전체 실행을 검증한다. 코루틴 기반 UnityTest는 이 동기 실행기로 실행하지 않는다.

T2는 현재 씬 오브젝트에 대한 일시적 레이아웃 변경을 단일 Undo 그룹으로 복원하고 씬 핸들·개수·dirty 상태를 검증한다. 다른 씬의 레이아웃을 대신 확인하지 않는다. 씬에 필요한 기능이 없으면 NOT APPLICABLE/Skipped로 기록하고 통과 수에 포함하지 않는다. 실패·예외·미실행 항목을 완료로 적지 않는다.

T3~T5는 현재 씬을 유지한다. 저장 불러오기를 검증할 때만 **현재 씬 경로로의 재로드**를 허용하며 저장 경로는 프로젝트 안의 회차별 격리 폴더여야 한다. 씬을 바꾸는 테스트용 준비/복원은 금지한다. 입력·자원·카메라 상태를 인위적으로 바꾸는 QA fixture와 정상 플레이 데이터는 분리한다.

## 기존 항목 변경

- 11개 씬 검사 파일에서 두 씬의 중복 TestCase와 OpenPreviewScene을 제거했다. 같은 기능·해상도 조합은 현재 씬에서 한 번 검사한다. 순수 계산 경계값과 기능별 회귀 조건은 보존했다.
- 기존 FoundationSandbox/ModuleSandbox PlayMode 4개는 현재 uGUI 게임의 필수 인수 목록에서 제외했다. `LegacyScene`/Explicit로 남기고 해당 씬이 이미 열려 있을 때만 실행 가능하다. 자동 씬 로딩은 제거했다.
- 씬을 이동시키던 과거 검증·복원 도구 25개는 [보관 매핑](archived-scene-tools.json)에 기록하고 `Tools/Archive/SceneSwitching/*.cs.txt`로 원문을 보존했다. 실행 가능한 C# 파일 목록에서 제외했다. 과거 문서의 이전 경로는 이 매핑으로 찾는다.
- 씬/에셋을 실제 저작하는 Author/Apply 도구는 테스트가 아니므로 이번 자동 검사 목록에 포함하지 않는다.
- `Tools/VerifyHud*`, 날짜별 fixture와 측정 도구는 과거 재현 자료다. 새 기능이 생길 때 복제본을 추가하지 말고 T1~T5의 해당 검사에 필요한 조건만 추가한다.
- 현재 정확한 항목과 이전 항목 대응은 자동 생성하는 [검사 인벤토리](inventory.json)를 따른다.

## 정상 플레이 기록 규칙

무한 자원, 낮/밤 강제 전환, 임의 적 체력·에너지·재고 주입을 사용하지 않는다. 테스트 UI는 기존 요구대로 남기되 사용 여부를 기록한다. 회차 시작 구성·버전·씬·초기 자원, 건설/업그레이드 비용, 생산량·소비량·재고 변화, 전력, 적 생성/처치/누적 생존/기지 피해, 운송 적재·하역·연료·운행 지연, 해금·보스·오브를 기록한다.

각 낮밤 전환, 첫 건설·기지 확장·철도 배송·해금·보스·파괴/실패/완료 때 스크린샷과 이벤트를 같은 시각/일차로 연결한다. 관찰 누락·중단·개입은 반드시 기록한다. 최대 생존은 실제 관측한 일차이며 게임의 이론적 최대치로 표현하지 않는다. 캠페인 기능이 없는 현재 씬에서는 정상 캠페인 회차를 통과 처리할 수 없다.

학술 표적 탐색 비교 실험은 이 제품 내부 플레이 테스트와 별개이며 아직 시작하지 않는다.

실제 생존 회차의 시작 조건과 단계는 [정상 플레이 실행 전 계획](normal-playthrough-plan.md)에 이어서 기록한다.
