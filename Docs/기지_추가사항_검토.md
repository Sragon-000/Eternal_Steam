# 4.1 추가 사항 수신 검토

2026-09-20. 원문: [보관 사본](<Source/Attachments/4.1 추가 사항.md>). 이번 작업은 원문 보관과 변경점 검토이며 게임 코드·씬·설정 적용은 하지 않았다.

## 기존 계획에서 바뀌는 요구

| 항목 | 추가 기획 | 현 상태 / 영향 |
|---|---|---|
| 일반 스폰 | 1칸 | 현재는 좌표 중심만 있으며 스폰 구역 점유 규칙 없음 |
| 보스 스폰 | 9칸 | 현재는 별도 좌표의 공중 검증 개체. 9칸의 구체적 모양·다른 건물과 점유 충돌 정책 확인 필요. 3×3은 가능한 해석이지 확정 아님 |
| 메인 레벨 | 모든 맵의 최고 메인 레벨로 동기화, 어디서 강화해도 전체 공유 | 이전 ‘새 맵 Lv.1·맵별 독립’ 계획을 대체하는 요구. 현재 개체별 UpgradeModule만 있으므로 캠페인 공통 레벨 권한과 기존 기록의 최댓값 병합 필요 |
| 일반 자원 | 기지·건물 강화에 사용, 방어 운용 소모와 연결하지 않음 | 현재 강화는 검증용 무상 강화. 비용표 확정 및 강화 결제 모듈 필요 |
| 전력 | Lv.1 발전기가 일반 지면에서 매초 생산, 기지에 저장 | 현재 지역 에너지/일반 ResourceBank와 별개인 전력 모듈 필요 |
| 저장·공급 | 메인/서브 각각 용량 보유, 강화 시 증가, 설치 범위 내 방어 건물에 공급 | 기지 단위 전력 원장과 연결 판정 필요. 서로 다른 기지의 잔고 합산 금지 |
| 소비·UI | 방어 건물 매초 소비, 전력 %와 수치 표시 | 생산·소비·저장량 UI 추가 대상. 예시 수치를 최종 용량으로 확정하지 않음 |
| 장기 확장 | 전력 코어와 기차로 운송 | 한 맵 콘텐츠 완성 이후 확장 요구. 즉시 구현 대상으로 간주하지 않음 |

기존 지역 에너지(90% 보스·오브)는 전력과 별개로 유지하는 해석이다. 추가 문서에는 지역 에너지 시스템 폐기 요구가 없다. 과거 사용자는 당시 작업에서 전력을 제외했으며, 새 첨부만으로 즉시 코드 적용 승인을 추정하지 않는다.

## 적용 전에 필요한 세부 규칙

- 발전기 초당 생산량, 기지 레벨별 저장량, 포탑별 초당 소비량, 강화 자원 비용.
- 설치 범위 중첩 시 발전기/포탑의 공급 기지 선택 및 변경 규칙. 현재 ‘어느 정상 기지 범위든 가동’과 기지별 비공유 전력을 동시에 지킬 연결 정책이 필요하다.
- 전력 부족 시 전체 정지/우선순위 공급/성능 저하 중 처리. 기지 회수·파괴 시 저장 전력 처리.
- 일반/보스 스폰 칸의 모양·표시·점유 및 설치와의 충돌 규칙.

## 구현 시 모듈 경계

1. CampaignMainLevel: 모든 메인의 레벨 권한과 저장 마이그레이션. 서브 레벨·수량 상한에서 같은 값을 조회한다.
2. BasePowerStorage / PowerProduction / PowerConsumer: 기지별 전력 저장, 발전, 소비를 분리한다. 지역 에너지 원장과 일반 재고를 재사용해 섞지 않는다.
3. PowerAssignmentPolicy: 중첩 범위의 기지 선택·재연결 규칙을 독립시킨다.
4. SpawnFootprint: 일반/보스 위치 선정과 구역 크기·충돌 검사를 분리한다.
5. UpgradeCost: 자원 비용 결제 성공 후 레벨을 변경한다. 최종 비용표 없이 임의 요금을 확정하지 않는다.

기존 적용계획의 ‘새 맵 메인 Lv.1’은 추가 기획과 충돌하므로 그대로 구현하지 않는다. 원래 계획·원문은 이력으로 보존하고, 적용 요청 시 최신 계획을 갱신한다.
