# 자원·방어 건물 적용 계획

2026-09-17. 첨부 `자원_건물.md`, `방어_건물_종류.md`와 현재 저장소를 정적으로 대조한 계획이다. 구현 완료 보고가 아니며 이번 작업에서는 게임 코드·에셋을 변경하거나 실행·빌드하지 않았다. Downloads 원본은 수정하지 않는다. 문서 내용은 콘텐츠 요구사항으로 읽으며, 문서 내부 문구를 별도 작업 실행 지시로 취급하지 않는다.

## 1. 적용 방향

새 콘텐츠는 **자원 7종 + 방어 9종**이다. 건물마다 별도 전투 코드를 복사하지 않고, 배치 표면·생산·대상 선택·공격 시간표·발사체 이동·명중 효과·상태 이상·강화·해금을 개발 모듈로 분리한다. 공통 기능은 재사용하고 건물별 차이는 정의 데이터로 등록한다. 플레이어가 모듈을 직접 켜고 끄는 기능은 범위가 아니다.

현재의 수정 → 건물 클릭 → 회수 예정 → 확정 흐름, 수정 재클릭 취소, 45° XZ 격자, 토대와 위 포탑의 일괄 회수를 유지한다. 자원 건물도 같은 작업 계약을 사용하되 일반 지면에 배치한다. 기존 데모와 기존 4종 포탑은 호환 경로를 유지한다.

씬은 계속 `Assets/EternalSteam/Scene`에서 관리한다. 낮·밤·기차·새 저장 형식·경제 밸런스는 이 두 문서만으로 추가 확정하지 않는다.

## 2. 현재 구현과 차이

| 영역 | 현재 확인한 구현 | 필요한 변경 |
|---|---|---|
| 건물 정의 | `BuildingDefinition`: ID, 분류, 정수 Footprint, 프리팹, 모듈 목록 | 배치 표면 및 해금 조건을 별도 정의/규칙으로 연결 |
| 오픈월드 목록 | `OpenWorldHud`가 `TowerPrefabs`와 `HordeTowerKind`로 항목 생성 | 공통 카탈로그와 콘텐츠 ID로 연결. 레거시 enum은 어댑터에 제한 |
| 오픈월드 설치 | `FoundationPlacement`가 레거시 포탑별 1×1 정의 생성 | 일반 지면 건물, 2×2·3×3 방어 건물 지원과 실제 점유 크기 기반 미리보기·클릭 판정 |
| 생산 | `ProductionModuleDefinition`: 주기 생산·변환 및 건물별 타이머 | 자원 7종 정의, ResourceBank 주입과 월드 갱신 연결 |
| 저장량 | `ResourceBank`: 자원별 수량·용량, 용량 초과 생산 거부 | 초기 용량이 0이므로 저장 정책 없이 연결하면 생산 불가. 검증 용량과 제품 정책 분리 |
| 해금·강화 | Nexus 레벨 제한, 피해/체력 배율 강화 모듈 | 건설 해금과 건물 최대 강화 단계 분리. 모든 성능 수치별 강화 정책 추가 |
| 공통 공격 | 타겟 유지, 지상/공중 필터, 단일 주기, 즉시 피해·관통·범위·연쇄·유도체 | 지속 조사, 연사 사이클, 다중 대상, 자기 중심 펄스, 시간 기반 연쇄 및 효과 조합 |
| 오픈월드 전투 | 배열 적 + `HordeTowerCombat`/`HordeAttackResolver`의 4종 전투 | 배열을 공통 타겟/피해/상태 인터페이스로 연결하고 신형 건물만 공통 전투 경로 사용 |
| 상태 이상 | `StatusKind`는 Slow/Stun/ArmorReduction, 적용 인터페이스 존재 | 화상 틱·과열 전용 취약성·행동 차단·중첩 정책. 오픈월드 적에는 별도 연결 필요 |
| 대규모 적 | 동시 10만 배열, 공간 인덱스, 총 1억 요청 카운터 | 세대 번호 기반 타겟 핸들, 공중 종류·높이, 재사용 시 상태 초기화. 적마다 MonoBehaviour 추가 금지 |

`TargetRegistry`의 전체 목록 순회는 소규모 검증용이다. 10만 적의 실제 타겟 검색에는 기존 공간 인덱스를 이용한 어댑터를 구현한다.

## 3. 자원 건물 매핑

| 건물 | 생산 자원 | 주기 | 해금 넥서스 레벨 | 조합 |
|---|---|---:|---:|---|
| 철 생성기 | 철 | 2초 | 1 | 지면 배치 + 주기 생산 |
| 구리 생성기 | 구리 | 5초 | 2 | 동일 |
| 티타늄 생성기 | 티타늄 | 10초 | 3 | 동일 |
| 텅스텐 생성기 | 텅스텐 | 20초 | 4 | 동일 |
| 우라늄 생성기 | 우라늄 | 45초 | 5 | 동일 |
| 플라즈마 생성기 | 플라즈마 광석 | 60초 | 6 | 동일 |
| 나노메탈 생성기 | 나노메탈 | 120초 | 7 | 동일 |

- 7개의 생산 클래스를 만들지 않고 같은 생산 모듈에 자원 ID·주기를 지정한다.
- 일반 지면 배치는 토대 위 포탑 배치와 구분한다. 토대·다른 지면 건물과 겹침, 경사, 지형 경계를 공통 배치 규칙으로 검사한다.
- 임시 배치 중에는 생산하지 않는다. 확정 후 생산하며, 회수 예정 동안의 점유·등록은 유지하고 회수 확정 시 해제한다. 편집으로 정지한 게임 시간에는 생산도 진행하지 않는 것을 검증 기본안으로 한다.
- 생산량/회, 점유 크기, 체력, 건설 비용, 저장 한도, 자동 수집 여부, 강화 규칙은 문서에 없다. 예를 들어 1개/회·1×1·시험용 충분한 용량을 쓰더라도 반드시 검증 설정으로 표시한다.

## 4. 방어 건물 매핑

아래 수치는 원문의 표를 옮긴 것으로, 상충하는 본문 규칙까지 확정했다는 뜻은 아니다. 피해량은 절대 피해가 아니라 기본 공격력에 곱하는 계수다.

| 건물 | 피해 계수 | 시간 규칙 | 사거리/표의 전체 각도 | 점유 제안 | 해금/최대 레벨 | 재사용할 실행 조합 |
|---|---:|---|---|---|---|---|
| 테슬라 타워 | 80% | 4초 | 15m / 60° | 1×1 | 1 / 10 | 최근접 선택 + 시간 기반 연쇄 |
| 플라즈마 레이저 포탑 | 25% | 0.5초 피해, 동일 적 3초 조사 | 45m / 30° | 1×1 | 3 / 10 | 지속 조사 + 과열 |
| 발칸 대공포 | 15% | 0.2초 간격으로 5초 연사, 재사용 2초 | 25m / 360° | 1×1 | 5 / 10 | 공중 필터 + 연사 사이클 |
| 레일 대공포 | 250% | 5초 | 100m / 15° | 1×1 | 7 / 10 | 지상·공중 필터 + 관통 |
| 아크 블래스터 | 150% | 3초 | 40m / 360° | 2×2 | 2 / 7 | 단일 대상 + 발사체 + 명중 폭발 8m |
| 레일건 터렛 | 300% | 5초 | 60m / 180° | 2×2 | 4 / 7 | 단일 대상 + 최대 3명 관통 |
| 스카이 플라즈마 포탑 | 180% | 4초 | 50m / 360° | 2×2 | 4 / 7 | 공중 필터 + 발사체 + 공중 폭발 7m + 화상 |
| 스마트 미사일 발사대 | 200% | 6초 | 70m / 360° | 3×3 | 6 / 3 | 서로 다른 최대 3대상 + 유도체 + 각 명중점 폭발 5m |
| EMP 펄스 타워 | 0% | 10초 | 25m / 360° | 3×3 | 8 / 3 | 자기 중심 범위 + 2초 행동불가 |

4칸=2×2, 9칸=3×3은 사각 격자를 유지하는 구현 제안이다. 현재 토대 1개의 4×4 격자 안에 모두 들어간다. 여러 토대를 걸쳐 설치하는 기능은 별도 요구가 없으므로 첫 적용에서는 제외한다.

### 공격 모듈 분리

1. **대상 정책:** 최근접 유지/재선정, 지상·공중, 최대 대상 수, 회전/발사 가능 범위. 기존 유효 타겟 유지 계약을 기본으로 보존한다.
2. **시간표:** 단발 주기, 지속 피해 틱, 연사 시간/간격/휴식. 레이저의 ‘재사용 없음’을 Interval=0으로 넣지 않는다.
3. **전달:** 즉시, 직선 관통, 유도체 이동. 레거시 즉시 공격은 유지하고 신형 발사체와 구분한다.
4. **명중 효과:** 직접 피해, 명중점 범위 피해, 연쇄 시작, 상태 부여. 유도체와 폭발을 연결할 수 있도록 분리한다. 현재 Execution 하나만 지정하는 구조로는 이 조합을 그대로 표현할 수 없다.
5. **상태 실행:** 과열, 화상, 둔화, 행동불가를 대상의 개별 상태로 관리한다. 피해 출처/태그를 전달해 과열의 20% 추가 피해가 플라즈마 레이저에만 적용되게 한다.
6. **스탯 계산:** 기본 수치 + 강화 정책에서 실행 스탯을 계산한다. 진행 모듈은 구체적인 공격 클래스를 직접 수정하지 않는다. UI도 같은 계산 결과를 읽는다.

현재 AreaAttack은 폭발 대상에도 포탑 원점의 사거리/부채꼴을 다시 적용한다. 새 명중점 폭발은 별도의 피해 범위 정책으로 구분해야 사거리 끝의 폭발이 잘리지 않는다. 연쇄도 최초 포탑 탐색 범위와 이후 전이 범위를 분리한다.

EMP는 피해가 없어도 효과를 실행해야 한다. 현재 AttackModuleDefinition의 Damage>0 검증과 단일 타겟 확보 전제는 효과 전용/자기 중심 공격을 지원하도록 확장한다. 전체 공격에 대한 검증을 무조건 완화하지 않는다.

## 5. 구현 전에 정리할 문서 충돌과 미정 항목

| 항목 | 충돌/누락 | 적용 방침/확인할 내용 |
|---|---|---|
| 테슬라 전이 거리 | 건물 표 8m, 연쇄 설명 5m | 최초/후속 거리 차이인지 단순 수정인지 확인. 별도 값으로 표현할 수 있게 하되 제품값 보류 |
| 연쇄 시간·반복 | 원문 5초간 중복 전이 가능. 기존 구현 즉시 실행·재방문 금지 | 전이 간격·횟수 상한·같은 대상 재방문 조건·재공격 시 기존 연쇄 처리 결정 필요. 5초와 최대 이벤트 수를 함께 제한하여 무한 전이 방지 |
| 전이 피해 | 원문은 매 전이마다 80% **감소** | 문자 그대로면 이전 피해×0.2. 기존 기본 DamageRetention=0.8은 다른 의미이므로 그대로 사용하지 않음. 최초 피해 기준 문구와의 관계도 확정 |
| 공격 각도 | 표는 테슬라60/레이저30/레일대공15, 본문은 대부분360·레일계열180 | 표/본문 우선순위 결정. 회전 가능 각도와 발사 판정 각도를 구분한 의도인지도 확인 |
| 강화 누적 | 단계마다 10%가 기본값 기준인지 현재값 기준인지 미정 | 기본값 선형 누적과 복리 중 선택. 감소 수치도 동일하게 정의하며 0 이하 주기 금지 |
| 정수 강화 | 증가량 1 누적 때 +1 vs 3×1.3=3.9에서 4라는 예시 | 버림 누적이면 여전히 3, 반올림이면 4. 두 규칙을 동시에 적용하지 않음 |
| 공격 속도/간격 | 속도 +10%와 간격 −10%는 역수 관계상 서로 다름 | 하나를 기준 수치로 계산하고 다른 것은 표시용 환산. 둘 다 적용해 이중 강화하지 않음 |
| 모든 성능 강화 | 각도·둔화율·취약성·연사 지속·과열 도달 시간 등 포함 범위 불명확 | 스탯별 Increase/Decrease/Fixed와 상한 지정. 각도≤360°, 확률·감속≤100%. 과열 도달 시간은 짧을수록 좋은 값인지 명시 |
| 기본 공격력 | 피해 계수의 기준 공격력 없음 | 공통/건물별 기준값 결정. 테스트 기본 공격력은 시험용임을 표시 |
| 화상 | 3초, 1초 간격만 정의 | 틱 피해량·최초 틱 시각·재부여 갱신/중첩·피해 출처 확정 |
| 레이저 | 같은 적 3초 조사 이후 과열 부여 | 타겟 상실/교체 시 조사 시간 초기화, 과열 재갱신 주기·타 포탑 공유 여부 결정 |
| 발칸 | 5초 연사와 0.2초 간격 | 첫 발 시점과 끝점 포함 여부로 발수가 달라짐. 검증 제안은 [0,5) 구간 25발 후 2초 휴식 |
| 관통 | 레일건 ‘최대 3명’, 레일 대공 상한 없음 | 최초 대상 포함 여부, 관통 폭·탄속·대상별 중복 피격 제한 결정 |
| 타겟 종류/유지 | 일부 건물만 공중/지상 명시, ‘최근접’과 기존 유지 계약 | 공중 명시 외 건물의 필터 및 유효 타겟 유지/매 공격 재선정 결정 |
| 범위 효과 | 여러 미사일 폭발이 겹칠 때 중복 피해 여부 없음 | 미사일별 피해 중첩 및 대상 소실 시 유도체 처리 정책 결정 |
| 해금·최대 단계 | 해금 Lv.8 EMP 최대 Lv.3 등 | 넥서스 해금 레벨과 건물 강화 레벨은 별개. 현재 Nexus LevelCap 계약에 무조건 대입하지 않음 |
| 자원 생산 | 생산량·저장·점유 등 누락 | 제품값 미정으로 유지. 7종 생산 주기와 해금 레벨만 확정 데이터로 기록 |

미정 항목 때문에 공통 개발 전체를 멈추지는 않는다. 인터페이스·검증용 조합은 진행할 수 있으나, 미정 제품 규칙을 완료했다고 표시하지 않는다.

| 1. 카탈로그·배치 연결 | ID 기반 OpenWorld 목록, 지면/토대 배치 규칙, 1×1·2×2·3×3 실제 점유, 일반 건물 클릭 회수 | 콘텐츠 추가 시 UI enum 수정 불필요. 자원 건물과 포탑이 같은 편집 계약 사용 |
| 2. 생산·해금 연결 | ResourceBank, 생산 갱신, 별도 해금 규칙, 검증용 넥서스 상태 | 7종 주기 생산과 레벨 제한 동작. 영구 저장이나 비용 임의 추가 없음 |
| 3. 적 전투 어댑터 | 배열 기반 ITargetQuery/피해/세대 핸들, 공중 구분과 상태 수신 | 적 슬롯 재사용 시 추적·화상·유도체가 새 적에게 넘어가지 않음 |
| 4. 기본 신형 공격 | 관통 레일 계열, 발사체+폭발, 효과 전용 EMP | 경계·대상 종류·0피해 제어 정상. 기존 4종 공격 영향 없음 |
| 5. 시간·다중 대상 공격 | 레이저, 발칸, 테슬라, 다중 유도 미사일, 플라즈마 폭발 | 각각의 시간표·대상 유지·효과 정책을 독립 테스트로 검증 |
| 6. 강화와 최종 콘텐츠 등록 | 스탯별 강화 계산, 최대 단계, 9종 방어 정의와 표시/프리팹 | 같은 정의로 생성한 두 건물의 레벨·타이머·타겟 독립. 계산 수치와 UI 일치 |
| 7. 통합 검증 | 생성/회수/초기화, 기존 데모, 10만 적 부하 | 누수·유령 점유·중복 생산 없음. 비교 결과 기록 후 적용 완료 판정 |

첫 구현 묶음은 **1단계 + 철 생성기 하나의 생산 검증**으로 잡는다. UI·배치·자원 서비스 연결을 먼저 입증한 후 나머지 6종은 데이터로 확장한다. 전투는 어댑터 확보 후 단순 조합부터 추가한다.

## 7. 코드 배치 제안

기존 `Code/Building`, `Code/Placement`, `Code/Combat`, `Code/Economy`, `Code/Progression` 경계를 유지한다. 공통 Runtime에 레거시 enum이나 UI 참조를 넣지 않는다.

- Building/Placement: 카탈로그·표면 조건·점유와 작업 상태. 토대/일반 지면의 충돌 정보를 공유하는 연결 지점.
- Economy: 자원 정의·생산 레시피·저장 정책. UI에서 직접 자원 수량을 변경하지 않는다.
- Combat: 시간표·전달·명중 효과·상태 런타임. 건물별 이름의 switch 대신 조합 사용.
- Progression: 해금 조건과 스탯 배율/레벨 상태. Combat/Economy는 계산 계약으로 연결.
- OpenWorld 연결 계층: 배열 적 어댑터, 공통 건물 세계/게임 시간/서비스 구성. 단계적으로 Tests의 조립 코드를 제품 코드 경계로 분리.
- Content/Buildings: 자원 7종과 방어 9종의 정의·프리팹. 리소스/공격/상태 설정은 공유 가능한 별도 에셋.
- Tests: 규칙은 EditMode, 실제 배치·회수·서비스 연결은 PlayMode. 검증 씬은 Scene/Tests 아래.

새 정의 에셋을 추가하는 것과 건물 실행 상태를 추가하는 것을 구분한다. 쿨다운·지속 조사·연쇄 경로·발사체·생산 누적·강화 단계는 항상 개별 건물 런타임에 둔다.

## 8. 검증 항목

- **배치/회수:** 지면 건물과 토대 충돌, 경사·경계, 4칸/9칸 전체 예약, 이동 실패 원위치 유지, 회수 예정 동안 점유 유지, 토대와 위 포탑 일괄 확정/취소, 자원 건물 회수 시 생산 중단.
- **생산:** 각 주기 직전/경계/직후, 여러 주기를 넘는 dt, 용량 부족과 재개, 시험용 용량 명시, 여러 건물 타이머 독립, 비활성/취소/초기화 후 중복 생산 없음.
- **전투:** 지상/공중 필터, 사거리·각도 경계, 명중점 폭발, 연쇄 재방문/만료/감쇠, 관통 최대 수와 정렬, 레이저 대상 교체, 발칸 첫·마지막 발, 미사일 대상 중복 금지, EMP 피해 0과 상태 적용.
- **상태:** 화상 틱 수·피해, 과열의 출처별 추가 피해, 상태 재부여 규칙, 행동불가 중 이동/공격/특수 행동 차단, 상태 종료 복원. 아직 없는 적 행동은 차단 계약만 두고 구현 완료로 표시하지 않음.
- **강화/해금:** Lv.1과 최대 단계, 해금 경계, 정수 처리, 상한, 각 건물의 독립 레벨, 역수 수치 이중 적용 방지, UI/실제 수치 일치.
- **대규모:** 같은 시드·배치·적 수로 4천/1만/10만 비교. 이동·검색·피해/상태·연출을 분리 측정하며 CPU 중앙값/p95와 GC를 기록. 3회 비교에서 반복되는 10% 초과 악화 또는 새 전투 루프 상시 GC는 해결 후 이전.
- **측정 해석:** 기존 10만 적 약 15ms 기록은 이동/인덱스만 측정한 값이다. 신형 공격·상태·렌더링을 포함한 전체 프레임 성능의 근거로 재사용하지 않는다. 1억은 누적 요청이며 동시 1억 부하 검증을 뜻하지 않는다.
- **기존 호환:** 3개 맵/4종 기존 포탑/저장 복원과 현재 수정·확정 UI를 회귀 검증한다. 게임 빌드는 별도 요청 전 수행하지 않는다.

## 9. 완료 판정

문서 충돌이 해결된 16개 콘텐츠 정의가 등록되고, 일반 지면 생산과 토대 위 신형 공격이 실제 오픈월드에서 작동해야 적용 완료다. 모듈 코드만 존재하거나 에셋만 생성한 상태는 완료가 아니다. 미정 항목은 목록으로 남기고 해당 콘텐츠는 검증용/미완료로 구분한다.

## 구현 상태 (2026-09-17)

검증용 콘텐츠 16종의 연결과 Editor 실행 검증을 완료했다. 원문의 미정·상충 수치는 검증값으로 남겼다. 최종 제품 규칙과 성능 측정의 제한을 포함한 [적용 결과](자원_방어_건물_적용_결과.md)를 함께 확인한다.
