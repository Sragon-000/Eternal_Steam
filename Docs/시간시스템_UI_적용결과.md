# 시간 시스템과 UI 적용

2026-09-18. 이번 범위는 시간 상태·좌상단 UI·개발자 전환이다. 다른 적용계획 항목은 세부 기획 대기 상태로 유지한다.

- 공통 `GameClock`: 1일차 낮 시작, 낮→밤→다음 날 낮. 큰 delta도 누락하지 않고 반영한다. 정의/화면/전투에 의존하지 않는 개별 실행 객체다.
- `OpenWorldSandbox` Inspector의 DayDurationSeconds/NightDurationSeconds: 검증 기본값 낮 300초, 밤 180초. 시작 시 실행 상태로 복사한다. Play 중 Inspector 변경 즉시 반영은 지원하지 않는다.
- 준비/전투 상태 모두 시계가 진행한다. 수정 상태에서는 자동 정지한다. 기존 전투 실행/일시정지 버튼은 기존 전투 제어를 유지한다. 시간 정지는 별도 개발자 버튼으로 제공한다.
- 좌상단: 일차·낮밤·전환까지 남은 분:초·정지 이유. `WorldClockView`는 표시 값이 바뀔 때만 문자열을 갱신한다.
- Editor/Development 환경에서 낮으로·밤으로·시간 정지/재개 버튼을 표시한다. 강제 전환은 날짜를 유지하고 해당 단계의 시작으로 이동한다. 정지 여부는 유지한다.
- 새 패널에서 클릭/휠 입력은 월드 배치·카메라 줌으로 전달되지 않도록 기존 UI 차단 영역에 포함한다.
- 재시작하면 1일차 낮으로 초기화한다. 영구 저장, 기지별 라운드, 조명/하늘 표현, 자동 소환, 날짜별 소환량/능력치 변화, 경제 연결은 이번에 추가하지 않았다.

## 검증

원본 StartRegionSandbox의 Play 모드에서 `Tools/VerifyWorldClock.cs` 통과:
- 낮/밤 경계와 날짜 증가, 복수 날짜 경과, 정지, 잘못된 delta 무시.
- 실제 UI 이벤트로 낮/밤 전환·시간 재개, 날짜 유지.
- 준비 중 진행, 수정 중 정지, 상태 문구·좌상단 레이아웃.
- 전투 실행 상태와 소환 대기량을 변경하지 않음.

Unity 재컴파일 오류 없음. 게임 빌드 없이 원본 Editor에서 검증했다.

## 원형 시계 표시

위쪽 절반은 노란 낮, 아래쪽 절반은 남색 밤으로 표시한다. 바늘은 왼쪽에서 시작해 시계 방향으로 회전한다. 각 단계의 진행률을 반 바퀴에 대응시키므로 낮/밤 설정 시간이 달라도 두 영역은 정확히 절반이다. 실제 Game 화면을 캡처하여 형태와 기존 HUD 배치를 확인했다. 컴파일 오류 없음. 이번 재검증에서 자동 시간 진행 검사는 남은 시간 변화가 관측되지 않아 통과하지 못했다. 원형 표시·낮밤 진행률 계산·전환 버튼까지 확인했으며 자동 진행 재검증은 남아 있다. 기존 날짜/개발자 버튼 기능 변경은 없다.

## 에디터 저작 방식으로 변경

원형 시계와 낮/밤 라벨을 OpenWorldHud.uxml에 명시하고 크기·라벨 배치를 USS로 이전했다. DayNightDial은 UxmlElement로 등록하여 UI Builder에서 표시/편집 가능하다. WorldClockView는 기존 요소를 조회하고 진행률만 갱신하며 실행 중 UI 요소를 추가하지 않는다. Play를 실행하지 않은 상태에서 UXML 복제만으로 시계와 라벨 두 개가 로드되는 것을 검증했다. UI Toolkit 요소이므로 개별 GameObject 대신 UXML 계층에서 관리한다.
