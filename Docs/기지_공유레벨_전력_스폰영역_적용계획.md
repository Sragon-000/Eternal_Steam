## 1. 목표와 기존 계획 변경

**메인 기지 레벨은 캠페인 전체에서 공유하고, 전력은 각 기지에 독립적으로 저장·공급한다.** 일반 자원·전력·맵 에너지는 서로 다른 책임으로 관리한다.

| 데이터 | 공유 범위 | 용도 |
|---|---|---|
| 메인 기지 레벨 | 모든 맵 공통 | 메인 성장, 기존 기지 레벨 기반 해금·서브 상한의 기준 |
| 서브 기지 레벨 | 개별 기지 | 개별 성장, 범위·체력·전력 용량 |
| 일반 자원 | 캠페인 공통 — 기존 계획 E와 연결 | 기지·건물 강화 비용. 방어 건물의 상시 운용비로 소모하지 않음 |
| 전력 | 기지별 독립 | 발전기 생산, 해당 기지에 연결된 방어 건물의 초당 소비 |
| 지역 에너지 | 맵별 독립 | 기존 90% 보스 조건·오브 제작 |

- 기존 계획의 **새 맵 메인 Lv.1 / 맵별 메인 레벨 독립**은 폐기한다. 새 맵에서 활성화한 메인은 공통 레벨로 시작한다.
- 기존 메인의 최대 Lv.10, 고정 설치 범위 11×11, 메인 파괴 시 해당 맵 실패는 추가 변경 지시가 없으므로 유지한다.
- 서브 레벨은 자동으로 같이 오르지 않는다. 상한은 공통 메인 레벨, 맵별 수량 상한은 기존 min(공통 메인 레벨×5,10)을 유지한다.
- 전력 공급을 받지 못한 건물도 설치·선택·회수·피격·파괴·물리 차단이 가능해야 한다.
- 기존 외부 설치 허용, 범위 밖 비작동 규칙은 유지한다.
- ‘보스 스폰 9칸’은 **스폰 구역의 크기**다. 보스전 일반 적 소환 지점 8개를 9개로 변경하는 의미가 아니다.
- 날짜별 적 능력치 강화는 계속 제외한다. 기차/전력 코어 운송은 후속 범위다.

## 2. 현재 코드와 변경 지점

| 현재 코드 | 변경 이유와 방향 |
|---|---|
| `UpgradeModule.Level`이 개체별 상태 | 메인만 공유 레벨 제공자/강화 명령에 위임. 서브·포탑의 개별 레벨 유지 |
| `OpenWorldContent.LevelCap`이 현재 메인 레벨 조회 | 캠페인 레벨 조회와 ‘이 맵에 활성 메인이 있는가’를 분리. 공통 레벨이 높다고 메인 없이 서브를 설치할 수 없어야 함 |
| `BaseRegistry`가 모든 정상 기지의 영역 합집합으로 가동 판정 | 영역 판정 유지. 전력 공급 기지 선택은 별도 정책으로 추가 |
| `OwnerBaseId`는 최초 소유에 가까우며 자동 변경되지 않음 | `PowerBaseId` 등 공급 연결을 별도 보관. 전력 때문에 기존 소유 정보를 덮어쓰지 않음 |
| `ResourceBank.Exchange`는 단일 입력→출력 변환 | 여러 자원 강화 비용의 원자 결제에는 부적합. 다중 자원 검사·결제 계약 추가 |
| `ProductionModuleDefinition`은 일반 재고에 생산 | 전력 발전은 기지별 전력 저장소에 지급하는 별도 기능으로 구현 |
| `BuildingInstance.Tick`은 비작동 시 모든 운용 모듈을 건너뜀 | 전력 부족으로 체력·등록·회수까지 정지시키지 않음. 소비 모듈과 그에 연결된 공격 기능에만 전력 상태 적용 |
| `HordeTowerCombat`과 신규 `WeaponRuntime`이 별도 공격 경로 | 두 경로 모두 같은 전력 허가 상태 확인. 기존 포탑 4종의 무상 공격 우회 차단 |
| `NightSpawnPlanner`는 셀 ID, `MapAssaultController`는 보스 좌표 사용 | 위치 추첨과 별도로 스폰 구역 점유·지면·충돌 검사 추가 |
| 에너지/오브는 현재 Play 세션 상태 | 공통 레벨을 추가해도 저장 완료라고 보고하지 않음. 기존 계획 E의 캠페인 저장과 연결하여 검증 |

## 3. 개발 모듈과 계약

명칭은 구현 제안이다. 기능별 실행 상태를 두고 구성 지점에서 의존성을 명시적으로 전달한다. 전역 싱글턴·범용 이벤트 버스는 추가하지 않는다.

### A. 공통 메인 레벨

- `CampaignProgression`: 공통 메인 레벨의 단일 권한. 맵 이동·메인 회수 여부와 무관하게 레벨을 유지한다.
- `MainBaseLevelAdapter`: 개별 메인의 읽기 모델/강화 명령을 공통 상태에 연결한다.
- 강화 요청은 활성 메인·최대 레벨·기대 현재 레벨·비용을 재검사하고 한 번에 반영한다. 중복 클릭·복수 기지의 같은 단계 요청으로 이중 결제하지 않는다.
- 레벨 변경 시 로드된 메인들의 표시·전력 최대량·해금/서브 상한을 갱신한다. 미로드 맵은 다음 로드 때 공통 레벨을 참조한다.
- 레벨 공유로 현재 체력이나 현재 전력이 서로 복사되거나 완충되지 않는다.
- 구형 맵별 레벨 기록이 존재하면 유효한 최고 레벨로 병합한다. 잘못된 값은 검증 오류로 처리하고 원본 기록을 보존한다. 아직 저장 파일이 없는 세션은 Lv.1로 시작한다.

### B. 기지별 전력

- `BasePowerStorage`: 안정적인 BaseId별 현재량·최대량. 최대량은 해당 기지 종류/레벨의 데이터로 계산한다.
- `PowerProducerModule`: 발전량/초와 공급 기지 연결. Lv.1 발전기를 카탈로그에 등록하며 일반 지면에 설치한다.
- `PowerConsumerModule`: 소비량/초, 현재 공급 가능 여부, 연결된 기능 목록. UI 분류만 보고 모든 건물에 자동 부여하지 않는다.
- `PowerAssignmentPolicy`: 발전기·소비 건물이 어느 기지에 연결되는지 결정한다.
- `BasePowerSimulation`: 기지 단위로 생산/요청 소비를 모아 고정 시간 간격으로 계산한다. 건물 순회 순서로 공급 결과가 달라지지 않게 한다.
- `CombatPowerGate`: 신규 공격 모듈과 기존 포탑 어댑터가 공통 공급 상태를 사용한다. 공격 모듈이 제거된 건물에는 기본적으로 전력 소비 기능도 연결하지 않는다.
- 등록은 확정·활성화 후 시작한다. 임시 배치는 생산/소비하지 않고, 회수 예정은 회수 확정 전까지 유지한다. 파괴/회수 시 연결과 구독을 해제한다.

### C. 강화 결제

- `UpgradeCostDefinition`: 레벨별 자원 ID와 수량 목록. 최종 비용표는 기획 데이터로 받는다.
- `UpgradeTransaction`: 대상·상한·전체 잔고 검사 → 다중 자원 차감과 레벨 변경을 원자적으로 반영한다. 실패 시 잔고/레벨 모두 유지한다.
- 일반 생산/변환 레시피는 유지하되, 광물 재고를 공격 시 소모하는 경로는 추가하지 않는다.
- 비용 미정 상태는 검증용 무상 강화로 명시한다. 누락된 제품 비용 데이터를 조용히 무료 강화로 처리하지 않는다.

### D. 스폰 영역

- `SpawnFootprintDefinition`: 일반 1칸, 보스 9칸의 모양·기준점.
- `SpawnAreaValidator`: 모든 점유 셀의 맵 경계·지면·건물/스폰 구역 충돌 검사.
- `NightSpawnPlanner`: 균등 추첨·밤 동안 유지·위치 대체·예산 보존 책임을 그대로 유지한다.
- 일반 적 실제 생성에서는 기존 적 간 최소 간격을 별도로 검사한다. 1칸 지점이라고 여러 적을 겹쳐 생성하지 않는다.
- 보스의 안전 영역 예외는 유지한다. 안전 영역을 무시하는 것과 지면/건물 충돌을 무시하는 것은 별개다.

## 4. 미정 사항과 검증용 제안

아래는 **제품 확정 규칙이 아닌 구현 검증 제안**이다. 확정 전에는 교체 가능한 정책/설정으로 격리한다.

| 미정 항목 | 검증용 제안 |
|---|---|
| 전력 수치 | 발전/초, 방어별 소비/초, 메인·서브 레벨별 용량을 에셋으로 분리. 테스트 픽스처만 사용하고 최종 수치로 표시하지 않음 |
| 범위 중첩 시 기지 연결 | 기존 연결이 유효하면 유지. 연결이 없거나 끊기면 건물 전체 점유를 포함하는 정상 기지 중 최근접, 동거리면 안정 ID 순. 잔고가 부족하다는 이유만으로 다른 기지로 갈아타지 않음 |
| 발전기와 소비 건물의 범위 밖 배치 | 설치는 허용하되 연결될 기지가 없으면 생산/공급 중단. 외부 전초를 전력 저장 기지로 자동 승격하지 않음 |
| 전력 부족 시 공급 | 최초 검증은 해당 기지 소비 건물 전체의 1틱 수요를 충족할 때만 동시 공급. 부족하면 해당 틱 공격을 모두 중단하고 잔량 보존. 우선순위/부분 공급은 별도 정책으로 교체 가능 |
| 시간 계산 순서 | 동일 틱의 기존 잔고+발전량에서 승인된 소비를 차감한 뒤 남은 양을 용량으로 제한. 부족한 틱에서도 발전량은 저장하고 음수 잔고 금지 |
| 공격 중 전력 상실 | 신규 공격/조준 회전과 공격 쿨다운 진행을 멈추며 남은 쿨다운 보존. 이미 발사된 투사체/적에게 적용된 상태효과는 별도 수명대로 처리. 복구 시 미실행 공격을 몰아서 실행하지 않음 |
| 기지 용량 증가 | 최대량만 증가하고 현재량은 유지. 레벨 공유가 전력 보충 수단이 되지 않음 |
| 기지 회수/파괴 | 다른 기지로 자동 전송하지 않음. 회수 시 전력 보존/소멸 정책은 확정 필요. 검증은 반환되지 않는 정책으로 분리하고 제품 저장 규칙 확정 전 영구 데이터에 적용하지 않음 |
| 전력 UI 형식 | `78% · 현재량 / 최대량`, 생산/소비를 `+x/s / -y/s`로 병기. 문서의 예시 숫자를 계산식으로 간주하지 않음 |
| 보스 9칸의 모양 | 3×3 정사각형, 중앙 셀 기준 제안. 기획 1칸을 기존 2m·45도 격자로 사용하면 일반 2×2m, 보스 6×6m. 최종 칸/모양 정의와 구분 |
| 스폰 구역과 건설 충돌 | 활성 일반 스폰은 충돌 시 재선정하고 예산 유지. 보스 고정 구역은 미리 씬에서 표시·검증하고 건설 불가로 예약하는 안을 제안. 범위 안이라는 이유로 보스 위치를 제거하지 않음 |
| 구역 유효성 상실 | 적을 겹쳐 생성하거나 임의 위치로 이동시키지 않고 생성 보류+실패 사유 표시. 다른 지점에 남은 일반 예산 재분배 |

전력 시뮬레이션은 렌더 프레임 수와 독립적으로 같은 시간만큼 처리한다. 수정·게임 일시정지·맵 실패 시 정책을 기존 진행과 맞춘다. 이동 물리의 deltaTime 제한 때문에 자원/전력 시간까지 느려지는 문제를 피하도록 단일 진행 시간을 전달한다. 클리어된 현재 맵에서는 생산과 잔존 적에 대한 방어 소비를 계속 계산하며, 미로드 맵의 전력 시간 진행은 기존 E 저장·백그라운드 생산 정책과 함께 정한다.

## 5. 적용 순서와 완료 조건

### 1단계 — 공통 레벨과 상태 계약

공통 메인 레벨 제공자, 개별 메인 어댑터, 저장용 CampaignId/MapId/BaseId 계약을 추가한다. 기존 개체별 업그레이드는 서브·포탑에 유지한다.

완료 기준:
- 서로 다른 두 맵 컨텍스트의 메인이 동일 레벨을 보이며 한쪽 강화가 양쪽에 반영된다.
- 새 맵 메인도 공통 레벨로 시작하지만 HP·전력·서브 레벨은 공유하지 않는다.
- 메인이 없는 맵에서 서브 설치를 우회할 수 없다. 기존 1메인·5/10서브 제한 회귀 통과.
- 최고 레벨 병합·중복 요청·최대 Lv.10 검증. 실제 두 번째 맵이 없어도 논리 컨텍스트 테스트는 진행 가능하다.

### 2단계 — 스폰 1칸/9칸

셀 영역 검사와 표시를 연결하고, 고정 보스 위치의 전체 구역을 Editor에서 검증한다. 3×3 및 보스 구역 건설 제한은 위 제안 기준의 검증 설정으로 적용한다.

완료 기준:
- 전체 9칸 중 하나만 맵 밖/금지 지면/충돌이어도 실패한다.
- 일반 균등 추첨, 기지 수+1, 보스전 일반 8개, 안전 영역 대체, 최소 적 간격과 예산 보존이 유지된다.
- 구역 크기가 적 모델 크기나 소환 마릿수로 오해되지 않도록 씬 표시와 UI 설명을 분리한다.

### 3단계 — 독립 전력 시뮬레이션

저장·발전·소비·공급 기지 선택을 구현하고 검증용 발전기 에셋/간단한 외형을 만든다. 기존 카탈로그 기반 설치·회수 흐름을 사용한다.

완료 기준:
- 두 기지의 전력이 섞이지 않으며 중첩 구역에서도 건물 한 개가 중복 생산/소비하지 않는다.
- 범위/연결 변경, 기지 강화, 회수 취소·확정, 파괴 처리 후 중복 등록·잔고 음수가 없다.
- 같은 총 경과 시간을 다른 프레임 간격으로 진행해도 같은 결과. 가득 찬 저장소와 0 용량에서도 안정적으로 동작한다.

### 4단계 — 공격·UI 연결

기존 포탑 4종과 새 방어 건물의 공격 경로에 공급 허가를 연결한다. 전력은 선택한 기지 중심으로 표시하여 전 기지 합계를 하나의 사용 가능한 재고처럼 보이지 않게 한다.

UI는 기존 UXML/USS에 저작한다:
- 상단 기존 일반 재고·맵 에너지와 구분되는 선택 기지 전력 표시.
- 기지 선택 시 현재/최대량, 생산·요청 소비·실제 소비, 공급 부족 상태.
- 발전기/포탑 선택 시 공급 기지·초당 생산/소비·연결 실패 이유.

완료 기준:
- 전력 부족 시 모든 공격 경로가 같은 정책으로 중단/복구된다. 방벽은 별도 소비 기능이 없으면 전력을 쓰지 않는다.
- 피격·회수·점유·장애물·선택은 계속 작동한다. 사거리 선택 표시·냉각 재탐색·회전 속도 회귀 통과.
- 시간 정지/수정 중 전력 증감과 공격 없음. 플레이 중 설정 에셋 변경은 실행 상태에 즉시 반영하지 않는다.

### 5단계 — 강화 비용과 캠페인 저장 연결

비용표가 도착하면 자원 결제 기능을 연결한다. 기존 E 작업과 함께 공통 레벨·공유 재고·기지별 전력·연결·개별 건물 상태를 저장한다.

완료 기준:
- 다중 자원 중 하나라도 부족하면 부분 차감/레벨 변경 없음. 성공은 한 번만 적용.
- 저장/로드, 이전 기록의 최고 레벨 병합, 손상 데이터 검출, 중단된 저장 복구 검증.
- 두 번째 맵이 준비되면 실제 이동·재방문에서 공통 레벨과 독립 전력 확인. 그 전까지 실제 다중 맵 완료로 보고하지 않음.
- 기존 데모 저장 키는 유지하고 새 캠페인 저장은 별도 버전/파일에 기록한다. 비활성 맵 생산은 활성 씬과 이중 계산하지 않는다.

## 6. 공통 검증·성능 기준

- 단위 검증: 레벨 권한/상한/병합, 원자 결제, 전력 보존·비공유, 연결 안정성, 부족 정책, 스폰 전체 영역 검사.
- Play 검증: 실제 설치 → 기지 연결 → 발전 → 포탑 소비 → 부족/복구 → 회수/파괴 → UI 갱신.
- 기존 에너지 90%·야간 보스·10% 보상·오브 제작·클리어 흐름은 전력 저장소와 혼용 없이 유지한다.
- 공급 기지 탐색은 설치/회수/파괴/범위 변경 때 갱신한다. 매 프레임 모든 건물×모든 기지를 반복하지 않는다.
- 적 수에 비례하는 전력 처리 루프를 만들지 않는다. 4천/1만/10만 적 및 건물 수별 CPU 중앙값/p95·GC를 동일 환경 3회 비교한다. 새로운 상시 할당이나 반복되는 10% 초과 악화는 원인 수정 후 연결한다.
- 원본 `StartRegionSandbox`에서 진행한다. 씬은 `Assets/EternalSteam/Scene`에 유지하고 새 프로젝트·게임 빌드·기차 구현은 이번 범위에 넣지 않는다.

## 7. 착수 범위

**1단계 공통 메인 레벨부터 시작하고 2~4단계를 검증 설정으로 연결하는 순서**를 권장한다. 최종 밸런스 없이도 구조·중복 방지·독립 저장·공급 차단은 테스트할 수 있다. 다만 부족 정책·회수 전력·스폰 구역 건설 제한 등 위 제안은 기획 확정과 구분하여 결과 문서에 명시한다.

5단계의 실제 비용표, 영구 저장과 다중 맵 검증, 기차 운송, 재활성화 조건·보상은 각각 독립 완료 항목으로 남긴다. 사용자의 현재 요청은 적용계획 수립이며 이 문서 작성 자체가 구현 완료나 후속 구현 승인 기록은 아니다.
