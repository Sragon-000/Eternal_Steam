## 신규 파일을 놓는 기준

- 관리하는 모든 `.unity` 파일은 **Assets/EternalSteam/Scene/** 아래에 둔다. 기능·콘텐츠·샘플 폴더에는 씬을 만들지 않는다. 실제 게임 씬이 생기면 `Scene/Game`을 추가한다.
- 동작을 바꾸는 코드는 `Code/<기능>`에 둔다. 공통 계약은 실제 소비 관계에 맞춰 배치하며, 아직 필요 없는 Core 폴더나 빈 기능 폴더를 미리 늘리지 않는다.
- 특정 건물·적·환경의 설정과 외형은 `Content/<종류>/<콘텐츠>`에 모은다. 하위 폴더는 필요한 `Data`, `Prefabs`, `Art`만 만든다.
- 해당 기능 안에서만 공유하면 그 기능의 Common에 둔다. 여러 영역이 사용하는 폰트·UI 스타일·재질만 Shared에 둔다.
- UI의 C#은 담당 기능 또는 검증 코드에, UXML/USS/공용 테마는 `Shared/UI`에 둔다. 같은 화면의 UXML과 USS는 함께 이동한다.
- 검증 전용 코드는 `Tests/Sandbox`에 둔다. Editor 전용 도구와 자동 테스트는 별도 어셈블리로 관리한다.
- 기존 데모는 동작 변경 없이 `Code/LegacyDemo`에 모았다. 이 폴더 분리는 전투 코드의 기능별 리팩터링 완료를 의미하지 않는다.
- 외부 플러그인은 Packages 또는 제공자가 요구하는 경로를 사용한다. 프로젝트 소유 코드와 섞지 않는다.

## 어셈블리 의존성

- `EternalSteam.Runtime`: Code의 Building·Placement·Combat. LegacyDemo와 Sandbox를 참조하지 않는다.
- `EternalSteam.LegacyDemo`: 기존 데모만 포함한다. GUID와 namespace를 유지한다.
- `EternalSteam.Sandbox`: 검증 진행·입력·HUD. Runtime을 참조한다.
- `EternalSteam.Editor`: Runtime과 Sandbox를 참조하는 Editor 전용 도구.
- EditModeTests와 PlayModeTests: Runtime과 Sandbox를 참조한다.

폴더는 파일 소유권을 보여 주고, 어셈블리는 실제 코드 의존 경계를 제한한다. 폴더 이동만으로 게임 규칙이나 데이터 구조를 바꾸지 않는다.

## 이동 시 지킬 사항

Unity AssetDatabase 이동으로 파일 GUID를 유지한다. 씬 빌드 경로, 문자열 기반 AssetDatabase 경로, UXML/USS의 경로, 생성·검증 도구, 현재 실행 문서를 함께 갱신한다. 기존 씬 이름과 빌드 순서, PlayerPrefs 저장 키는 유지한다.

외부 작업 폴더의 중복 Docs와 기획 원본, 사용자 `_Recovery`는 이번 정리 대상이 아니다. 과거 검증 보고서는 당시 경로·검증 기록으로 보존하고, 현재 실행 위치는 이 문서와 실행 안내를 따른다.
