# 기지 기반 1차 적용 결과

2026-09-20. 「기지·맵 진행·에너지 오브 적용계획」 A 단계부터 원본 StartRegionSandbox에 적용했다. 전체 계획 B~F의 완료를 의미하지 않는다.

## 적용

- 메인 기지: 맵당 1개(예약 포함), 설치 후 회수 불가, Lv.1~10, 범위 11×11칸 고정, HP 100. 파괴 시 현재 공략 실패 표시와 전투/생산/시간/편집·소환 중단. 저장 삭제·자동 재시작은 없다.
- 서브 기지: 기존 installation.nexus ID를 보존하고 표시 이름을 서브 기지로 변경. 3×3칸 점유, 회수 가능. 레벨은 메인 이하이며 범위 11→20칸, 체력 100→280의 선형 증가.
- 서브 개수: 메인 Lv.1에서 5개, Lv.2 이상에서 10개. 실제 설치 수와 현재 예약 수를 함께 검사한다. 회수 예정은 확정까지 개수를 차지한다.
- 기지 한도 규칙은 지면 세션에 적용하고 기지를 토대 세션으로 우회 설치할 수 없게 한다. 생성 전 전체 배치 재검증과 원자적 확정은 기존 계약을 재사용한다.
- 실제 메인 레벨을 시작 맵 건물의 해금/강화 기준으로 연결. 기존 공통 검증 레벨은 호환 구성에 남긴다.
- 정상 메인/서브 기지 중 하나라도 건물 전체 점유를 덮으면 가동. 과거 소속 기지를 잃어도 다른 정상 기지가 덮고 있으면 유지한다. 영역 밖 건물은 남으며 행동만 정지한다.
- 시작 맵 생산 정의는 복제된 배치 프로필로 새 가동 규칙에 연결했다. 원본 DocumentContent 정의는 변경하지 않았다. 방벽 물리 차단/피격은 그대로 유지한다.
- 범위 표시는 강화 후 크기를 다시 읽는다. 선택 정보에 기지 레벨/범위와 서브 개수/한도를 표시한다.
- 기존 전초는 새 정책의 정상 기지/한도·가동 영역 제공자로 세지 않는다. 새 정책은 BasePlanningRules를 켠 시작 씬에 한정되며 다른 구성의 이전 소속 기반 영역 동작을 유지한다.

## 검증용 가정과 미정 항목

- 1칸=기존 2m, Y축45도 격자를 사용한다. 원문 수치대로 11칸은22m다. 50×50·1m 프리팹을 최종150×150칸 맵으로 확대하지 않았다.
- 메인 점유/초기 위치는 별도 자료가 없어 기존4×4칸과 유효 평지 선택을 유지한다. 고정 시작 지점 기획 완료로 보지 않는다.
- 범위 강화는 중심을 유지한다. 홀짝 범위의 셀 정렬 확정은 남아 있다.
- 강화 시 현재 HP는 기존 HealthModule의 체력 비율 보존 방식을 사용한다. 기지 비용/환급, 회수 후 레벨 보존은 새로 확정하지 않았다. 기존 회수 후 새 설치는 Lv.1이다.
- 안전 범위5칸/새 야간 스폰, 에너지, 보스/오브, 다중 맵·영구 저장, 재활성화는 아직 미구현. 현재 메인 실패는 세션 내 중단이며 재시작/체크포인트는 기획 대기다.

## 검증 결과

원본 Editor 재컴파일 오류 없음. Tools/VerifyBasePlanning.cs Play 통합 검증 통과:

- 메인 선행, 메인 중복 예약 거절·확정·회수 거절.
- 실제 서브5개 예약/확정 후6번째 거절, 메인Lv.2 후10개 설치와11번째 거절.
- 서브 레벨 메인 초과 거절, 양쪽Lv.10 상한, 서브범위11→20·HP100→280, 메인 범위 고정.
- 중첩 기지 중 소속 기지가 없어져도 다른 기지 범위로 가동 유지, 둘 다 없어지면 건물을 지우지 않고 비작동.
- 서브 파괴는 실패 아님, 메인 파괴는 실패, 이후 소환/재설치 차단.

개별 모듈/배치/피격 통합 검사이며 전체 데모·자연 시간 흐름·대규모 성능 회귀를 새로 통과한 것은 아니다. 게임 빌드는 하지 않았다. Tools/ApplyBasePlanning.cs는 초기 구성을 재현하는 도구이며 기존 BasePlanning 에셋이 있으면 덮어쓰지 않고 중단한다.
