# 회의 적용 상태 — 건설·영역·가동 분리

2026-09-17. 원본 `Eternal_Steam` Editor 연결 복구 후 스타트 지역 씬/에셋 생성을 완료하고 아래 플레이 회귀 검증을 통과했다. 게임 빌드와 다른 프로젝트를 이용한 대체 검증은 수행하지 않았다.

## 이번에 확인된 사용자 결정

- 허용 지형이면 범위 밖에도 설치 가능. 유효 범위 밖에서는 공격·생산 정지.
- 전력과 에너지는 이번 작업에서 제외.
- 원본 프로젝트에서만 작업. 게임 빌드를 실행하지 않음.

## 작성한 구현

| 모듈 | 동작 |
|---|---|
| BaseModuleDefinition / BaseRegistry | 기지 역할과 영역 제공자 역할 분리. 기지마다 런타임 ID, 배치 건물의 소속 고정. 넥서스 선택으로 다음 배치의 소속 선택 |
| BuildAreaModuleDefinition | 원/정사각형 공통 계약. 네 모서리 전체 포함, 경계 포함, XZ 판정. 동일 Boundary 데이터로 영역 테두리 표시 |
| BuildingInstance / 모듈 계약 | 가동 사유와 상태 변경 통지. IOperationalModule만 비작동 시 정지, ICombatModule은 준비 단계에서도 정지. 체력·선택·회수 유지 |
| 배치와 회수 | 새 프로필은 지면 설치 허용과 가동 범위를 분리. 공급자 회수 시 주변 건물을 제거하지 않음. 기존 프로필은 이전 규칙 유지 |
| 기존 4종 어댑터 | 자동 공격 모드에서 공통 가동 상태 확인. 기존 3개 맵의 연사 모드 변경 없음 |
| 월드 격자 | 카메라 주변 9개 재사용 메시. 2m 셀·45° 격자. 배치 수정 중에만 표시하고 확정·취소하면 숨김. 숨겨진 상태에서는 갱신하지 않음. 청크 변경 때만 다시 생성. 넥서스별 중복 격자 제거 |
| 표시 | 비작동 건물의 주황색 X, 선택 시 범위 밖/기지 상실 사유와 소속 기지 표시. 공격 반경은 기존대로 편집 밖에서 선택한 포탑만 표시 |
| RegionDefinition | 스타트 A/인접 B의 영역과 예정 자원 데이터. 생산 기능은 아직 연결하지 않음 |

가동 범위는 같은 소속 기지의 넥서스/전초가 제공한다. 전초는 넥서스가 아니므로 적 목적지가 되지 않는다. 넥서스 소실 시 전초와 그 종속 건물은 비작동으로 남는다. 범위 자체에 의존하는 영역 제공자 구성은 검증 오류로 차단해 순환 의존을 방지한다.

소속 없는 건물은 첫 기지가 등장하면 가장 가까운 기지에 한 번 귀속한다. 이후 새 기지 등장이나 기존 기지 소실로 자동 소속 이동하지 않는다. 이 초기 귀속은 검증 정책이다. 재귀속 UI 및 영구 ID 저장은 후속 범위다.

## 준비된 Editor 적용 도구

`Eternal Steam → Open World → Apply Meeting Construction` 또는 `Tools/ApplyMeetingConstruction.cs`를 실행한다. **원본 Editor에서 실행 완료했다.** 이 도구는 다음을 수행한다.

1. 기존 문서 카탈로그에서 넥서스·방어 건물을 별도 StartRegion 카탈로그로 복사한다. 기존 자원 건물 카탈로그를 유지한다.
2. 넥서스 한 변 80m, 전초 한 변 40m인 정사각형 영역을 설정한다. 크기는 검증값이다.
3. 외부 전초의 간단한 프리팹과 영역 모듈을 생성한다.
4. 기존 TWC 지형 씬을 `Assets/EternalSteam/Scene/Tests/StartRegionSandbox.unity`로 복사하고 새 구성만 연결한다. 원본 지형/씬을 덮어쓰지 않는다.
5. 맵의 X축 중앙을 기준으로 두 검증 지역과 서로 다른 자원 ID를 연결한다. 지형 자체는 변경하지 않는다.

원본 씬에 미저장 변경이 있거나 Play 중이면 적용 도구가 중단한다. 새 씬에는 `MeetingConstructionRules`를 사용하며 기존 OpenWorldSandbox 구성은 그대로 유지한다.

## 검증 결과와 남은 검증

Unity 설치에 포함된 C# 컴파일러와 원본 프로젝트의 어셈블리 참조로 Runtime, Combat, Economy, Progression, Presentation, LegacyBuildings, OpenWorldSandbox, OpenWorldEditor 및 적용/검증 도구의 컴파일을 확인했다. 이후 원본 Editor의 임포트/컴파일과 Play 진입도 확인했다. 오류 0개. 기존 renderer 이름 가림과 UI Toolkit PreventDefault 경고는 남아 있다. 초기 컴파일 검사 출력은 `/tmp`에만 만들었다. 이후 아래 검사는 원본 Editor의 Play 모드에서 실행했다.

`Tools/VerifyMeetingConstruction.cs`에 다음 회귀 시나리오를 작성했다. **전체 통과**:

- 정사각형 경계·모서리·시각화와 판정 일치.
- 외부 포탑 설치, 미확정 전초 제외, 전초 확정으로 가동.
- 회수 예정/취소는 범위 유지, 회수 확정으로 비작동, 재설치로 복원.
- 범위 밖 공격·생산 정지와 비작동 건물의 피해 수신.
- 기지 ID 독립·소속 유지·기지 소실 전파.
- 전초를 적 목적지에서 제외.
- 기존 포탑의 외부 설치·비작동·회수.
- 순환 의존 구성 차단, 예약 누수 및 넥서스별 중복 격자 없음.

추가로 `VerifyNexusGroundInput`, `VerifySelectedTowerRange`, `VerifyRadialTargeting`, `VerifyWorldGridVisibility`를 통과했다. 실제 클릭 배치/회수, 선택 시에만 공격 반경 표시, 신규 9종·기존 4종 원형 자동 공격, 수정 모드 격자 표시를 확인했다. 씬 재시작 후 기지/건물/예약이 비어 있고 월드 격자 하나만 존재하는 것을 확인했다.

청크 중앙에서 한 청크 이동 시 9개 중 3개 메시만 재생성했고 정지/숨김 시에는 재생성하지 않았다. 단일 관측 갱신 시간은 3.3863ms였으며 성능 기준값으로 취급하지 않는다. 첫 검사에서는 경계의 부동소수점 오차로 두 축을 건너 5개를 재생성했으므로 검사 시작점을 청크 중앙으로 바꿔 단일 축 이동을 검증했다. 4천/1만/10만 적의 3회 비교와 렌더링 포함 성능 측정은 미실시다.

적용 도구의 첫 실행에서 씬 전환 시 미저장 에셋 참조가 해제되는 오류를 발견해, 에셋 저장 후 씬 전환 및 카탈로그 재조회 순서로 수정했다. 수정 후 적용을 완료했다.

## 후속 단계

회의 계획의 기지별 Day/라운드·넥서스 지역 생산·새 저장 형식은 아직 구현하지 않았다. 건물을 공격하는 적은 아래 후속 작업에서 구현했다. 현재 완료 범위는 계획의 1~4단계 중 건설 검증 기반과 스타트 지역 조합이다. 전체 계획이 완료된 것은 아니다. 기존 3개 맵 전체 흐름 및 대규모 성능 재검증은 별도로 남아 있다. 전력·에너지는 사용자 결정에 따라 제외한다. 기존 영구 저장 키는 변경하지 않았다.

## 테스트 적 체력 수정

기존 소환 체력 1,000과 기관총 피해 10 때문에 100발이 필요하던 설정을 수정했다. `OpenWorldSandbox.VerificationEnemyHealth` 기본값은 10이며 소환 스트림 생성 시 설정을 복사한다. 이후 적 종류별 체력은 별도 콘텐츠 설정으로 확장할 수 있다. 현재 진행 중인 Play 세션은 재실행해야 새 스트림 설정이 적용된다.

원본 Editor에서 `Tools/VerifySandboxEnemyHealth.cs`를 실행해 실제 소환 스트림의 기본 체력 10/기관총 1발 처치, 설정 체력 20/2발 처치, 활성 슬롯 해제와 처치 수 증가를 확인했다. 피해·체력 시스템 자체는 유지하며 기존 데모 적 체력은 변경하지 않았다.

## 냉각 포탑 재탐색

오픈월드 자동 공격의 냉각 포탑은 `slowTime > 0`인 적을 표적에서 제외한다. 부채꼴로 함께 둔화된 적과 다른 냉각 포탑이 둔화한 적도 제외하며, 남은 적 중 최근접(동거리 ID 순)을 찾는다. 모두 둔화 상태면 발사를 쉬고, 둔화가 만료되면 다시 표적이 된다. 타겟 변경으로 공격 쿨다운을 초기화하지 않는다. 다른 포탑과 기존 데모의 방향 연사 경로는 변경하지 않았다.

원본 Editor에서 `VerifyFrostRetargeting` 통과: 부채꼴 동시 둔화 대상 제외, 기존 쿨다운 중 재조준, 전원 둔화 시 발사 중지, 만료 후 재탐색, 기관총의 기존 표적 유지.

## 포탑 회전 모듈

`TurretRotationDefinition` 에셋과 개체별 `TurretRotation` 실행 상태를 추가했다. `ITurretRotation` 계약은 현재 방향, 초당 회전 각도, 제한 회전/정렬 판정, 별도 속도 배율 변경을 제공한다. 공통 Runtime은 특정 포탑 종류나 씬을 참조하지 않는다. 모듈이 없는 기존 구성은 즉시 조준 호환 경로를 사용한다.

- 신규 방어 건물은 정의의 Modules에, 기존 4종은 SceneTower 프리팹의 Rotation에 개별 설정 에셋을 연결했다. 기존 4종도 공통 BuildingInstance 모듈로 실행된다.
- 검증 기본값: 기관총 240°/초, 대포 120°/초, 냉각/관통 화살 및 신규 포탑 180°/초. 설정 에셋별 변경 가능. 조준 허용 오차 기본 1°.
- 조준이 완료되기 전에는 새 공격을 발사하지 않는다. 회전 중에도 공격 쿨다운은 흐르며 타겟 변경으로 초기화하지 않는다. 이미 발사된 효과의 진행은 유지한다. EMP 같은 전방위 펄스는 방향 조준을 요구하지 않는다.
- 현재 강화 모듈은 레벨당 기본 속도의 10%를 가산한다. 별도 회전 업그레이드는 SetSpeedMultiplier로 연결할 수 있으며 최종 속도는 기본값 × 별도 배율 × 기존 강화 배율이다. 실행 중 변경은 개체에만 적용되고 공유 정의를 변경하지 않는다.
- 기존 4종에도 강화 모듈을 연결했으며 선택 후 기존 강화 버튼으로 회전 속도를 올릴 수 있다. 선택 정보에 현재 °/초를 표시한다. 기존 4종의 다른 능력치를 이 작업에서 강화 체계로 이전하지 않았다.

원본 Editor에서 VerifyTurretRotation, VerifyLegacyRotation, VerifyRadialTargeting, VerifySelectedTowerRange 통과. 각도 제한/조준 전 피해 없음/개체 독립/강화 배율/공유 에셋 불변/실제 기존 4종 정의 연결/9종 후방 공격/배치 회수와 선택 반경을 검증했다. 기존 후방 공격 검사의 1초 대기는 설정 회전 시간+공격 효과 도달 여유로 수정했다. 게임 빌드는 실행하지 않았다.

## 방벽·건물 피격·적 공격 후속 적용

방벽, 명시적 건물 전투 역할, 건물 체력, 지상/공중 적 공격을 두 오픈월드 씬에 연결했다. 기존 3개 맵 회귀도 다시 통과했다. 설정·모듈·검증 및 4천/1만/10만 적의 CPU·GC 측정은 [적용 결과](방벽_건물피격_적공격_적용결과.md)에 정리했다. 렌더링 포함 10만 적 60fps 검증이 완료된 것은 아니다.

## 적 전투 최적화 후속 적용

목표·접근 위치 캐시, 공격 후보 분리, 빈 건물 버킷 재사용, 지형 통행 스냅샷 및 정지 높이 조회 생략을 적용했다. [최적화 결과](적전투_최적화_결과.md)에 동일 조건 전후 비교와 실제 씬 프레임 측정·제한을 구분해 기록했다.
