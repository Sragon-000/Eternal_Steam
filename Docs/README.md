최신 확인: **2026-09-25**. 실행 기준은 원본 `Assets/EternalSteam/Scene/Tests/StartRegionSandbox.unity`다. 사용법은 [프로젝트 README](../README.md)를 따른다.

## 현재 구현

| 영역 | 적용 상태 | 현재 문서 |
|---|---|---|
| 시작 기지·맵 | 기존 모델로 메인 자동 설치, 정면 11×11칸, 맵 45° | [시작 루프](고정_메인기지_플레이루프_적용결과.md) |
| 건설·회수 | 예약/확정/취소, 두 클릭 방벽 직선 배치, 사각 회수 선택 | [건설 편집](드래그_건설_편집.md) |
| 전투 | 원형 자동 조준, 회전 모듈, 냉각 재탐색, 적의 건물/방벽 공격 | [건물 피격](방벽_건물피격_적공격_적용결과.md) |
| 시간·자원·전력 | 낮/밤, 자원 생산·상단 표시, 발전/기지 전력/포탑 소비 | [전력](공유레벨_전력_스폰영역_적용결과.md) |
| 맵 진행 | 유한 칸별 에너지, 날짜별 소환 예산, 보스와 오브 제작 | [맵 진행](맵에너지_야간소환_오브_적용결과.md) |
| 저장·패배 | 안전 저장·복원, 정상 백업, 영구 패배 기록, 확인 후 새 게임 | [저장 계약](단일_맵_저장_복원.md) |
| 강화 | 공통 결제 경로와 비용 정책. 실제 콘텐츠는 검증용 무료 | [저장·강화](단일_맵_저장_복원.md) |
| 미니맵 | 지형 개요·기지/건물/적/보스·카메라 범위, 클릭/드래그 이동, 접기 | [미니맵](미니맵_적용결과.md) |
| 레퍼런스 | 기존 디펜스 분석에 BELTFED 추가. 기능 채택과 구분 | [BELTFED](References/BELTFED.md) |

최근 레퍼런스 방향, 플레이어 캐릭터 없는 시작 경험, 고정 시작점과 지역 확장 논의는 [레퍼런스 방향과 시작 경험](References/레퍼런스_방향과_시작_경험.md)에 정리했다. 확정된 현재 구현과 제안 단계의 아이디어를 구분한다.

미니맵은 기존 우측 테스트 패널 안에 있다. 별도 렌더링 카메라 없이 지형 개요를 캐시하고, 적을 밀집도로 집계한다. 안개/탐험·발견 제한·미니맵 줌·핑은 포함하지 않는다.

저장 기능은 고정 메인/기지 규칙/맵 공략 설정을 갖춘 시작 씬에 연결된다. 모든 옛 검증 씬에 동일한 저장 정책이 적용됐다고 해석하지 않는다. 기존 Horde 데모의 PlayerPrefs는 별도다.

## 다음 작업과 기획 대기

- 실제 다중 맵 이동·재방문·비활성 맵 생산·재활성화, 기지별 독립 라운드.
- 최종 지역별 자원 제한, 건설/강화 비용표, 건물별 테크·개수 제한의 확정 규칙.
- 9종 오브 효과, 기차/자원 운송, 최종 맵·적·보스 디자인과 애니메이션.
- 지형 우회 길찾기, 저장 버전 마이그레이션, 전체 게임 성능 목표/플랫폼 검증.
- 추가 최적화는 [백로그](추가_개선_백로그.md)를 따른다. 최신 미니맵 추가를 10만 적 전체 프레임 성능 검증으로 간주하지 않는다.

## 문서 보관 원칙

- [Source](Source/README.md): 사용자 제공 문서 10개와 이미지 1개를 원본 바이트로 보관한다. 외부 링크·회의 내용은 별도 출처 기록이다.
- `적용계획` 문서: 작성 시점의 제안과 승인 범위. 현재 전체 구현 목록으로 사용하지 않는다.
- `적용결과` 문서: 해당 변경의 상세 내용과 당시 검증. 최신 상태 보충 안내를 우선한다.
- `Validation` / `Measurements`: 당시 검사·측정 근거. 과거 결과를 새 테스트 결과로 바꾸지 않는다.
- `References`: 레퍼런스의 확인된 사실과 프로젝트 검토 관점을 구분한다.

현재 상태가 충돌하면 최신 사용자 결정 → 실제 코드·씬 구성과 최신 검증 → 이 인덱스/루트 README → 과거 계획 순으로 확인한다.
