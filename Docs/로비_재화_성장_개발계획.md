# Eternal Steam — 로비·재화·성장 개발 계획

> 검토용 초안 · 2026-09-11 · 구현 전 계획
>
> 이번 작업은 계획 문서 작성까지다. 아래의 ‘기준’은 전달된 메모를 정리한 것이며, ‘제안’은 구현 전에 조정할 수 있는 설계다.

## 1. 개발 방향

전투에서 재화를 얻고, 로비에서 기지를 성장시키며, 기지 성장으로 포탑 강화의 상한과 새로운 포탑을 열어 주는 흐름을 만든다. 주 성장 축은 기지, 보조 성장 축은 포탑이다. 처음부터 전체 스킬트리를 만들지 않고 전투와 로비를 왕복하는 작은 완성본부터 검증한다.

**개발 순서: 관통 화살 포탑 → 기본 로비·재화·저장 → 기지 성장 → 포탑 강화·추가 종류 해금.**

‘포탑 3개 이후’는 우선 총·대포·화살의 **3종 구성이 갖춰진 다음**이라는 뜻으로 해석한다. 전장 설치 수를 3개로 제한한다는 뜻으로 적용하지 않는다. 이 해석은 확인이 필요하다.

## 2. 기준과 미확정 사항

| 항목 | 계획 기준 | 상태 |
| --- | --- | --- |
| 신규 포탑 | 진행 방향으로 적을 관통하는 화살 포탑 | 요청 기준 |
| 로비 | 기지 레벨·재화·포탑·출격을 보여 주는 단순한 화면 | 요청 기준 |
| 초기 구현 | 로비와 재화를 먼저 연결하고 강화는 후속 단계로 분리 | 요청 기준 |
| 성장 중심 | 기지를 올려 포탑 성장 가능 범위를 확장 | 요청 기준 |
| 최대 레벨 | 기지 12, 포탑 9 | 요청 기준 |
| 강화 조건 | 기지 4 → 포탑 3 / 기지 8 → 포탑 6 / 기지 12 → 포탑 9 | 마지막 상세안 우선 |
| 강화 효과 | 총·대포는 각 단계 공격력 +5, 화살은 +10 | 마지막 안을 초안 기준으로 채택 |
| 특수 강화 | 연사·폭발 범위·불장판·크기·도탄 | 후보로 보관, 초기 구현 제외 |
| 비용·보상·기본 공격력 | 플레이 테스트 후 수치 확정 | 미정 |

앞서 나온 ‘총 포탑 Lv.3에 기지 Lv.2 요구’ 예시는 뒤의 기지 4/8/12 조건과 충돌하므로 이 계획에는 적용하지 않는다. 퍼센트 수치를 영구적으로 금지한다는 의미는 아니며, 첫 강화 구현을 정수 공격력으로 단순화한다.

## 3. 현재 데모와 필요한 변경

현재 코드 기준으로 총·대포·냉각 포탑, 방향·사거리 지정, 설치 그리드, 수동 전투 시작, 3개 맵, 각 맵의 500/1,000/1,500마리 스테이지가 있다. 전원 처치 시 클리어하며 통과한 적이 있으면 전투 종료 시 실패한다. 체력이 0이면 즉시 패배한다.

총과 대포는 현재 피해량을 누적하지 않고 적을 즉시 제거한다. 따라서 **적 체력 → 피해 적용 → 체력 0에서 처치** 순서를 도입해야 공격력 +5/+10이 의미를 가진다. 냉각은 피해 없이 감속을 적용하는 기존 보조 포탑이다.

제안: 첫 로비의 기본 3종은 총·대포·화살로 구성하고, 냉각 포탑 코드는 유지하되 후속 해금 후보로 둔다. 냉각의 실제 기본 노출 여부와 해금 레벨은 확정 전까지 변경하지 않는다.

## 4. 첫 구현 범위 — 강화 없이 연결되는 게임

### 4.1 관통 화살 포탑과 피해 시스템

- 총은 빠른 단일 공격, 대포는 범위 공격, 화살은 일렬로 정렬된 적의 관통 공격을 담당한다.
- 화살은 설치 방향과 설정 사거리를 사용하고 전투 중 적 유무와 관계없이 발사한다.
- 초기 제안은 사거리까지 직진하며 만나는 모든 적에게 한 발당 한 번씩 피해를 주는 방식이다. 기본 도탄과 관통 시 피해 감소는 넣지 않는다.
- 빠른 화살이 한 프레임 사이 적을 지나쳐도 맞도록 이전 위치와 현재 위치 사이 구간으로 판정한다. 적 슬롯을 재사용해도 새 적과 이전 적을 구분한다.
- 기본 피해량·화살 속도·발사 간격은 데이터로 분리하고 미정 값으로 둔다. 적 체력 역시 함께 조정한다.

완료 기준: 일렬의 여러 적이 한 발에 피해를 받으며, 뒤쪽·사거리 밖 적은 제외된다. 같은 적에 중복 피해가 없고, 총과 대포도 동일한 체력·처치 처리를 사용한다.

### 4.2 평범한 로비

한 화면에 상단 재화와 기지 레벨, 중앙 출격 버튼과 맵·스테이지 선택, 하단 포탑 3종의 기본 정보를 배치한다. 처음에는 복잡한 기지 건설 화면이나 스킬트리 지도를 만들지 않는다.

흐름은 **로비 → 맵·스테이지 선택 → 설치 → 시작 버튼 → 전투 → 결과 → 로비 또는 다음 스테이지 설치**다. 미해금 스테이지는 조건을 표시한다. 첫 단계에서는 기지와 포탑 레벨을 보여 주되 강화 구매는 제공하지 않는다.

현재의 무조건 다음 스테이지 이동 버튼은 결과 처리 이후 이동하도록 연결한다. 연속 진행 시 배치를 유지하고, 로비에서 새로 출격하면 해당 맵의 기본 배치로 시작하는 안을 제안한다. 영구 배치 저장은 제외한다.

### 4.3 단일 재화와 보상

초기에는 영구 재화 한 종류만 사용한다. 이름은 임시로 ‘부품’이라 부르고, 별도의 전투용 설치 비용은 추가하지 않는다. 재화는 우선 축적·표시·저장하고 기지와 포탑에 사용하는 기능은 다음 단계에서 연결한다.

제안 보상 규칙:

- 클리어 보상은 반복 보상과 최초 클리어 추가 보상으로 나눈다.
- 실패·중도 이탈은 초기 버전에서 보상 없음으로 단순화한다. 처치 비례 실패 보상은 플레이 테스트 후 검토한다.
- 결과 확정 시 1회만 지급한다. 결과창 재열기, 다음 버튼 연타, 게임 재실행으로 중복 지급되지 않아야 한다.
- 재화 잔액, 클리어 기록, 지급 처리한 전투 식별자를 하나의 저장 상태로 반영한다.
- 맵·스테이지별 보상과 나중의 강화 비용은 데이터로 관리한다. 필요한 반복 횟수는 `올림((다음 목표 비용 - 현재 재화) / 반복 보상)`으로 검토한다.

첫 클리어 후에도 성장이 막히지 않도록 이미 깬 스테이지를 재도전할 수 있어야 한다. 보상 액수나 예상 플레이 시간은 아직 확정하지 않는다.

### 4.4 로컬 저장

재화, 기지 레벨, 포탑 종류별 영구 강화 레벨, 해금 목록, 맵별 최고 클리어 스테이지, 최초 보상 수령 여부, 저장 버전을 보관한다. 전투 중 적 위치와 탄환은 저장하지 않는다.

종료 후 로비 상태를 복원하고, 파일이 없으면 새 게임을 만든다. 저장 도중 종료되는 경우를 고려해 임시 파일 작성 후 교체와 백업 복구를 제공한다. 온라인 계정·클라우드 저장은 이번 범위 밖이다.

## 5. 후속 구현 — 기지 중심 성장

기지는 Lv.1에서 시작해 Lv.12까지 재화로 성장한다. 구매 조건은 현재 레벨, 다음 레벨 비용, 최대 레벨 여부다. 포탑은 재화만 충분하다고 올릴 수 없고 **요구 기지 레벨도 충족**해야 한다. 강화는 설치된 개별 포탑이 아닌 종류별 영구 강화로 적용하는 안을 제안한다.

| 기지 레벨 | 포탑 강화 허용 범위 | 설명 |
| --- | --- | --- |
| 1~3 | 기본 상태 | 시작 포탑은 사용 가능, 첫 강화는 잠김 — 제안 |
| 4~7 | Lv.3까지 | 첫 강화 구간 해금 |
| 8~11 | Lv.6까지 | 두 번째 강화 구간 해금 |
| 12 | Lv.9까지 | 최종 강화 구간 해금 |

기지 레벨을 올리는 것만으로 포탑 공격력이 자동으로 오르지는 않는다. 강화 가능 상한을 열고, 별도 포탑 강화 구매로 효과를 얻는다. 로비에서는 ‘기지 Lv.4 필요’, ‘부품 부족’, ‘최대 레벨’을 구분해서 보여 준다.

기지의 중간 레벨에 별도 효과가 없으면 4/8/12까지의 구매가 단순 통행료처럼 느껴질 수 있다. 우선 다음 해금까지 남은 레벨을 보여 주고, 테스트 결과에 따라 신규 포탑 해금 등을 배치한다. 기지 체력 증가·설치 수 증가 같은 추가 효과는 아직 확정하지 않는다.

### 강화 레벨 사이 구간 처리

현재 메모에는 Lv.3/6/9 효과만 있고 Lv.1/2/4/5/7/8 효과가 없다. 효과 없는 강화를 여러 번 구매하게 만드는 것은 피하는 편이 좋다.

**초안 제안: 기본 Lv.0 → Lv.3 → Lv.6 → Lv.9의 세 번 구매로 구현한다.** Lv.0은 미강화 상태다. 1씩 올리는 9단계 방식이 필요하다면 각 레벨의 효과와 비용 분배를 먼저 추가로 정한다. 이 항목은 구현 전 결정 사항이다.

| 포탑 | Lv.3 / 기지 4 필요 | Lv.6 / 기지 8 필요 | Lv.9 / 기지 12 필요 | 최종 누적 증가 |
| --- | --- | --- | --- | --- |
| 총 | 공격력 +5 | 공격력 +5 | 공격력 +5 | 기본 대비 +15 |
| 대포 | 공격력 +5 | 공격력 +5 | 공격력 +5 | 기본 대비 +15 |
| 관통 화살 | 공격력 +10 | 공격력 +10 | 공격력 +10 | 기본 대비 +30 |

수치는 단계마다 누적한다. 강화 구매는 로비에서만 가능하고 출격 시 능력치를 확정한다. 이렇게 하면 전투 중 강화로 피해량이 갑자기 바뀌지 않는다.

화살이 여러 적을 맞히므로 +10의 실제 효과는 총의 +5보다 훨씬 클 수 있다. 기본 공격력·발사 속도·적 체력을 함께 시험하고, 정수만 사용하더라도 평균 처치 시간이 얼마나 달라지는지 확인한다.

## 6. 구현 작업 순서와 완료 조건

| 단계 | 작업 | 완료 조건 |
| --- | --- | --- |
| A | 적 체력·공통 피해 처리·관통 화살 | 관통·중복 피해·사거리 검증, 기존 포탑과 전원 처치 판정 정상 |
| B | 기본 로비·출격·결과 화면 | 세 맵을 오가며 설치와 수동 시작 유지, 성공·실패 후 복귀 가능 |
| C | 단일 재화·보상·로컬 저장 | 최초/반복 보상 구분, 중복 지급 방지, 재실행 후 잔액과 진행 복원 |
| 1차 검토 | A~C를 팀에서 플레이 | 강화 없이도 전투→결과→로비 순환 확인, 수량과 전투 시간 조정 |
| D | 기지 Lv.1~12·비용·상한 해금 | 재화 부족·최대 레벨·4/8/12 경계 조건 검증 |
| E | 포탑 3단계 공격력 강화 | 재화와 기지 조건 동시 검사, 누적 공격력·종류별 저장 검증 |
| F | 신규 종류 해금·특수 강화 검토 | 기본 순환 검증 후 별도 범위로 결정 |

이번 계획의 첫 구현 목표는 A~C다. D~F를 동시에 만들지 않는다. 단계별 일정은 A의 피해 처리 변경량과 로비 UI 구성을 확인한 뒤 산정한다.

## 7. 코드 구성 제안

현재 HordeSimulation이 적 생성·공격·스테이지를 함께 관리한다. 전투 전체를 한 번에 다시 쓰기보다 피해 처리부터 분리하고, 영구 진행 데이터가 전투 씬을 이동해도 유지되도록 구성한다.

- 전투: 적 체력과 피해 적용, 화살 이동·관통 판정, 스테이지 결과 생성.
- 데이터: 포탑 기본 능력치, 스테이지 수량·보상, 기지 비용, 포탑 강화 조건·효과 테이블.
- 영구 진행: 재화·기지·포탑·해금·클리어 기록을 담는 저장 데이터.
- 서비스: 결과 보상 확정, 강화 조건 검사와 재화 차감, 저장·복구.
- 화면: 로비·출격 선택·결과·후속 강화 패널. 화면 버튼 외에도 실제 구매 처리에서 조건을 다시 검사한다.

보상 지급과 강화 구매는 데이터 변경을 한 번에 저장한다. 잔액만 차감되고 레벨은 저장되지 않는 식의 상태를 방지한다. 디버그 맵 이동·리셋 기능은 실제 보상 지급 경로와 구분한다.

## 8. 구현 전에 남은 결정

1. ‘포탑 3개’가 총·대포·화살의 3종 구성을 의미하는가? 기존 냉각은 기본 목록에 남길 것인가, 후속 해금으로 둘 것인가?
2. 포탑 강화는 제안한 3회 구매 방식인가, 매 레벨 구매하는 9단계 방식인가?
3. 기본 적 체력·포탑 피해량, 스테이지 보상, 기지·포탑 비용은 얼마인가? 첫 테스트 후 함께 맞춘다.
4. 전원 처치에 실패하면 보상이 없는 규칙을 유지할 것인가? 성장 전에도 첫 스테이지를 충분히 깰 수 있어야 한다.

현 단계의 목표는 플레이 시간을 수치로 늘리는 것보다 **다음에 얻고 싶은 해금이 보이고, 한 번 더 출격할 이유가 생기는지** 확인하는 것이다. 특수 강화와 추가 포탑은 이 흐름을 검증한 후 확장한다.
