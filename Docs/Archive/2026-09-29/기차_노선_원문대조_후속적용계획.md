이번 요청은 이 계획 수립까지이며 아래 단계의 게임 코드 변경은 아직 수행하지 않았다. 원문의 미결 정책을 구현 필수 누락과 섞지 않고, 확정 가능한 버그/화면부터 처리한다.

| 단계 | 순서·작업 | 주요 파일/계층 | 종료 조건 |
|---|---|---|---|
| A0 회귀 기준 | G01/G02 실패 사례를 정식 테스트에 추가. 미설정 저장·오류 회수·3기지 이름 fixture 준비 | RailwayTests, 저장 Play 도구 | 현재 코드에서 두 실패 재현, 기존 정상 경로 유지 확인 |

의존성: A0→A1→A2→A3→A4→A5를 권고한다. A2의 확인 상태는 A3에서 만드는 `DraftPreview` 계약을 먼저 정해 빈 임시 패널을 중복 제작하지 않는다. A4의 이름 저장 변경은 기존 baseId를 바꾸지 않고 이름/순번 메타데이터만 추가한다. v1 이관 및 기존 v2 지원 사례를 동시에 유지한다.

### 구현 계약 제안

- `RouteEditorState`: List / StationContext / Editing / Validating / Confirming / DiscardPrompt / Detail. 각 상태는 출처 문맥, 선택 역/구간, 원본 revision, dirty 여부를 명시적으로 가진다. 목록 정렬 인덱스 대신 stationId/routeId를 유지한다.
- `RouteValidationResult`: 유효성, 정상 구간 목록, 오류 코드/대상/수정 안내. 확인 화면은 이 결과와 검증한 토폴로지 revision을 보유하되 Commit에서 재검사한다. `bool valid`만으로 오래된 표시를 유지하지 않는다.
- `DraftPreview`: 실제 RailRoute와 분리된 읽기용 역/포트/길이/예상시간/표시 데이터. 노선이나 기차를 먼저 생성해서 프리뷰하지 않는다.
- `CanEditInfrastructure`: segmentPaid인 중간 구간 정지는 잠금 유지. 역의 오류 정지/연료 대기는 미사용 선로의 복구를 허용하고 점유 역은 별도 보호. 회수 전체 선택 집합에 대한 최종 상태를 검사한다.
- `RailwaySettings`/공통 Quote: 현재 검증 숫자를 기본값으로 옮기고 화물/연료/비용/전력을 구분. 설정 변경의 저장 호환 처리 없이는 기존 구성 지문을 조용히 바꾸지 않는다.
- 새 Canvas/버튼/포트/오류/확인 표시는 씬·프리팹에 저장하고 Play에서는 상태·텍스트·위치만 갱신한다. 코드 작성, 저장 참조 검사, 실제 Play 검사를 별도 증거로 남긴다.

### 완료 판정

`테스트 n개 통과`만으로 닫지 않는다. G01~G10/G12 및 채택한 G11 해석에 각각 코드·저장 계층·재현/인수 증거를 붙인다. 원문 TBD는 채택한 기본안과 미확정 항목을 표시하고, 확장 제외를 억지로 구현하지 않는다. 마지막 문서 상태는 “원문 핵심 기능 구현”, “UI 행동 구현”, “정책 확정”, “실기 검증”을 별도 열로 보고한다.
