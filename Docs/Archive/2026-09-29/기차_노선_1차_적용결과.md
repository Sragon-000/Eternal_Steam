## 후속 Editor 확인 (2026-09-28)

재실행 후 PID 67345가 연결됐으며 시작 씬의 메인 스레드 조회에 응답했다. 당시 컴파일/갱신/Play는 모두 꺼져 있었고 씬은 미수정 상태였다. `EternalSteam.EditModeTests` 어셈블리를 실제 Unity NUnit 러너로 실행해 **72/72 통과**했다. [결과 JSON](../../Validation/2026-09-28-railway-editor-tests.json)을 보관했다. 아래 최초 미연결 기록을 이 범위에서 갱신한다. 전체 테스트 어셈블리 실행·실제 운송 Play·구버전 저장 이관 인수는 여전히 남아 있다.

새 Editor의 2초 스택 표본에서는 이벤트 대기와 Editor tick이 관측됐고 게임 코드 무한 반복은 확인되지 않았다. 이는 사용자에게 보인 멈춤의 원인을 확정하거나 재발이 해결됐다는 의미가 아니다. 오래된 별도 프로세스는 강제 종료하지 않았다.

## 적용 범위

|---|---|

| 철도 시설 | 1셀 선로, 2×2 역, 기본 기차 프리팹 및 석탄 검증용 생산 시설. 직선 예약 도구로 구간을 이어 건설하며 역 임시 배치 방향을 90°씩 변경 |
| 노선 | 서로 다른 2개 이상 역, 진입/진출 포트, 마지막→첫 역 순환 검증. 단절·분기·교차·중복·타 노선 선로 공유 거부. 요청 ID 재사용 시 기차 중복 생성 방지 |
| 운송 | 노선당 기차 1대, 화물 1종/1,000개, 자원 지정 후 변경 금지. 역에서 하역 후 적재, 10초 정차. 부족 자원·도착 용량에 맞춰 실제 이동량 제한 |
| 운행 | 수동 시작·석탄 보급. 이동 중 중지는 다음 역까지 진행 후 정지. 구간 출발 때 연료 지불, 부족 시 수동 재시작 대기. 오류 발생 시 위치·화물 보존 |
| 수정·회수 | 역에 정지한 기차의 노선 수정 시 기차와 화물 유지. 현재 역 제거 금지. 운행 중 사용 시설 회수 차단. 운행 중 예약 수정은 후속 |

| 저장 | payload v2에 기지 재고·노선·기차·역 순번 저장. v1 원본을 해시별 보관한 뒤 공유 재고를 메인에 1회 이관하는 경로 추가. 초과 용량 재고 보존, 복원 중 저장 건물 용량 중복 합산 방지 |

주요 구현은 `Assets/EternalSteam/Code/Railway`, `Code/Economy/BaseInventoryRegistry.cs`, `Code/Economy/ConstructionPurchase.cs`, `Tests/OpenWorld/Runtime/Railway*.cs`, `SingleMapPersistence.cs`다. 신규 콘텐츠는 `Content/Buildings/Railway`에 있다. 철도 코어 어셈블리는 Runtime에만 의존하고, 씬 연결부가 재고·건설·UI를 연결한다.

정적 UI는 런타임에 생성하지 않는다. 씬에 각 84개 GameObject와 30개 철도 버튼 콜백을 저장했다. 런타임은 표시·선로 형상·노선 강조와 기차 인스턴스를 갱신한다. `OpenWorldSandbox`에도 계층은 저장했지만 기지 규칙이 없는 해당 씬에서는 철도 조작을 차단한다. 실제 사용 기준은 `StartRegionSandbox`다.

## 검증용 수치와 현재 제한

선로 철 1개/셀, 역 철 10개, 석탄 생산 2초당 1개, 연료 계수 1, 선로 셀당 이동 1초는 **검증용 설정**이다. 최종 밸런스 승인으로 해석하지 않는다. 기존 비철도 건물의 무료 검증 정책은 유지했다. 기차 외형과 설치칸은 확인용 프리팹이며 설치칸 무기 기능은 아직 없다.

이 버전은 자동 경로 건설·선로 공유·신호·맵 간 이동·운행 중 예약 변경·이동 방어를 포함하지 않는다. 포트 번호의 월드 표시, 오류 구간 강조, 최종 아트와 반응형 화면 품질도 추가 검증·개선 대상이다. 다중 역 모델은 있지만 3·4역 실제 인수 시나리오는 아직 실행하지 않았다.

## Editor에서 확인할 사용 순서

다음은 **검증 절차이며 실행 성공 기록이 아니다.**

1. Unity에서 `Assets/EternalSteam/Scene/Tests/StartRegionSandbox.unity`를 연다. 컴파일·프리팹·씬 import 오류와 RailwayInterface/Presentation 참조를 확인한다.
2. 기존 진행으로 두 기지를 확보하고 각 기지에 필요한 철·석탄을 준비한다. 선택 기지 변경 시 자원 표시가 독립적인지 확인한다.
3. 철도 도구에서 각 기지 영역에 역을 예약하고 확정한다. 소속 기지의 철만 차감되는지 확인한다. 방향 변경은 임시 배치 후 확정 전에 한다.
4. 역 A 진출→역 B 진입, 역 B 진출→역 A 진입을 서로 닿거나 분기하지 않는 별도 선로로 연결한다. 기본 포트 번호는 1:서, 2:동, 3:남, 4:북이며 역 회전을 따른다.
5. 새 노선에서 맵의 역을 선택하고 추가한다. 역 순서·포트를 설정한 뒤 검증→확정한다. 기차 1대가 정지 대기하는지 확인한다.
6. 상세에서 자원 ID(예: `iron`)와 각 역 적재/하역량을 설정한다. 출발 역 소속 기지에서 석탄을 보급하고 수동 시작한다.
7. 출발지 감소량=기차 적재량+도착지 증가량인지 확인한다. 도착 재고 가득 참, 연료 부족, 중지·재개, 분기 추가와 오류 복구도 검사한다.
8. 기존 안전 저장 조건에서 이동·정차 상태를 각각 저장한다. 다시 열어 재고·화물·연료·위치·정차 시간이 보존되고 중복 하역/연료 차감이 없는지 확인한다.
9. 별도 v1 저장 복사본으로 원본 보관→메인 1회 이관→재실행 시 재이관 없음과 백업 복구를 확인한다. 실제 사용자 저장을 검증용으로 임의 수정하지 않는다.

## 수행한 검사와 근거

- Unity 번들 Roslyn과 프로젝트 참조를 사용한 Runtime·Economy·Railway·OpenWorldSandbox·EditModeTests **5개 어셈블리 컴파일 통과**. 기존 숨김 멤버/구 UI API 경고가 남는다.
- 독립 managed 검사 **경제 8개 + 철도 9개 통과**. 기지 분리, 비용 원자 처리, 초과 재고 보존, 순환 배송, 용량 제한, 수동 재시작, 선로 공유/분기 거부, 시간 분할 일치, 잘못된 초안·저장 수량 거부 포함. [결과 JSON](../../Validation/2026-09-28-railway-independent-checks.json)
- 두 씬의 신규 로컬 참조·외부 에셋 root ID·콜백 정적 검사 통과. [결과 JSON](../../Validation/2026-09-28-railway-scene-references.json)
- 기존 `verify_authored_hierarchy.py`의 7개 씬 정적 검사 통과.

독립 검사는 synthetic building handle을 사용하며 Unity 생명주기·물리·렌더링·JsonUtility 저장 왕복을 대신하지 않는다. EditModeTests는 컴파일만 했고 Unity NUnit 러너에서 실행하지 않았다. 이전 문서의 89개 NUnit/Play 통과 기록은 이번 변경 전 결과다.

재현 도구: `python3 Tools/run_railway_checks.py`, `python3 Tools/verify_railway_authoring.py`, `python3 Tools/verify_authored_hierarchy.py`. 컴파일 도구는 로컬 Unity 6000.3.14f1과 기존 Library/Bee 참조를 사용한다. `author_railway_offline.py`는 이번 오프라인 씬 저작 도구이며 일반 런타임 초기화 코드가 아니다.

## 최초 환경 차단 기록과 후속 순서

Unity 프로세스는 실행 중으로 탐지되지만 CLI 연결이 없고 화면 조회도 응답하지 않았다. 기존 Editor를 강제 종료하지 않았다. 사용자에게 미저장 작업 저장 후 프로젝트 재실행을 요청한 상태다.

후속 실행에서 import·NUnit 104개·두 기지 운송·저장 왕복·합성 v1 이관을 확인했다. 남은 다중 역/회전/입력/이관 사례를 보강해 P1~P4 인수를 마친다. 그 후 계획의 P5 예약 노선 수정, P6 이동 방어를 적용한다. 역 상실·전력과 이동 방어의 최종 정책 및 비용 밸런스는 계획의 결정 항목을 따른다.

원문 [4.3](<../../Source/Attachments/4.3 기차.md>)·[4.4](<../../Source/Attachments/4.4 노선.md>)는 보관본을 수정하지 않았다. 이 문서는 실제 변경과 검증 한계를 기록한 파생 문서다.
