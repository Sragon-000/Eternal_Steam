## 변경

- G01: TrainState의 미설정 자원을 빈 문자열 기본값으로 두고 `HasCargoResource`로 구형 null과 빈 문자열을 동일하게 판정한다. Configure의 최초 지정, Start의 미지정 차단, Snapshot의 미지정 화물 수량 검증, 실제 저장기의 카탈로그 ID 검증, HUD의 미지정 표시가 같은 판정을 사용한다. 유효한 자원 지정 후 다른 자원으로 바꾸는 제한은 유지한다. 빈 문자열 외 미등록 ID는 저장기 카탈로그 검사에서 계속 거부한다. 저장 스키마 변경은 없다.
- G02: 선로 회수 가능 상태를 Stopped/RouteError/FuelWait 중 역 정지 상태로 제한한다. `segmentPaid`가 참인 중간 구간 오류는 계속 차단하고, 기차가 점유한 역도 계속 보호한다. Dwelling/Moving/StopRequested는 허용하지 않는다. 이 판정은 기존 WorldEditSession 확정 경로에서 그대로 호출된다. 회수 판정은 재고·연료·방문 처리 상태를 수정하지 않는다.
- NUnit 회귀 5사례를 추가했다: null/빈 문자열의 JSON 왕복 후 최초 지정, 미지정 화물에 수량을 숨긴 저장 거부, 역 오류 후 추가 회수와 점유 역 보호, 이동 중 오류 보호. 이번에는 컴파일만 확인했고 NUnit 실행 완료로 세지 않는다.
- 독립 철도 검사에 최초 지정/변경 금지, 오류 후 연속 회수, 점유 역/중간 구간 보호, 연료 대기 회수, 미지정 화물 저장 거부를 추가했다. 검사 도구에 출력 경로 인자를 추가하여 기존 실행 기록을 덮어쓰지 않았다.

- 수정 전 독립 검사에서 `first assignment rejected` 실패를 확인했다. [실패 기록](../../Validation/2026-09-28-railway-a1-red.json). G02의 수정 전 Unity 재현은 [이전 감사 증거](../../Validation/2026-09-28-railway-gap-probes.json)를 따른다.

- [독립 검사 결과](../../Validation/2026-09-28-railway-a1-independent-checks.json): 경제 8 + 철도 12 = **20개 통과**. 합성 BuildingInstance로 실제 관리 코드 경로를 실행한 결과이며 Unity 수명주기·JsonUtility·실제 저장/재시작 검증을 대체하지 않는다.
- CLI 연결 실패 후 pipeline list에서 실행 중 Editor 등록 3개, 응답 서버 0개, Safe Mode 감지 0개를 확인했다. 사용자 Editor를 종료하거나 씬을 저장/리로드하지 않았다. 실제 NUnit 전체 실행, 미설정 노선의 SingleMapPersistence 저장→재시작→최초 품목 지정, 실제 건설 회수 입력은 아직 검증하지 못했다. 이전 141개 테스트를 새 실행 결과로 인용하지 않는다.
- 게임 씬/프리팹과 원본 첨부는 수정하지 않았다. 기존 씬 YAML의 trailing whitespace는 이번 변경에서 정리하지 않았다.
