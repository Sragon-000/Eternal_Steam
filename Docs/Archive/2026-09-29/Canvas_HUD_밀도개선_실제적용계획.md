# Canvas HUD 밀도 개선 실제 적용 계획

작성: 2026-09-28. 후속 상태: **두 현재 씬에 적용 완료**. [실제 적용 결과와 검증 범위](../../Validation/2026-09-28-compact-canvas-hud.md)를 참고한다. 아래는 적용 전 수립한 계획이다. 사용자의 “UI가 너무 큼직하다”는 피드백에 대한 후속 적용 계획이다. 이번 작업에서는 문서만 작성한다.

## 1. 적용 기준과 범위

근거: [레퍼런스 비교 검토](../../Validation/2026-09-28-ui-reference-review.md), [현재 Game 화면](../../Validation/2026-09-28-canvas-game-view.png), [일반 시안 v2](../../References/BELTFED_UI_시안_v2.png), [선택 시안 v3](../../References/BELTFED_UI_시안_v3_강화패널.png), [설치 시안 v4](../../References/BELTFED_UI_시안_v4_설치.png).

목표는 좁은 주변 패널과 넓은 중앙 월드 화면을 회복하는 것이다. 현재 기능과 데이터는 유지하고 배율·패널 크기·빈 배경·정보 정렬을 개선한다. 시안의 장식·아이콘·예시 수치는 구현 사양으로 복제하지 않는다.

대상 씬:

- `Assets/EternalSteam/Scene/Tests/StartRegionSandbox.unity`: 우선 적용·검증.
- `Assets/EternalSteam/Scene/Tests/OpenWorldSandbox.unity`: 동일 레이아웃 적용, 씬별 카탈로그·기능 차이는 유지.

**HUD는 Canvas/uGUI 실제 Hierarchy에 저장한다.** 새로 필요한 배경·레이아웃 컨테이너·텍스트도 Edit Mode에서 저작·저장한다. Play에서 정적 UI를 생성하거나 누락 참조를 복구하는 코드는 추가하지 않는다. 과거 계획의 UXML/USS 구현 방향은 이번 계획에 적용하지 않는다. 과거 스냅샷 씬·게임 규칙·카메라 줌·저장 포맷·기지 영역은 변경 대상이 아니다.

## 2. 현재 원인과 대응

| 확인한 구현 | 영향 | 적용 작업 |
|---|---|---|
| CanvasScaler 1280×800, Match Height=1 | 1080p에서 배율 1.35, 패널·폰트 동반 확대 | 기준을 1920×1080, Match=0.5로 전환하고 모든 관련 크기를 새 기준으로 재저작 |
| TopBar 높이 84, 좌/우 폭 236/292 | 1080p 환산 113px, 319/394px | 아래 표의 명시적 목표 크기 적용 |
| LeftStatus/RightStatus가 각각 높이 470의 큰 배경 | 접거나 선택을 해제해도 빈 배경 잔존 | 부모는 배치 컨테이너로, 배경은 내용별 자식에 분리 |
| `fold:` 명령이 Body 활성 상태만 전환 | 카탈로그를 접어도 ConstructionBar와 Notifications 위치 유지 | 실제 표시 상태에 따라 부모 높이와 안내 위치 재배치 |
| `RefreshCatalog()`가 매번 6열 계산·높이 60 강제 | Inspector에서 변경한 셀 높이가 다시 덮어써짐 | 씬에 저장한 셀 높이·간격·열수 기준을 사용하도록 해당 부분 수정 |
| 자원 이름·수량이 단일 문자열로 출력 | 수량 정렬이 흔들리고 큰 글자와 안내가 충돌 | 저장된 이름/수량 텍스트 두 열에 동일 행 순서로 출력 |
| Notifications가 화면 하단 기준 폭 1200 고정 | 좌측 자원 및 좁은 화면과 충돌 | 좌우 패널 사이 중앙 안전 영역에 앵커·최대 두 줄 적용 |

현재 StartRegion HUD는 텍스트 80개·버튼 59개·카탈로그 25개다. 이는 변경 전 비교 기준이며, 필요한 컨테이너·자원 수량 텍스트 추가 후 같은 개수를 강제하지 않는다. 기존 명령과 카탈로그 항목의 누락 여부를 별도로 비교한다.

## 3. 1차 적용 치수

아래 값은 **1920×1080에서 scale=1인 Canvas 단위**이며 1차 구현 목표다. 외곽 여백 16, 패널 간격 8, 내부 여백 8–12를 사용한다. 실제 캡처 검증에서 조정한 값은 결과 문서에 남긴다.

| 영역 | 적용값 | 배치·제약 |
|---|---|---|
| CanvasScaler | 1920×1080, Scale With Screen Size, Match=0.5 | 전체 Transform scale은 1 유지 |
| 상단 상태 영역 | 높이 60 | 날짜/남은 시간, 상태, 전력, 정지 버튼을 한 줄 구획으로 정렬; 전체 폭의 단일 배경 제거 |
| 좌측 체력 | 폭 232, 높이 76 | 좌상단, 이름·체력·얇은 체력바 |
| 시계 영역 | 폭 232, 펼침 높이 156 | 체력 아래 8 간격; 시계 지름 112, 접기 헤더 28 |
| 자원 영역 | 폭 208, 최대 높이 280 | 시계 아래 8 간격; 행 높이 26, 이름 좌측·수량 우측; 넘치면 세로 스크롤 |
| 지도 영역 | 폭 272, 펼침 높이 292 | 우상단 상태 바 아래; 지도 248×248, 헤더 28, 나머지는 여백 |
| 선택 상세 | 폭 272, 높이 240 이하 | 지도 바로 아래; 선택 없거나 수정 중이면 배경 포함 숨김; 내용은 스크롤 |
| 건설 바 | 펼침 높이 204, 접힘 높이 44 | 화면 하단; 부모 높이가 실제로 줄어들고 안내도 따라 이동 |
| 건설 명령 행 | 높이 36 | 수정/확정/취소·목록 접기·전력/저장 접근 유지 |
| 분류 행 | 높이 30 | 전체/방어/자원/설치/기타 유지; 현재 선택 유지 |
| 카탈로그 | 셀 높이 52, 간격 6 | 한 줄 이상 완전히 보이는 viewport 확보; 추가 항목은 세로 스크롤 |
| 건설 상태 안내 | 높이 24 | 카탈로그와 별도 행; 긴 내용은 중앙 Notifications로 상세 표시 |
| 중앙 Notifications | 최대 두 줄, 최대 높이 52 | 건설 바 상단+8; 좌측 자원·우측 상세 영역 침범 금지 |
| 저장/전력/개발자 | 기존 기능 유지, 화면 안전 영역 안에 제한 | 고정 큰 높이 대신 viewport 안에서 스크롤; 주요 버튼을 화면 밖에 두지 않음 |

폰트는 본문·버튼 18, 보조 문구 16, 제목 22를 기본으로 한다. 핵심 수치의 강조는 크기·색/굵기로 구분하며 모든 문장을 제목처럼 키우지 않는다. 1366×768에서는 본문·버튼의 실제 표시 크기 14px, 보조 12px를 하한으로 검증한다. 필요한 경우 저장된 반응형 표시 설정에서 글자 크기만 보정하며 무제한 TMP AutoSize로 잘림을 숨기지 않는다.

시계는 다른 요소와 함께 일괄 축소하지 않는다. 현재 캡처에서 시계 자체는 주변 빈 패널에 비해 작다. 기존 낮/밤 표현·시간 데이터·바늘 참조를 유지하고 새 컨테이너 안에서 중심을 맞춘다.

## 4. 계층 변경 방법

기존 오브젝트를 이동·재배치하고 기존 컴포넌트와 persistent callback을 유지한다. HUD 전체 삭제 후 재생성하지 않는다.

| 현재 부모 | 적용 구조 |
|---|---|
| TopBar | 투명 배치 부모 + 날짜/상태/전력/시간 조작 구획별 배경 |
| LeftStatus | 배치 부모 + HealthPanel / ClockPanel / ResourcePanel. 접기 상태에 따라 아래 패널이 위로 이동 |
| RightStatus | 배치 부모 + MinimapPanel / SelectionPanel. 부모 배경과 불필요한 Raycast Target 제거 |
| ConstructionBar | CommandRow / InventoryBody(CategoryRow + CatalogScroll) / StatusRow. 접힘 상태는 CommandRow만 표시 |
| Notifications | 좌우 안전 영역 사이의 안내 컨테이너. 중앙 입력을 막지 않는 텍스트 |

레이아웃은 앵커와 LayoutGroup/LayoutElement를 우선 사용한다. ScrollRect의 viewport/content/mask를 유지하고, ContentSizeFitter와 부모 LayoutGroup이 같은 축의 크기를 경쟁하지 않도록 한다. 작은 창에서 두 측면 패널과 하단이 충돌하면 내용 viewport를 먼저 줄여 스크롤하며 필수 조작을 없애지 않는다.

공간이 더 좁은 비16:9 Editor 창에서는 ① 열수 축소 ② 자원/선택 viewport 높이 축소 ③ 상세 패널을 같은 폭의 스크롤 오버레이로 표시하는 순서로 대응한다. 사용자 선택 없이 목록 접기 상태나 카탈로그 범주를 초기화하지 않는다. 지원하는 최소 검증 크기는 1024×768이며 그보다 작은 창은 이번 완료 보장 범위 밖이다.

## 5. 런타임 코드 조정 범위

주 대상: `Assets/EternalSteam/Tests/OpenWorld/Runtime/CanvasWorldHud.cs`.

- 레이아웃 크기·폰트·최소 셀 폭은 Inspector에서 검토 가능한 직렬화 설정으로 관리한다. 기본 크기와 필요한 오브젝트는 씬에 저장한다.
- 카탈로그 열수는 viewport 폭, 최소 셀 폭 160, 간격 6으로 산정하고 4–8열 범위에서 조정한다. 열수 산식은 `floor((사용가능폭+간격)/(최소셀폭+간격))`을 기준으로 한다. 작은 viewport에서 최소 셀 폭을 유지할 수 없으면 가로 overflow 대신 열수를 추가 축소한다. 긴 이름은 최대 두 줄에 맞춘다.
- 셀 크기 계산은 화면/viewport 크기 변경 시 수행한다. 매 프레임 상수로 덮어쓰는 현재 코드를 제거한다. 카탈로그 필터링·버튼 활성 판정은 기존 규칙을 유지한다.
- `fold:` 수행 후 표시 상태에 맞는 부모 레이아웃을 갱신한다. 건설 바와 Notifications가 같은 상태를 기준으로 배치되게 한다. 미니맵을 접으면 기존 `CancelInteraction()` 호출을 유지한다.
- 자원 표시를 이름/수량 두 열로 나눠도 동일 데이터·정렬 순서·행 높이를 공유한다. ResourcePriority 미설정 시 전체 접근을 유지하고 재고 0을 숨기지 않는다. “주요 자원” 버튼은 우선순위가 없는 경우 비활성화 이유를 분명히 하거나 공간을 차지하지 않도록 처리한다.
- 전력은 상단에 짧은 요약, 기존 상세 패널에 전체 기지 식별·생산/소비 정보를 남긴다. 숫자나 기지 소속의 의미를 변경하지 않는다.
- 런타임에서 허용하는 변경은 텍스트·활성 상태·크기/위치 등 반응형 표시값이다. `new GameObject`, 패널/버튼 Instantiate, 누락 UI 재구축은 금지한다.

`CanvasWorldMinimap`, `CanvasClockDial`은 가급적 계산 로직을 유지하고 RectTransform만 조정한다. 입력 좌표 변환에 크기 가정이 있는 경우에만 최소 수정한다.

`Tools/author_canvas_hierarchy.py`는 최초 마이그레이션 도구이므로 기존 씬에 다시 실행하지 않는다. 후속 조정은 Unity CLI로 연결된 에디터의 실제 오브젝트에 수행한다. 반복 적용이 필요하면 기존 경로/컴포넌트를 검사하고 변경하는 멱등 Editor 도구를 작성한다. 다른 씬의 직렬화 참조나 서로 다른 카탈로그를 통째로 복사하지 않는다.

## 6. 적용 순서와 단계별 완료 조건

| 단계 | 작업 | 다음 단계 진입 조건 |
|---|---|---|
| P0 기준 보존 | 현재 Git diff·씬 dirty 확인, 사용자 변경 유지, 두 씬의 계층/콜백/카탈로그 기록 | 원래 상태와 변경 대상 식별, 현재 Play 중이면 종료 후 작업 |
| P1 기본 치수 | StartRegion의 CanvasScaler 및 상단/좌우/하단 RectTransform, 폰트 재저작 | 1920×1080 일반 상태 캡처에서 크기·본문 가독성 확인 |
| P2 빈 공간/접기 | 좌우 배경 분리, LayoutGroup, 접기 높이와 Notifications 연결 | 펼침/접힘/선택 해제 시 빈 배경과 입력 차단 영역이 남지 않음 |
| P3 내용 밀도 | 자원 두 열, 카탈로그 가변 열수, 긴 이름·메시지·스크롤 | 자원/안내 겹침 제거, 모든 항목·버튼 접근 가능 |
| P4 두 번째 씬 | 검증된 설정을 OpenWorld 씬의 기존 계층에 적용 | 씬별 참조·항목 보존, 두 씬 재열기 후 저장된 배치 동일 |
| P5 회귀 | 아래 매트릭스의 화면·입력·기능 검사 | 실패 0개 또는 미완료/제한을 명확히 기록; 기존 통과 결과를 재사용하지 않음 |
| P6 결과 정리 | 전후 캡처·실제 치수·테스트 결과, README/Docs 갱신 | 계획/적용/검증 상태를 구분한 결과 문서 완성 |

각 단계는 변경 직후 확인하고 실패하면 해당 변경을 수정 또는 되돌린다. 사용자 작업과 앞선 테스트 수정·Unity 직렬화 변경을 함께 되돌리지 않는다. GitHub 업로드는 이번 계획 수립에 포함하지 않는다.

실제 화면 증거는 Overlay Canvas를 포함하는 Game View 캡처로 수집한다. 현재 CLI screenshot 명령의 카메라 전용 출력만으로 HUD 검증을 완료하지 않는다. 대표 비교는 1920×1080 일반·선택·수정 상태를 같은 화면비와 카메라 위치에서 전후로 남긴다.

완료 시 `Docs/Validation/`에 실제 결과와 남은 제한을 기록한다. 이번 문서는 적용 승인을 기다리는 형식이 아니라 다음 구현 작업을 구체화한 계획이며, 문서 작성만으로 UI 변경이나 검증 완료를 주장하지 않는다.
