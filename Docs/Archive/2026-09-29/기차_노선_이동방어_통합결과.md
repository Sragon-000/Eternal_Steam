## 적용 범위와 결정 출처

DEC-01~04(확정 성공 시 결제, 소속 기지 결제, 구 재고 메인 1회 이관, 단계별 확장)는 기존 사용자 채택 사항이다. 이번 전력·비용·피격 정책은 후속 구현 요청을 구체화한 **개발 기본값**이다. 전용 축전지를 추천하는 선택 질문에 별도 답변이 없어 기본값으로 적용했으며, 개별 수치를 사용자가 확정했다고 해석하지 않는다.

## 구현과 저장 계약

`MobileDefenseRuntime`은 기존 정의에서 무기·회전·성능 강화 모듈만 조합한다. `BuildingInstance`의 선택적 위치 공급자를 통해 현재 기차 포탑 위치를 조회한다. 지상 `BuildingWorld`, `BaseRegistry`, `BuildingTargetRegistry`, 이동 장애물과 전력 공급 대상에는 등록하지 않는다. 기존 지상 건물은 고정 위치 생성 방식을 유지한다.

`TrainArmament`는 칸 형태, 정의 ID, 축전지, 모듈 상태를 기차에 저장한다. 저장 검사에서 크기/해금/레벨/유한 수량/모듈 필드를 확인한다. P6 이전 v2 저장의 누락 방어칸은 빈 2×2로 읽는다. Unity JSON의 빈 문자열도 빈 무기 상태로 처리한다. 투사체·연쇄 공격이 남아 있으면 기존 안전 저장에 기차 공격 대기 조건을 추가한다. 무기 쿨다운·회전·강화·축전지는 실제 씬 재시작으로 복원했다.

새 정적 표시물은 두 씬 및 프리팹에 저장되어 있다. `Train.prefab`에는 포탑·총구·사격 LineRenderer, `RouteMarker.prefab`에는 World Canvas 순번과 방향 화살표가 있다. Play에서는 이 프리팹을 노선/기차 게임 인스턴스로 사용한다. 기차 Collider는 0개다. 장착 화면과 39개 철도 영구 콜백은 두 씬 모두 저장했다. 일시정지 중 장착 변경도 즉시 표시를 갱신한다.

## UI 보완

- 노선 상세: 각 구간 길이·연결 상태, 총 길이, 예상 시간, 중지 요청의 다음 역 표시.
- 지도: 선택 노선의 전체 경로, 역 방문 순번, 각 출발 구간의 방향 화살표.
- 전체 목록: 페이지별 역 순서와 연결 유효/오류 요약.
- 역 문맥: 해당 역이 포함된 노선만 표시하고 방문 순번·이전/다음 역 안내. 상세에서 목록으로 돌아와도 역 문맥 유지.
- 경로 실패: 구간 번호·문제 셀 좌표·원인. 셀을 특정할 수 있는 연결 실패는 저장된 LineRenderer로 표시.
- 역 비활성: 상세 목록에 비활성 표기. 기존 건물 상세는 범위 밖/기지 상실 사유를 표시.
- 장착 패널: 후보 변경, 장착, 강화, 충전, 빈 칸 형태, 해제, 노선 상세 복귀. 수치/비용이 검증값임을 표시.

## 실행 안내와 후속 콘텐츠 범위

1. `StartRegionSandbox`에서 두 기지와 역/선로를 확정하고 노선을 만든다. 노선 상세에서 자원·역별 물류·연료를 설정한다.
2. 기차를 역에서 정지한다. 기본 2×2 방어 후보는 메인 레벨 2의 아크부터 해금된다.
3. `기차 방어`에서 후보를 골라 장착한다. 정차 역 기지에 철과 충전할 저장 전력이 있어야 한다.
4. `축전지 충전` 후 운행한다. 기차에 전력이 남아 있으면 기존 전투 활성 흐름에서 공격한다.
5. 변경/추가 충전은 다음 역 중지를 완료한 뒤 한다. 안전 저장은 낮·적 없음·진행 중 공격 없음·편집 확정 조건을 따른다.

P5/P6의 핵심 예약·이동 방어 경로는 연결했으나, 후속 원문 대조에서 추가 결함과 UI 미구현을 확인했다. 먼저 후속 계획 A0~A5를 수행한다. 최종 비용/충전량/연료 밸런스·아트·다수 노선 성능·장시간 수동 QA도 남아 있다. 1×3·3×1 호환 무기 추가는 콘텐츠 결정 사항이며 원문이 세 형태 각각의 무기 제공을 확정한 것은 아니다. 맵 간 운송·추가 기차·추가 칸·동적 분기·선로 공유는 기존 초기 범위 밖으로 유지한다. 기차 파괴를 도입하려면 TRN-208의 초기 무피해 정책과 저장/화물 처리 계약을 함께 개정해야 한다.

원본 `4.3 기차.md`, `4.4 노선.md`는 `Docs/Source/Attachments`의 원본과 manifest 해시를 그대로 유지했다.
