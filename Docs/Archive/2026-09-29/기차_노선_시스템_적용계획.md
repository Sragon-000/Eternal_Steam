# 기차·노선 시스템 적용계획

2026-09-28 후속 [원문·실제 소스 대조 및 적용계획](기차_노선_원문대조_후속적용계획.md): 71개 명시 요구와 화면/이벤트를 대조하여 미설정 화물의 JSON 왕복·오류 노선 회수 결함 2개를 재현했고, 확인/폐기 화면·지도 편집·역 문맥 등의 누락을 확인했다. **P1~P6 초기 연결 완료는 원문 전체 구현 완료가 아니다.** 최신 미구현 목록과 후속 순서는 이 감사의 A0~A5를 따른다. 이번 후속 작업은 감사·계획 수립이며 게임 코드 수정은 하지 않았다.

작성·개정: 2026-09-28. 사용자 합의를 반영한 개발 계획이다. 후속 **“그대로 적용 개선 진행”** 요청에 따라 P1~P4의 1차 코드·콘텐츠·씬 연결을 적용했다. [1차 적용 결과](기차_노선_1차_적용결과.md)에 현재 구현과 검증 한계를 기록한다. [실제 실행 결과](../../Validation/2026-09-28-railway-live-play.md)에서 핵심 운송·저장/이관 및 104개 테스트를 확인했다. 후속 [P5 예약 수정 결과](기차_노선_예약수정_적용결과.md)에 첫 역 복귀 적용·취소·저장 및 115개 테스트 통과를 기록했다. 후속 **“계획 내 작업 모두 순차적으로 진행”**에 따라 [이동 방어·통합 결과](기차_노선_이동방어_통합결과.md)까지 적용했다. **P1~P6 초기 구현은 검증용 정책 기준 완료, 최종 회귀 141/141 통과**다. 최종 밸런스·아트 및 대규모 수동 QA는 별도이며, 아래 초기 설계/비교 기록보다 최신 통합 결과의 결정 상태를 우선한다. 첨부 자체의 지시와 후속 사용자 구현 요청은 구분한다. 아래 “현재 확인” 비교표는 구현 전 기준이다.

## 1. 적용 방향

기차를 기존 건물에 이동 기능만 붙이는 방식으로 추가하기보다, **기지별 재고 → 역·선로 → 노선 검증 → 운행·운송 → 예약 편집 → 이동 방어** 순서로 적용한다. 저장과 UI는 각 단계에 함께 연결한다. 특히 현재 공용 일반 재고를 그대로 두면 출발 기지에서 차감하고 도착 기지에 더하는 운송의 의미가 사라진다.

현재 단일 맵·45° 격자·기지 가동 범위·기지별 전력·Canvas/uGUI·안전 저장은 재사용한다. 맵 간 운송, 추가 기차, 선로 공유, 교차·분기·합류, 자동 선로 건설, 신호 시스템은 초기 범위에서 제외한다. 원문 Must인 이동 방어와 예약 편집을 후반 단계로 나누더라도, 앞 단계 완료만으로 전체 요구사항을 완료했다고 기록하지 않는다.

### 1.1 사용자 확정 사항과 적용 우선순위

2026-09-28 후속 대화에서 추천 방향을 채택하고 이를 문서에 반영하기로 했다. 아래 네 항목은 더 이상 선택 대기 항목이 아니다. [후속 결정 요약](../../Source/Conversation/계획과_후속결정_요약.md)에 출처를 기록한다.

| 확정 ID | 확정 기준 | 원문/초안에서 바뀌는 부분 |
|---|---|---|
| DEC-01 | 선로·역 설치는 **예약 → 확정 → 취소** 흐름을 사용하고 실제 비용은 확정 성공 때 차감 | RAIL-003/009의 자유 드래그 즉시 설치·차감 대신 기존 프로젝트 편집 흐름 적용. 꺾인 선로 경로도 예약 도구로 구성 |
| DEC-02 | 시설의 건설·강화 비용은 **해당 시설의 소속 기지 재고**에서 지불 | 기지 간 합산/자동 대납 없음. 범위 밖 시설과 신규 기지 등의 소속 지정 세부 절차는 §4.1 기본안 |
| DEC-03 | 기존 저장의 공용 일반 재고를 **메인 기지에 한 번만 이관** | 기지별 복제·균등 분배 없음. 용량과 저장 건물은 별도 재구성하고 초과 재고 보존 |
| DEC-04 | 첫 완료 목표는 **두 기지 순환 운송 + 기본 UI + 저장·복원** | 내부 모델은 다중 역 지원. 예약 노선 수정과 이동 방어는 첫 완료 후 순서대로 진행 |

우선순위는 이번 사용자 확정 → 첨부의 구체적인 최신 요구 → 이 문서의 설계 기본안 순이다. 미정 밸런스·아트 수치를 사용자 확정으로 바꾸지 않는다. 원본 파일은 수정하지 않고 충돌 해소는 이 파생 문서에만 기록한다.

### 1.2 첫 구현의 경계

첫 버전은 P1~P4를 묶은 하나의 플레이 가능한 완료 단위다. 기지 A/B의 독립 재고, 역 두 곳, 분리된 왕복 선로로 이루어진 폐쇄 노선, 기본 기차 한 대, 화물 1칸(1,000), 수동 석탄 보급, 시작/중지/오류 표시, 노선·역 설정 UI, 안전 저장과 구버전 이관을 포함한다.

운전칸·화물칸·설치칸의 기본 편성 데이터는 첫 버전부터 둔다. 설치칸의 무기 장착·공격은 P6까지 비활성으로 표시한다. 운행 중 노선 수정은 P5까지 비활성으로 안내하되 정지 중 수정은 기존 기차·화물을 유지한다. 후속 기능 버튼이 작동하는 것처럼 표시하지 않는다. 전체 원문 Must 완료는 P6 후 판정한다.

첫 시연은 두 역으로 하되 배열·ID·경로·검증기를 두 역 전용으로 만들지 않는다. 세·네 역의 순서와 폐쇄 경로를 별도 검증한다.

| ROUTE-VAL-001~008 | 역 개수·포트 역할·유일 경로·폐쇄·역 중복·타 노선 독점·존재/활성·방향/분기 제한을 확정 직전에도 재검사 |

한 노선에 임의의 역 수 상한을 추가하지 않는다. 역별 화물 설정이 모두 0이어도 10초 정차 규칙은 유지한다. 역 타일은 선로 길이에 포함하지 않는다.

예상 순환 시간은 `Σ(구간 선로 타일 수) × 1초 + 역 수 × 10초`다. 연료 부족·수동 중지·오류 대기는 제외한 정상 운행 예상값으로 표시한다. 두 역, 각 10타일 구간이면 40초다.

### 원문 사이의 충돌·해석 주의

- **자동 출발:** ACC-005의 생성 후 운행 표현보다 TRN-113·ACC-017 및 4.4의 수동 시작을 적용한다. QA에는 시작 버튼 단계를 넣는다.
- **선로 회수:** ACC-008은 운행 중 회수 허용으로 읽지 않는다. TRN-120에 따라 운행 중 회수는 거부하고, 정지 후 회수로 무효화되는 경우를 별도 검사한다.
- **역 이름:** 4.3 요약의 `<기지 이름> 역`과 4.4의 `기지명 기차역 순번`이 다르다. 구체적인 4.4 기준을 적용 제안으로 채택하고, 기지별 증가 순번을 저장하며 철거 시 재번호를 매기지 않는다. 초기에는 §4.1에 따라 소속 변경 기능을 제공하지 않는다. 이후 재연결 기능에 표시명 변경 규칙을 포함한다.
- **선로 방향:** 설치 설명은 단방향이나 RAIL-012는 노선 확정 시 방향 기록을 명시한다. 미배정 선로는 물리 연결/외형만 보유하고 확정 시 방향·소유권을 기록하는 해석을 제안한다. 배치부터 방향을 고정하려면 입력 설계를 추가 확정해야 한다.
- **화물 보류 표현:** 4.4의 전달량 별도 논의 문구는 UI 문서의 범위 제한이다. 4.3 TRN-005/006의 계산식은 이미 명시되어 있으므로 다시 임의의 분배 방식으로 대체하지 않는다.
- **TBD 목록:** TRN-TBD-005/010에 적힌 최소 보유량 없음·하역 불가 화물 유지·하역 후 적재는 본문에서 확정된 규칙이다. TBD 표에 있다는 이유로 전부 미결로 되돌리지 않는다.

## 4. 제안하는 기능 구조와 데이터

신규 `Code/Railway` / `EternalSteam.Railway`를 제안한다. Railway는 Runtime의 최소 계약에 의존하고 Economy·Combat·Presentation을 직접 참조하지 않는다. Sandbox 구성 지점이 재고 이동·공격·표현 어댑터를 연결한다. 공통 Runtime에 철도 전체 로직이나 UI를 넣지 않으며 아키텍처 테스트의 새 어셈블리 검사도 추가한다.

| 제안 모델/서비스 | 데이터·책임 |
|---|---|
| `BaseInventoryRegistry` (Economy) | `MapId + BaseId → 재고/용량`. 생산·변환·저장·결제의 동일 소속 기준 |
| `StationState` | 영속 StationId, 건물 PersistentId, InventoryBaseId, 설치 순번, 방향, 로컬 포트 ID/좌표/역할, 가동 상태 |
| `RailTileState` | 맵·격자 셀, 물리 연결, 배정 RouteId, 확정 방향, 토폴로지 버전. 공격 대상/내구도는 부여하지 않음 |
| `RouteDefinition` | 영속 RouteId, 이름, 시작역, 중복 없는 역 순서, 구간별 포트 쌍과 순서 있는 선로 셀, revision |
| `RouteDraft` / `PendingRouteRevision` | 미확정 초안과 예약된 확정 변경 구분. 기준 revision·재검증 대상·적용 순환 경계 |
| `TrainState` | TrainId, RouteId/revision, 상태, 현재 역/구간/타일 인덱스·진행률, 정차 잔여시간, 중지 요청, 화물·연료·편성 |
| `CargoRule` | `(RouteId, StationId, WagonId)`의 적재량·하역량. 역 방문 순서 인덱스로 저장하지 않음 |
| `RouteValidator` | ROUTE-VAL 결과에 역/구간/포트/셀과 오류 코드를 반환. UI와 실행 명령이 공유 |
| `RailwaySimulation` | 고정 경로 진행, 도착 이벤트·화물 처리·출발 연료 검사, 예약 적용 경계 |

기지·역·노선·기차의 식별자는 런타임 슬롯 번호와 분리한다. 2×2 역의 포트는 로컬 좌표로 정의하고 설치 회전을 적용해 월드 셀로 변환한다. 선로의 직선/모서리 외형 연결과 실제 통행 연결 데이터는 분리한다.

선로의 건설 점유와 적 이동 장애 여부도 별개다. 적의 공격 비대상이라는 규칙만으로 통행 차단 여부를 추론하지 않는다. 기차는 월드 격자 칸에 매 프레임 건물을 재배치하는 대신 경로 진행 상태와 시각 위치를 연결한다.

### 기지별 재고를 먼저 나누는 이유와 방법

1. 생산/저장/변환 건물과 역의 재고 소속을 명시한다. 정상 기지 범위 중첩 시 소속 결정과 재연결은 D03 정책을 따른다.
2. 해당 기지의 생산은 해당 원장에만 반영한다. 공용 재고로 우회하는 결제·변환·저장 용량 경로도 함께 전환한다.
3. 상단 HUD에는 선택 기지 재고를 표시하는 안을 우선한다. 전체 합계는 읽기 요약일 뿐 결제 가능한 공동 지갑으로 사용하지 않는다.
4. 건설·강화는 소속 기지에서 결제한다(DEC-02). 연료는 정차 역의 소속 기지, 오브 제작은 실제 제작 시설의 소속 기지에서 지불하는 설계 기본안을 적용한다. 현재 검증용 무료 정책은 최종 비용 확정이 아니다.
5. 저장 건물 회수로 용량보다 재고가 많아질 수 있는 현재 정책을 보존하려면 `하역 여유=max(0, 용량-재고)`로 계산한다. 무조건 상한으로 잘라 자원을 삭제하지 않는다.

### 4.1 재고 소속·비용의 설계 기본안

DEC-02를 구현하기 위한 다음 세부 정책은 개발 기본안이다. 기존 가동 범위 규칙을 바꾸거나 자동 재고 이동을 허용하는 것으로 해석하지 않는다.

| 상황 | 소속·결제·보존 처리 |
|---|---|
| 기존 시설 | 저장된 소속 BaseId가 유효하면 유지. 누락/모호한 소속은 이관 사전 검사에서 보고하고 추측으로 결제하지 않음 |
| 신규 일반 시설·역 | 설치 예약 시 사용할 기지를 명시하고 확정 데이터에 InventoryBaseId를 저장. 자동 선택은 현재 선택 기지를 기본으로 하되 화면에 표시 |
| 기지 범위 중첩 | 가동 가능 여부는 기존 범위 합집합 판정을 사용. 재고 소속은 기존 연결을 유지하고 가까운 기지로 자동 이전하지 않음 |
| 범위 밖 선로·시설 | 설치 허용 여부는 기존 방벽/외부 설치 정책으로 검사. 허용 위치여도 결제 기지를 명시해야 하며 무료/공용 지갑으로 우회하지 않음 |
| 신규 서브 기지 | 건설 예약의 발주 기지를 비용 소속으로 기록. 설치 후 새 BaseId의 독립 재고를 만들고 건설비를 그 빈 재고에 다시 청구하지 않음 |
| 강화 | 대상 시설 InventoryBaseId로 조회·검증·차감. 잔액 부족 시 다른 기지의 자원으로 보충하지 않음 |
| 회수 | 확정된 환급 정책이 있다면 원래 결제 기지로만 반환. 정책/금액이 미정이면 임의 100% 환급을 넣지 않음 |
| 수동 연료 적재 | 정차 중인 역의 기지에서 석탄을 차감하고 연료칸에 같은 양 증가. 역/기지 연결이 무효하면 거부 |
| 기지 상실 | 원장과 소속 ID 보존, 해당 원장을 통한 신규 생산·결제·인계 중지. 다른 기지로 자동 합산하지 않음. 메인 패배는 기존 패배 정책 우선 |
| 소속 변경 | 초기 별도 재연결 UI는 제공하지 않음. 범위 재확보와 소속 이전을 구분. 이후 소속 변경 기능은 재고·용량·이름 이관까지 별도 설계 |

선로 비용을 낸 기지와 기차가 운송하는 양끝 기지는 서로 다를 수 있다. 선로의 결제 소속 때문에 다른 노선의 사용권이 생기지 않는다. 소속 기지 선택이 유효하지 않으면 명확한 이유와 함께 확정을 차단한다.

### 4.2 설치 예약과 결제 계약

1. 선로 도구에서 시작점과 끝점을 지정해 격자 축 방향 직선을 예약한다. 끝점에서 다음 구간을 추가해 꺾인 경로를 만든다. 이는 설계 기본안이며 최단 경로 자동 생성이 아니다.
2. 중복 셀은 한 번만 예약하고 설치 불가 셀은 위치·사유를 표시한다. 유효 셀만 예약돼 경로가 끊기면 노선 검증에서 단절을 표시한다. 자동 연결/철거/우회하지 않는다.
3. 예약 단계에서는 실제 재고·지형·선로를 변경하지 않는다. HUD에는 기지별 확정 예정 비용과 부족량을 표시한다. 회수 예정과 신규 설치는 기존처럼 한 작업에 혼합하지 않는다.
4. 확정 명령에서 지형·점유·범위·운행 잠금·비용표·기지별 잔액을 최신 상태로 재검사한다. 비용은 `(지불 BaseId, 자원 ID)`별 합계로 계산한다.
5. 한 확정 작업은 예약된 설치 전부와 전체 결제가 함께 성공하거나 모두 실패한다. 예: A의 비용이 충분하고 B가 부족해도 A에서 먼저 차감하지 않는다. 실패 시 예약은 편집 가능하게 남기고 원인을 표시한다.
6. 성공한 요청 ID를 재사용한 중복 입력은 재설치/재결제하지 않는다. 취소·포커스 상실·미리보기 이동은 실제 재고를 바꾸지 않는다. 저장은 확정 완료 경계에서만 가능하다.

실제 건설비·환급률은 콘텐츠 비용표에 두고 미지정 금액을 0으로 해석하지 않는다. 검증용 비용표는 명시적 테스트 설정으로 분리한다.

### 화물 인계

화물칸 현재량 C, 용량 K, 역 재고 S, 역 용량 B, 하역 설정 U, 적재 설정 L일 때:

```text
하역량 u = min(U, C, max(0, B-S))
하역 후 C1 = C-u, S1 = S+u
적재량 l = min(L, max(0, K-C1), S1)
최종 C2 = C1+l, S2 = S1-l
```

`적재 목표량`은 잔량을 목표까지 채우는 차이값이 아니라, TRN-006에 명시된 이번 방문 적재량 상한이다. 예를 들어 화물 200, 목표 100, 여유/역 재고가 충분하면 최종 화물은 300이다.

역과 화물 양쪽 변경은 한 거래로 완료한다. 기존 `Exchange`는 한 ResourceBank 내 변환이므로 두 저장소 이동에 그대로 사용하지 않는다. 인계 직전 가용량/여유를 재검사하고, 실패 시 양쪽 모두 유지한다. 반복 도착 이벤트·로드로 중복 처리하지 않도록 방문 식별자와 처리 여부를 저장한다. 후속 다중 화물칸 확장에서도 모든 칸 하역 후 모든 칸 적재 순서를 보장한다.

### 노선 확정과 예약 수정

- 초안에서는 실제 방향·독점·기차를 변경하지 않는다. 확정 직전 최신 지형/역/포트/점유와 revision을 재검사한다.
- 노선 저장·선로 배정·기차 한 대 생성은 하나의 성공 단위다. 중복 입력에는 동일 결과를 반환하고, 실패하면 부분 배정/자원 변경을 남기지 않는다.
- 기존 노선 수정은 기존 TrainId와 화물을 유지한다. UI의 `CommitRoute`를 기존 수정에도 무조건 신규 생성으로 연결하지 않는다.
- 운행 중에는 현재 적용 중인 노선을 유지한다. 예약본은 현재 순환의 기준 출발역을 유지하며 다른 역의 추가/삭제/재정렬을 허용한다. 원문의 ‘현재 출발역’이 마지막으로 출발한 역을 뜻하는지 순환 기준역인지 D07에서 확정한다.
- 예약본 적용 시 선로 독점·포트·역 가동을 다시 확인하고 기존 소유권 해제/신규 확보를 원자적으로 교체한다. 자기 노선의 기존 선로는 타 노선 점유 오류로 판단하지 않는다.
- 제안: 예약본의 신규 선로는 예약만으로 독점하지 않고 적용 시 재검증한다. 적용 실패 시 기존 노선이 유효하면 계속 운행하고 예약 오류를 표시한다. 기존 노선까지 무효하면 오류 정지한다. 이는 원문에 없는 실패 처리 제안이다.

## 5. 운행·연료·전투 적용

`정지 → 수동 시작 → 이동 → 10초 정차 → 다음 구간 이동`을 기본으로 한다. 이동 중 중지 요청은 현재 구간을 끝내고 다음 역에서 정지한다. 연료 부족과 오류 복구 후에는 사용자 재개가 필요하며 자동 출발하지 않는다. 이동·정차 타이머는 기존 게임 시간과 일시정지/배속 정책을 공유하고 벽시계로 별도 진행하지 않는다.

연료 용량은 `역 수 × 50`(50은 임시값), 길이 배율은 `1+0.1×(L-1)`이다. 실제 소비량의 기준 계수·반올림·차감 시점은 미정이다. 제안은 구간 출발 시 필요량을 전부 확인·차감해 중간 연료 부족을 막는 방식이다. 길이 10칸은 배율 1.9일 뿐 석탄 1.9개로 확정된 것이 아니다. 최대 연료로도 통과할 수 없는 구간은 시작 불가 사유로 표시하는 검증이 필요하다.

최초 출발 전 화물 처리, 정차 중 중지 요청, 오류로 구간 중간에 선 기차의 복구 위치는 §5.1에 설계 기본안으로 구체화했다. 임의로 첫 역으로 순간이동시키거나 화물을 지우지 않는다.

이동 방어는 기존 공격 계약과 대상 탐색을 어댑터로 재사용한다. 이동 위치·회전·발사 원점·범위 표시를 갱신하고 적 공격 대상 레지스트리와 어그로에는 기차/탑재 포탑을 등록하지 않는다. 역까지 공격 불가라고 확대 해석하지 않는다. 지면 포탑을 그대로 자식으로 붙이면 격자 점유·전력·피격 등록이 따라올 수 있으므로 편성 전용 생성 경계를 둔다.

기지 전력을 기차가 자동 공유하거나 석탄을 전력으로 바꾸는 규칙은 원문에 없다. P6에서는 정차 역 기지에서 수동 충전하는 기차 전용 축전지, 소속 기지 설치/강화 결제, 환급 없는 무기 해제, 기차/탑재 무기의 직접·간접 피해 없음 정책을 개발 기본값으로 적용했다. 검증 수치와 개별 사용자 확정은 [통합 결과](기차_노선_이동방어_통합결과.md)의 정책표에서 구분한다.

### 5.1 첫 운송 버전의 상태기계 기본안

다음은 미정 경계 처리를 검증 가능하게 만든 설계 기본안이다. 원문이 명시하지 않은 처리 시점까지 사용자 확정으로 간주하지 않는다.

| 이벤트 | 처리 순서 | 결과 |
|---|---|---|
| 처음 운행 시작 | 노선/역/화물 지정/다음 구간 연료 검증 → 첫 역 방문 생성 → 1회 하역·적재 → 10초 서비스 | 첫 출발도 적재 기회를 제공. 서비스 종료 때 최신 조건 재검사 후 출발 |
| 정상 역 도착 | 위치를 역에 고정 → 새 방문 ID → 하역 후 적재를 원자적으로 1회 처리 → 정차 타이머 | 10초 후 출발. 렌더 프레임마다 적재를 반복하지 않음 |
| 이동 중 중지 요청 | 현재 경로/이미 지불한 연료 유지 → 다음 역 도착 → 방문 인계 1회, 서비스 잔여시간 10초 기록 | 정지. 재개 시 서비스 완료 후 출발 |
| 정차 중 중지 요청 | 처리된 인계와 남은 서비스 시간을 유지 | 현재 역에서 정지. 재개 시 남은 서비스만 완료하고 중복 인계 없음 |
| 연료 부족 | 출발 직전 검사 실패, 화물/정차 완료 표식 유지 | 연료 부족 대기. 수동 보충 후 재개 입력 필요 |
| 역에서 재개 | 현재 방문 처리 표식 확인 → 남은 서비스 완료 → 유효성/연료 재검사 | 구간 비용 1회 차감 후 이동 |
| 구간 중 노선 오류 | 현재 Route revision·구간 진행률·화물·연료 지불 표식 보존 | 오류 정지. 같은 경로가 복구되면 수동 재개, 이미 지불한 구간 재차감 없음 |
| 구간 중 경로 변경 필요 | 보존한 진행 위치를 새 경로에 임의 투영하지 않음 | 시작/해당 수정 차단 및 원인 표시. 구조적으로 다른 경로로의 구출은 후속 설계 |
| 기차가 선 역을 없애는 정지 노선 수정 | 현재 역/화물 참조 보존 검사 | 현 위치 역 제거는 초기 거부. 다른 역 변경은 기존 TrainId 유지하며 재검증 |

중지 완료로 서비스가 중단된 경우 잔여시간을 저장해 시작/중지 반복으로 10초를 건너뛰지 못하게 한다. 무효 노선에서는 새로운 인계를 시작하지 않는다. 정상 운행 예상 시간은 첫 출발 준비/수동 중지 시간을 제외한 한 바퀴 기준이다.

## 6. Canvas/uGUI 적용

전역 진입은 기존 플레이 메뉴의 `노선 관리`를 제안한다. 전체 목록에서 행을 선택하면 별도 상세 화면으로 이동하고, 맵 역 선택 시에는 기존 선택 상세에서 해당 역의 노선만 보여준다. 상세·편집 화면은 공용으로 사용하되 뒤로가기 목적지는 진입 문맥을 보존한다.

편집은 역 순서 패널·맵 강조·구간 정보·검증/확정 영역으로 구성한다. 기차 상태와 노선 유효성은 별도 표시하고 오류는 색뿐 아니라 원인·위치·해결 행동을 제공한다. 새 노선은 사용 가능한 역 두 개가 필요하나 선로가 완성돼야 편집을 시작할 수 있는 것은 아니다. 검색·복제·삭제·역 이름 커스텀은 임의로 추가하지 않는다.

고정 패널·버튼·목록 표현 기반·미리보기는 씬/프리팹에 저장하고 Inspector 참조와 콜백을 연결한다. 큰 역 목록은 재사용 가능한 목록 슬롯/스크롤 방식으로 표현하되 표시 슬롯 수를 게임의 역 수 상한으로 쓰지 않는다. 런타임 초기화에서 누락 UI를 재생성하지 않는다. 노선 편집 중 건설·회수·카메라·미니맵 입력 소유권을 구분하고, 숫자 입력 포커스 때 단축키가 작동하지 않도록 한다.

원본 4.4는 목업 제작 이력을 언급하지만 별도 목업 파일은 이번 수신 자료에 없으므로 보관/적용 완료로 표시하지 않는다.

## 7. 저장·복원 확장

현재 안전 저장 조건(낮·전투/투사체/편집 없음, 무결성·백업·패배 정책)을 유지하면서 다음을 확장한다.

- 기지별 재고/용량, 재고 소속, 역 설치 순번 카운터, 역/포트, 선로 점유·방향, 노선 revision/구간.
- TrainId, 편성·고정 자원·화물·석탄, 현재 경로 진행률, 정차 잔여시간, 방문 처리 여부, 중지 요청과 오류 상태.
- 사용자가 저장한 예약 노선 변경과 적용 경계. 편집 중인 미확정 초안은 기존 편집과 같이 저장 대상에서 제외하는 안을 제안한다.

기차 운행 자체를 무조건 저장 불가 조건으로 추가하면 계속 순환하는 동안 저장이 막힌다. 제안은 안전 시점의 시뮬레이션 경계에서 철도 상태까지 일관된 스냅샷을 수집하는 것이다. 예약 변경을 기존 ‘예약 있음’ 검사에 단순 합치지 않도록 구분해야 한다. 이동 포탑의 투사체/효과는 기존 안전 검사에 반드시 포함한다.

복원 순서: 기지/영속 ID → 기지 재고 → 역/포트·선로 → 노선·독점 → 기차/화물/예약본 → 표현 연결 → 일시정지 상태로 표시. 복원에서 신규 기차 생성 이벤트·화물 인계·연료 결제를 재실행하지 않는다. 음수/비정상 값·중복 ID·참조 누락·중복 선로 소유·범위 초과 진행률을 검증한다. 손상 데이터와 게임 규칙상 일시 무효인 노선은 구분해 오류 노선의 화물을 보존한다.

DEC-03에 따라 **지원되는 기존 v1 공용 재고는 메인 기지에 한 번만 이관한다.** 새 형식은 구현 시점의 최신 스키마 다음 버전을 사용한다. 현재 v1 기준 목표는 v2이며, 기존과 신규 형식을 같은 버전으로 쓰지 않는다. 자동 새 게임·균등 분배·기지별 복제는 금지한다.

### 7.1 구버전 이관 절차

1. 패배 기록을 먼저 확인한다. 패배한 진행을 이관으로 되살리지 않는다. 기존 무결성/백업 검사를 통과한 지원 대상만 읽는다.
2. 원본 current/previous 및 이관 대상 파일의 해시·진행 ID·버전을 별도 보관한다. 원본을 직접 수정하지 않는다.
3. 메인 기지가 정확히 한 곳인지, 기지/시설 ID와 자원 ID가 유효한지 사전 검사한다. 구버전 구성 지문은 명시적으로 지원하는 이전 구성만 매핑하고, 기존 호환성 검사를 통째로 생략하지 않는다.
4. 각 자원의 공용 amount 전부를 메인 원장에 1회 기록한다. 다른 기지의 초기 amount는 0. 기존 stocks를 기지 수만큼 복사하지 않는다.
5. capacity는 소속 저장 시설·기본 용량 규칙에서 다시 계산하고 복원 중 이중 증가를 막는다. 소속 누락·지원하지 않는 구성은 중단 사유로 표시한다. 재고가 새 용량보다 많아도 amount를 잘라내지 않고 추가 생산/하역만 제한한다.
6. v1에는 철도가 없으므로 역·선로·노선·기차 목록은 빈 목록으로 시작한다. 신규 형식에는 이관 원본 해시·원본 버전·완료 표식을 넣는다.
7. 메모리에서 새 형식 전체 참조와 자원 총량을 검증한 뒤 임시 파일 작성·flush·재읽기 검증·원자적 교체를 수행한다. 성공 파일이 재실행의 기준이다.
8. 중간 실패 시 원본과 정상 백업을 유지하고 오류를 표시한다. 재시도는 같은 원본에서 새 결과를 계산하며 현재 재고에 더하는 명령으로 실행하지 않는다. 새 형식을 읽을 때 이관은 재실행하지 않는다.

이관 전후 각 자원의 총량은 같아야 한다. 구버전 백업까지 이관 전 슬롯인지 식별하고, 새 버전 실행 중 손상으로 이전 백업을 복구할 때에는 진행이 되돌아간다는 안내와 함께 같은 일회성 절차를 사용한다. 백업 원장과 현재 원장을 합치지 않는다.

포트·비용·연료 수치는 테스트용 설정을 주입해 로직을 검증할 수 있다. 테스트 설정으로 통과한 사실과 최종 게임 밸런스 확정은 분리해서 기록한다. 문서의 완성은 결정 상태와 완료 기준이 명확하다는 뜻이며, 미수신 수치를 임의 확정했다는 뜻이 아니다.

### 10.1 첫 버전 인수 시나리오

아래는 구현 후 실행할 테스트이며 현재 통과 기록이 아니다. 생산/비용/석탄은 별도 원장으로 통제해 운송 보존량을 관찰한다.

1. 기지 A 철 300, B 철 0, 화물 0으로 시작한다. A/B 용량은 테스트 전송량 이상으로 설정한다. 역/선로 건설비는 별도 준비하고 설치 후 기준 재고를 확인한다.
2. 선로 예약을 취소하면 설치/차감이 없어야 한다. 확정 비용이 부족한 기지가 하나라도 있으면 전체 작업이 실패하고 모든 원장이 유지돼야 한다.
3. A→B와 별도 B→A 선로를 확정한다. 선로 설치만으로 노선/기차가 없어야 한다. 노선 확정을 두 번 입력해도 기차는 한 대, 상태는 정지여야 한다.
4. 화물 자원을 철로 지정하고 A 적재 100/하역 0, B 적재 0/하역 100을 저장한다. 실제 연료 정책으로 충분한 석탄을 수동 적재한다.
5. 시작하면 첫 역 서비스 뒤 A 철 200, 화물 100. B 도착 서비스 후 B 철 100, 화물 0. 생산이 없는 동안 A+B+화물 철 합계는 항상 300이다.
6. 이동 중과 인계 완료 후 정차 중 각각 안전 조건에서 저장·로드한다. 위치/잔여시간·재고·연료·방문 처리 표식이 동일하고 다시 인계/출발 비용을 청구하지 않아야 한다.
7. A→B 중 중지를 요청하면 B에서 정지한다. 재개·연료 대기·오류 복구를 반복해 같은 방문의 인계가 중복되지 않는지 확인한다.
8. 기지 A의 재고가 부족하면 B에 충분한 재고가 있어도 A 소속 시설의 건설/강화는 실패한다.
9. 테스트 v1 저장의 철 300을 변환하면 메인 300·다른 기지 0. 두 번 재실행해도 총량 300. 이관 중 실패/손상/용량 초과·패배 기록 케이스도 검사한다.
10. 실제 씬 Canvas의 목록/상세/역 문맥, 입력 포커스·취소·뒤로가기를 확인한다. 기존 건설·시간·전력·안전 저장 회귀가 통과하면 P4 완료로 기록한다.

### 10.2 구현 결과에 남길 근거

- 변경한 코드·씬·프리팹·콘텐츠 목록과 적용 버전, 비용/연료/포트가 검증용인지 최종값인지.
- 원자적 결제·자원 총량·중복 입력·경로 검증의 자동 검사 결과.
- 정지/이동/정차/중지 요청/연료 부족/오류 상태의 저장 왕복 및 구버전 이관 결과.
- 실제 저장된 Canvas 계층·참조 검사와 Editor/Play 입력·표시 결과를 구분한 기록.
- 미완료 후속 기능(P5/P6), 남은 결함과 완료 판정. 문서 수정만으로 기존 테스트 수치를 새 결과로 인용하지 않음.
