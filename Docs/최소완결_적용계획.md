# 최소 완결 단계 적용계획

> **2026-09-25 현재 상태:** 시간/생산 UI, 고정 메인, 전력, 야간 예산·보스·오브, 단일 맵 저장, 기본 미니맵은 구현됐다. 미니맵은 전체 지도·적 밀집도·클릭 이동을 지원한다. 최종 맵/적 표현·경제·지역 제한·기지별 라운드는 남아 있으므로 계획 전체 완료는 아니다. [최신 문서 인덱스](README.md). 아래 본문과 검증 수치는 당시 기록을 보존한다.

작성: 2026-09-18. 근거: 사용자 일정 목록, 외부 원본 `일정 계획.md`, 현재 코드 정적 검토.
본 문서는 적용계획이며 구현 완료 기록이 아니다. 이번 작업은 문서 작성만 수행했고 Unity 실행 검증·게임 빌드는 수행하지 않았다. 외부 원본은 수정하지 않았다.

## 1. 목표와 범위

원본 프로젝트의 StartRegionSandbox를 바탕으로 낮의 건설·자원 생산과 밤의 방어가 이어지는 최소 플레이를 완성한다. 적 모델·애니메이션 연결까지를 첫 완료선으로 잡는다. 이후 지역 맵 확장, 추가 건물, 기차 운송을 진행한다.

명시된 요구:
- 시간 UI 좌상단, 자원 UI 최상단. 자원 UI의 향후 좌/우중단 이동은 레이아웃 교체만으로 가능하게 한다.
- 개발자 낮/밤 전환, 날짜별 스폰량 증가. 날짜별 적 능력치 강화는 제외한다.
- 시작 지점 설치 범위 고정, 메인 기지 에너지, 기존 넥서스의 서브 기지 역할.
- 지역별 자원 제한, 기지 레벨 해금, 자원과 방어 운용 연결, 테크 및 설치 개수 제한.
- 시작 맵과 미니맵, 적 종류·모델·애니메이션.

검토 사항은 제품 규칙으로 확정하지 않는다: 저장 건물, 서브 기지 이동·회수 변경, 날짜별 강화. 전력 체계는 이번 목록에 없으므로 추가하지 않는다. 이전 에너지 제외 결정은 이번 계획의 메인 기지 에너지 추가 요청으로 갱신하되 세부 규칙은 기지 문서를 따른다.

## 2. 현재 기반과 미완료 연결

| 영역 | 코드에서 확인한 기반 | 필요한 작업 |
|---|---|---|
| 시간·라운드 | Sandbox Running/편집 상태로 갱신 분기 | 월드 시계, 낮밤 단계, 기지별 라운드, 명시적 정지 규칙 |
| 소환 | EnemySpawnStream 대기열·최소 간격·동시 처리 제한 | 밤별 소환 예산, 기지/라운드 식별, 밤 종료 시 대기열 처리 |
| 생산 | ProductionModuleDefinition의 생산·변환, ResourceBank | 지역 허용 자원 연결, 생산 차단 사유, 경제 설정 |
| 재고 UI | OpenWorldHud에서 생산 정의를 순회해 수량 표시 | 자원 ID별 중복 없는 표시 모델·상단 배치·변경 시 갱신 |
| 지역 | RegionDefinition Bounds/ResourceId | 실제 생산 규칙 연결. 현재는 예정 자원 표시 |
| 해금 | RequiredNexusLevel과 공통 LevelCap | 소속 기지의 실제 레벨 판정. 현재 VerificationNexusLevel 기본 8 |
| 저장 | StorageModuleDefinition, 재고/용량 기반 | 저장 건물 채택은 보류. 생산 종류마다 백만 용량을 더하는 검증 초기화 제거 |
| 기지 | BaseRegistry ID·소속·영역·기지 소실 처리 | 메인/서브 역할 분리, 고정 시작 영역, 에너지 |
| 전투·건설 | 체력·적 건물 공격·방벽·회전·냉각·예약 확정/회수 | 자원 비용과 제한을 기존 트랜잭션에 연결 |
| 맵·표현 | StartRegionSandbox, Terrain 및 대규모 적 렌더링 | 최종 시작 맵 검수, 미니맵, 적 표현 교체 |

근거 파일: OpenWorldSandbox.cs, OpenWorldContent.cs, OpenWorldHud.cs, EnemySpawnStream.cs, BuildingOperations.cs, BaseModuleDefinition.cs, RegionDefinition.cs, ProductionModuleDefinition.cs, ResourceBank.cs 및 기존 Docs 적용 기록. 기존 기록의 테스트 통과는 당시 결과이며 이번 계획 작성 중 재실행한 결과가 아니다.

## 3. 먼저 확정할 규칙

아래는 구현 기본안/검토점이며 사용자 확정 내용과 구분한다. 독립적인 기반 구현은 이 결정들을 기다리지 않고 진행 가능하다.

1. **시간과 기지별 라운드:** 월드 낮밤은 하나, 기지별 방어 라운드와 난이도 카운트는 별도로 두는 안을 권장한다. 화면에는 월드 날짜와 선택 기지 라운드를 구분한다. 새 기지는 기존 기지 라운드를 상속하지 않는다. 밤중 신규 기지의 첫 참가 시점, 스폰량 증가에 사용할 월드 날짜/기지 라운드는 확정 필요. 기본 제안은 다음 밤부터 참가하고 기지 라운드 기준 증가다.
2. **낮 전환 시 적:** 낮에는 새 자동 소환과 남은 밤 대기열 유입을 멈추는 안을 제안한다. 이미 나온 적을 계속 싸우게 할지, 퇴각시킬지, 밤을 연장할지는 확정 필요. 임의로 삭제하지 않는다.
3. **시간 정지:** 수정 상태와 명시적 일시정지는 시간·자동 소환·생산·전투를 함께 정지시키는 검증안을 사용한다. 기존 편집 중 정지와 호환되도록 한다. 실제 제품의 편집 중 시간 진행 여부는 별도 확정한다.
4. **시작 고정 범위:** 메인 기지의 초기 설치/가동 영역과 외부 설치 허용 규칙을 분리한다. 이전의 외부 설치 가능·범위 밖 비작동 규칙을 전맵 설치 금지로 바꾸지 않는다. 정확한 시작 위치·크기·회전·확장 가능 여부는 참조 이미지/기획 필요.
5. **경제 귀속:** 현재 공용 재고를 초기 호환안으로 유지한다. 향후 기차 운송을 위해 재고 접근에 기지/지역 소유자 식별을 전달할 수 있게 한다. 기지별 창고·운송으로 실제 전환하는 것은 후속 결정이다.
6. **지역 제한:** 채집/생산 자원 제한과 가공품 레시피를 구분한다. 특정 원산 자원이 없는 지역에서 가공까지 금지할지는 세부 기획으로 결정한다. 경계·중첩·지역 없는 지점의 처리 규칙도 명시한다.

## 4. 적용 순서와 완료 기준

### 단계 0 — 기획 대조와 검증 구성 분리

- 기지/에너지 문서, 시작 범위 이미지, 자원·방어 비용/테크 표, 설치 제한, 미니맵, 적 종류 자료를 확보해 ID와 규칙 대조표를 만든다.
- 미정 수치는 검증 설정으로 분리하고 최종 밸런스로 취급하지 않는다.
- 기존 3개 데모 맵과 저장 키는 그대로 둔다. 기존 Sandbox 수동 소환은 개발자 기능으로 보존한다.
- 완료: 요구별 확정/제안/자료대기 목록과 검증 구성, 기존 회귀 체크리스트 확보.

### 단계 1 — 시간 시스템과 좌상단 UI

- GameClock은 누적 시간과 월드 날짜/낮밤만 담당한다. BaseRoundState는 기지별 진행도, NightSpawnDirector는 기지별 소환 계획을 담당한다.
- UI는 시계 읽기 상태와 명령을 사용한다. 개발자 패널의 낮/밤 강제 전환도 같은 전환 경로를 이용한다.
- 전환 ID를 부여해 같은 밤의 중복 소환을 막는다. 강제 전환 시 날짜·라운드 증가 규칙을 명시하고 숨겨진 자동 증가를 만들지 않는다.
- DaySpawnProfile에 증가량/곡선과 상한을 둔다. 날짜가 커져도 정수 넘침을 방지하고 기존 대기열 누적 상한과 충돌하지 않게 밤별 요청을 관리한다.
- 적 체력·공격력·이동속도는 날짜와 무관하게 유지한다. 기존 공격력 1 규칙을 보존한다.
- 큰 프레임 시간을 잘라 버리지 않고 시뮬레이션 시간 누적기로 처리하며 정지 중 누적하지 않는다. 시간 경과와 소환 처리의 프레임별 작업 예산을 분리한다.
- 완료: 자연/강제 전환, 일시정지/수정, 중복 전환, 서로 다른 기지 라운드, 날짜별 수량 증가, 능력치 불변 검증. 낮 잔존 적 규칙은 확정 후 완료 판정.

### 단계 2 — 지역 생산·해금과 최상단 자원 UI

- 기존 생산/변환 모듈과 ResourceBank를 확장하고 중복 시스템을 만들지 않는다.
- RegionResourcePolicy는 생산 허용 여부, UnlockPolicy는 소속 기지 레벨과 건물 테크를 판정한다. UI 분류로 기능을 추론하지 않는다.
- 배치 예정 건물의 소속을 예약 단계에서 명시하고 미리보기·확정·실행이 같은 기지 레벨을 사용하게 한다. 전역 LevelCap을 제품 규칙에서 제거한다.
- 지역 제한은 배치 안내와 실행 양쪽에서 검증한다. 건물 중심/전체 점유 중 지역 귀속 기준은 기획 확정 후 단일 규칙으로 적용한다.
- 자원 표시를 자원 ID 기준 목록으로 구성한다. 현재량·생산 중단 사유를 제공하고 배치 위치는 화면 레이아웃에만 둔다.
- 용량은 명시적 초기 재고 설정으로 옮긴다. 카탈로그에 같은 생산 건물을 추가했을 때 용량이 늘어나는 현재 검증 경로를 제거한다. 저장 건물 구현 확대는 보류한다.
- 완료: A/B 지역 생산 차이, 비작동 영역 생산 정지, 실제 레벨별 잠금/해제, 용량 포화·입력 부족·가공 원자성, 정지 시간 동안 생산 없음, UI 중복 없음.

### 단계 3 — 고정 시작 구역과 메인/서브 기지

- Main/ Sub 역할을 별도 기지 정의로 명시한다. 기존 넥서스 정의 ID와 기능은 유지하고 표시/역할만 서브 기지로 정리한다.
- 시작 위치·범위는 씬에서 저작한 설정을 읽는다. 화면 테두리와 설치 판정은 같은 영역 데이터를 사용한다.
- 기존 영역 제공/소속/회수/파괴 흐름을 재사용한다. 메인 기지 파괴·회수 허용·유일성은 기지 문서대로 설정한다.
- 서브 기지 이동·회수의 신규 규칙은 미적용. 기존 동작과 변경 예정 사항을 구분해 기록한다.
- 완료: 초기 영역 경계·건물 전체 점유 검사, 외부 설치 호환, 다른 서브 기지의 영역/소속 독립, 기존 넥서스 기능 회귀.

### 단계 4 — 메인 기지 에너지

- 에너지 상태/공급·소비 규칙/UI를 독립 모듈로 연결한다. 전력과 자동 통합하지 않는다.
- 세부 문서에서 단위·최대량·충전 방식·소비 시점·부족 효과·메인 파괴 시 처리·서브 기지 공유 범위를 확정한다.
- 생산된 일반 자원과 에너지 상태를 구분하되 변환이 필요하면 명시적인 변환 정책을 둔다.
- 가동 차단 사유에 에너지 부족을 추가하는 경우 체력·적 피격·선택·회수는 계속 작동한다. 어떤 건물이 멈추는지는 기획에 따른다.
- 완료: 공급/소비 경계, 부족/회복, 복수 소비자 처리 순서, 파괴/회수 구독 해제와 개체별 상태 독립. 자료 미확보 시 계약·검증 설정까지만 진행하고 기능 완료로 보고하지 않는다.

### 단계 5 — 자원과 방어 연결·테크·설치 개수 제한

- 건설 비용, 업그레이드 비용, 유지/공격 비용은 별도 정책으로 구성한다. 실제 채택한 비용만 활성화한다.
- 테크 표를 ID 기반 정의로 작성하고 누락 참조·중복 ID·순환 선행 조건·도달 불가 항목을 Editor 검증한다.
- 설치 한도는 전역/기지별/종류별 정책으로 분리한다. 한도 수치와 적용 범위는 기획 표에서 확정한다.
- 예약 시 자원·슬롯을 확보하고 확정 때 전체 재검증한다. 생성 실패 시 비용·개수·점유를 모두 되돌리며 임시 상태를 보존한다. 취소하면 예약만 해제한다.
- 방벽 두 클릭 일괄 배치도 같은 비용/개수 규칙을 통과한다. 한도 초과 시 건너뛴 수와 이유를 표시하고 성공 예약분의 최종 확정은 원자적으로 처리한다.
- 회수 예정 건물은 확정 전까지 개수를 차지한다. 파괴/회수 중복 해제를 방지한다. 환급률은 확정 기획이 없으면 구현하지 않는다.
- 완료: 복수 예약으로 한도/잔고 우회 불가, 여러 기지의 독립 한도, 취소/실패 복구, 파괴 후 슬롯 반환, 테크 해제와 비용 일관성.

### 단계 6 — 시작 맵 확정과 미니맵

- 최종 맵은 현재 Terrain/통행/스폰 경로 조건으로 검수한다. 맵 확정은 데이터·아트 승인 작업이며 코드만으로 완료 처리하지 않는다.
- 미니맵은 월드 좌표→지도 좌표 변환, 지도 배경, 기지/건물/적 표식, 카메라 위치 표시를 분리한다.
- 초기 제안은 정적 지형 배경과 기지·카메라 표식이다. 클릭 이동, 적 집계, 탐험 안개, 표시 범위는 미니맵 기획 확인 후 채택한다.
- 대규모 적에 개별 UI 오브젝트를 만들지 않는다. 적 표시 채택 시 공간 집계와 갱신 간격을 사용한다.
- 완료: 맵 가장자리/45도 배치/카메라 영역 좌표 일치, UI 클릭이 월드 배치로 전달되지 않음, 기존 시작 영역/스폰 통행 회귀.

### 단계 7 — 적 종류·모델·애니메이션과 최소 완결 검증

- 적 정의는 종류 ID·전투 설정·표현 참조를 분리한다. 모델 교체가 타겟 핸들·이동·피격을 바꾸지 않게 한다.
- 컨셉/종류 확정 후 이동·공격·사망 표현을 실제 시뮬레이션 상태에 연결한다. 공격 애니메이션이 피해를 중복 발생시키지 않게 한다.
- 기존 배열·슬롯 재사용·대량 렌더링 구조를 유지한다. 적마다 Animator/GameObject를 추가하는 방향으로 전환하지 않는다. 애니메이션 표현 방식은 목표 수량의 측정으로 선정한다.
- 완료: 지상/공중, 첫 공격 1초, 피해 1, 기절/냉각, 타겟 파괴/재선정, 슬롯 재사용 시 애니메이션 초기화 검증.
- 실제 씬에서 4천/1만/10만 시나리오의 CPU 중앙값/p95·GC·렌더링 비용을 같은 조건으로 3회 비교한다. 반복 10% 초과 악화나 전투 루프 새 상시 할당은 원인을 수정한다. 10만 적 60fps를 측정 없이 보장하지 않는다.

## 5. 구조와 이전 원칙

공통 실행 모듈은 `Assets/EternalSteam/Code`의 책임별 영역(Time, Economy, Building, Progression, Combat 등)에 둔다. 화면은 Shared/UI와 표현 코드로 분리하고 씬은 `Assets/EternalSteam/Scene`에서 관리한다. OpenWorldSandbox에는 조립과 명시적 의존성 전달만 남기는 방향으로 단계별 이전한다. 테스트용 조합을 별도 제품 규칙으로 복제하지 않는다.

정의 에셋은 불변 설정, 실행 객체는 기지/건물별 상태를 소유한다. UI는 읽기 모델과 명령만 사용한다. 전역 서비스 탐색기·범용 이벤트 버스를 추가하지 않는다. 전체 폴더 재이동, 외부 모딩, 실행 중 모듈 교체는 이번 범위가 아니다.

## 6. 최소 완료 판정과 후속 단계

시작 영역에서 건설 → 낮 생산 → 해금/방어 준비 → 밤 자동 소환 → 건물 피격/방어 → 다음 날 진행의 한 사이클이 실제 씬에서 재현되어야 한다. UI 날짜/자원/차단 사유가 실제 상태와 일치하고, 복수 기지 진행과 소속이 섞이지 않아야 한다. 회수·취소·기지 파괴·재시작과 기존 데모 저장 호환도 회귀한다.

이 단계는 세션 내 최소 플레이 기준이다. 새 진행도의 영구 저장/이어하기가 필요하면 별도 범위로 확정하고 기지의 영구 ID 및 저장 버전 마이그레이션을 계획한다. 기존 저장 키는 임의 변경하지 않는다.

최소 완료선 이후: 지역 맵 추가/연결 → 건물·컨텐츠 확장 → 기지별 물류와 기차 운송 → 장시간 경제/난이도/성능 테스트. 테스트는 마지막에 몰지 않고 각 단계에 포함한다.

첫 구현 묶음은 단계 1 시간·UI·자동 소환 기반과 단계 2 지역 생산·실제 레벨 해금 연결이다. 최종 경제/에너지/맵 규칙이 필요한 단계는 해당 자료를 대조한 후 구현한다. 일정 일수는 세부 자료와 자산 제공 범위가 확정되기 전 추정하지 않는다.
