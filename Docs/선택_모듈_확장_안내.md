# 선택 모듈 확장 안내

## 실행과 범위

`Assets/EternalSteam/Scene/Tests/ModuleSandbox.unity`를 열고 실행한다. 기본 검증 건물 3개와 확장 조합 9개가 카탈로그에 표시된다. 원래 `FoundationSandbox.unity`와 기존 데모 3개 맵은 유지한다.

다운로드의 건물·방어 건물·기타 건물 문서를 바탕으로 공격 방식, 특수 효과, 넥서스·강화, 자원 생산·저장·변환, 지상 이동 방벽을 선택 기능으로 추가했다. 실제 게임의 밸런스·강화 비용·자원 체계·시야 차단·경로 탐색·영구 저장은 확정하지 않았다. 이번 확장도 기존 데모로의 이전과는 별개다.

1. 넥서스와 원하는 포탑을 임시 배치하고 확정한다.
2. 넥서스를 선택해 강화한다. 포탑의 강화 레벨은 넥서스 레벨까지 허용된다.
3. 에너지 저장소와 생산기를 설치한다. 부품 변환기는 에너지를 소비하고 자체 저장 용량에 부품을 적립한다.
4. 지상 이동 방벽은 지상 적의 이동을 막고 적의 공격을 받는다. 공중 적은 통과한다.
5. 전투 시작 후 공격·특수 효과·자원 변화를 확인한다. 검증 씬의 적은 30초가 지나면 통과 처리되며, 통과한 적마다 넥서스에 피해 25를 준다. 넥서스가 파괴되면 즉시 패배한다.
6. 결과에서 초기화하면 새 월드와 서비스가 생성되어 건물·자원·넥서스 상태가 초기화된다.

넥서스 없이도 공격만 시험할 수 있다. 다만 넥서스 제한이 있는 건물의 강화는 불가능하다. 전투·생산은 전투 단계에서만 진행한다. 강화는 준비 단계에서만 가능하며 검증용으로 무료다.

## Inspector에서 조합하기

| 목적 | 에셋 구성 |
|---|---|
| 단일 즉시 공격 | Attack 모듈의 Execution을 비움 — 기존 에셋 호환 기본값 |
| 광역·관통·연쇄 | `Create → Eternal Steam → Attacks`에서 실행 에셋을 만들고 Execution에 연결 |
| 유도 투사체 | Homing Projectile 실행 에셋, Speed·Lifetime 지정 |
| 둔화·기절·방어력 감소 | Effects/Status 에셋의 Kind·Strength·Duration을 지정하고 Attack의 Effects에 추가 |
| 내구도 | Building의 Modules에 Health 추가 |
| 넥서스 | Health와 Nexus 추가, Recoverable 해제 |
| 강화 | Upgrade 추가, 최대 레벨·레벨당 공격력 및 체력 증가율 지정 |
| 저장소 | Storage 추가, 문자열 ResourceId와 Capacity 지정 |
| 생산기 | Production or Conversion 추가, OutputId·OutputAmount·Interval 지정 |
| 변환기 | 같은 생산 모듈에 InputId와 InputAmount도 지정 |
| 이동 방벽 | Movement Obstacle 추가. 파괴 가능한 방벽은 Health도 추가 |

건물 정의를 카탈로그에 등록하면 UI 코드 수정 없이 목록에 표시된다. 특정 기능을 제거할 때는 Modules·Execution·Effects의 해당 참조를 변경한다. 설정은 개체 생성 시 복사되며 실행 중 에셋 수정은 이미 생성된 개체에 반영되지 않는다. 소스 폴더 삭제나 실행 중 모듈 교체는 보장하지 않는다.

새 동작은 `AttackExecutionDefinition`, `HitEffectDefinition`, `BuildingModuleDefinition`을 상속해 추가한다. 건물 분류가 기능을 자동으로 부여하지 않는다. 건물마다 실행 객체가 따로 생성되고, 회수·파괴·설치 실패 시 종료된다.

## 구현 계약과 검증용 선택

- 광역: 최초 타겟 중심 반경 안에서 공격 종류·건물 부채꼴 조건을 만족하는 대상에 피해를 준다.
- 관통: 최초 타겟을 향한 직선 폭 안의 대상을 가까운 순서로 최대 개수만큼 타격한다. 같은 거리면 ID 순서다.
- 연쇄: 이미 맞은 대상은 제외하고 직전 적중 위치에서 가장 가까운 다음 대상을 고른다. 매 타격마다 피해 유지율을 적용한다. 모든 연쇄 대상에 원래 건물의 종류·부채꼴 조건을 적용한다.
- 투사체: 타겟 식별자와 세대를 저장한 이동 상태를 보유한다. 발사 후 사거리·각도·필터 변경으로 취소하지 않는다. 현재 타겟 중심에 도달할 때 피해를 주며 타겟 사망·등록 해제·세대 변경·수명 만료 시 소멸한다. 발사 건물 회수·파괴 시 해당 건물의 비행 상태도 정리한다. 물리 콜라이더 충돌 대신 중심 도달을 쓰는 첫 유도 방식이다. 표현은 이동 위치의 짧은 선분이며 전용 투사체 아트는 미정이다.
- 특수 효과: `IStatusReceiver`를 구현한 대상에만 적용한다. 같은 종류는 가장 강한 효과가 적용되고 각 적용의 지속시간은 독립적으로 만료된다. Strength는 0~1 비율이며 기절은 양수이면 이동과 샘플 적의 방벽 공격을 멈춘다. 샘플 적은 이동 배율과 방어 감소를 실제로 사용한다. 기존 Horde 적 어댑터에는 아직 연결하지 않았다.
- 강화: 일반 건물은 활성 넥서스 레벨을 초과해 강화할 수 없다. 넥서스 자신의 강화는 자신의 MaximumLevel까지만 허용된다. 여러 넥서스를 조합하면 최고 레벨을 상한으로 사용하며 하나라도 파괴되면 패배한다. 기존 건물 레벨을 강제로 낮추지는 않는다. 체력 강화는 현재 체력 비율을 보존한다. 공격력 증가율·체력 증가율 기본값은 검증용이다.
- 넥서스: 회수할 수 없고 내구도가 필요하다. 실제 파괴만 패배 사건을 발생시키며 월드 종료·생성 롤백은 패배로 처리하지 않는다.
- 자원: 생산·변환은 출력 저장 용량과 입력 잔량을 함께 검사해 모두 성공할 때만 반영한다. 저장소 제거 시 용량만 줄이고 이미 저장한 자원은 보존한다. 용량 초과 상태에서는 추가 생산을 막는다. 가격·환불·강화 비용·영구 저장은 없다.
- 이동 방벽: `MovementObstacles`에 점유 영역을 등록한다. 샘플 지상 적은 다음 이동 위치를 검사해 멈추고 방벽을 공격한다. 우회 경로 탐색이나 NavMesh는 포함하지 않는다. 시야 차단과는 별개다.

`BuildingServices`에서 `NexusState`, `ResourceBank`, `MovementObstacles`, `ITargetQuery`를 명시적으로 전달한다. 해당 기능이 없는 조합에는 그 서비스가 필요 없다. 일반 이벤트 버스나 전역 서비스 탐색기는 사용하지 않는다.

## 생성·검증

처음 생성할 때 `Eternal Steam → Foundation → Create Extension Samples`를 사용한다. 이미 생성된 확장 에셋이 있으면 덮어쓰지 않는다. 샘플은 `Content/Buildings/ModuleSamples/Data`, 카탈로그는 `Settings/Catalogs/ModuleCatalog.asset`, 씬은 중앙 `Scene/Tests`에서 관리한다.

EditMode·PlayMode 테스트는 기존과 같은 두 어셈블리에 포함된다. 결과는 `Docs/Validation/modules-editmode.json`, `modules-playmode.json`과 `선택_모듈_검증.md`에 기록한다.

## 개발 의존성

Inspector는 조합을 저장하는 수단이다. 기능 간 구체 클래스 참조를 제거하고 컴파일 경계를 나눈 구조와 교체 계약은 [개발 모듈 경계](개발_모듈_경계.md)를 따른다.
