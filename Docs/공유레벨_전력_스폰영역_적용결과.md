# 공유 레벨·전력·스폰 영역 적용 결과

2026-09-20 착수, 2026-09-21 정리. [적용계획](기지_공유레벨_전력_스폰영역_적용계획.md)의 1~4단계를 원본 `StartRegionSandbox`의 단일 세션에 연결했다. 최종 비용표·캠페인 저장·실제 맵 전환은 아직 구현하지 않았다.

## 플레이 방법

1. 수정 → 설치 분류 → 메인 기지 설치·확정.
2. 자원 분류의 **전력 발전기**를 기지 범위 안 지면에 설치·확정.
3. 방어 포탑을 범위 안에 설치·확정. 첫 전력 정산 이후 공격한다.
4. 기지를 선택하면 상단에서 해당 기지의 현재/최대 전력, 생산·요청·실제 소비를 확인한다. 포탑/발전기 선택 정보에는 연결 상태가 표시된다.

## 적용한 모듈

- `CampaignProgression` + `ICampaignMainLevel` + `MainBaseUpgradeDefinition`: 주입된 공통 캠페인 레벨을 모든 메인이 참조. 새 메인도 공통 레벨을 사용하며 최고 레벨 병합 API·상한 검증 제공. 메인 전력·체력이나 서브의 개별 레벨은 복제하지 않는다.
- `PowerModuleDefinition` / `PowerModule`: 저장·발전·소비 설정을 실행 상태로 복사한다. 별도 `BasePowerSimulation`이 기지별 연결과 정산을 수행한다.
- `ICombatPermission` / `IUnpoweredCombat`: 기반·전투 어셈블리가 전력 구현에 직접 의존하지 않는 공통 계약. 신규 무기와 기존 4종 포탑이 같은 공급 허가를 사용한다.
- `SpawnAreaValidator`: 일반 1칸, 보스 9칸의 경계·지면·건물·토대 충돌 검사. 검증용 보스 모양은 설정의 3×3이다.
- `SpawnAreaView`: 씬에 미리 저작한 선으로 구역 표시. 게임에서는 수정 중에만 표시하며 평상시에 상시 표시하지 않는다.
- `BasePowerView`: 기존 UXML의 전력·선택 정보 갱신. 실행 중 UI 계층을 새로 만드는 방식이 아니다.

새 구성 에셋은 `Assets/EternalSteam/Content/Buildings/BasePower`에 두고 시작 씬 카탈로그에 연결했다. 이전 콘텐츠 에셋을 광범위하게 덮어쓰지 않았다. 변경 전 저장되지 않은 씬 상태는 `Assets/EternalSteam/Scene/Tests/StartRegionBeforeBasePower.unity`에 별도 보관했다.

## 검증용 정책과 수치

최종 경제·밸런스로 확정한 값이 아니다.

- 발전기: Lv.1, 일반 지면, 1셀, 간단한 모델, **20 전력/초**.
- 방어 건물: **5 전력/초**. 기존 4종은 외부 공격 어댑터 전용 소비 설정을 사용한다. 일반 조합은 공격 모듈이 제거되면 전력 수요도 사라진다.
- 메인/서브 저장: **200 + (레벨-1)×20**. 강화는 용량만 늘리고 잔고를 채우지 않는다.
- 기지 간 전력 이동/합산 없음. 정상 연결이 유효하면 유지하며, 끊어진 경우 범위를 포함하는 최근접 기지로 재연결한다. 동거리에서는 BaseId 순. 부족하다고 다른 기지로 갈아타지 않는다.
- 1초 단위 정산. 부분 시간의 생산·수요를 실제 존재한 시간만 누적하므로 정산 직전에 발전기를 놓아 과거 시간의 전력을 얻지 않는다. 기지 설치 전에는 정산 시계를 누적하지 않는다.
- 기지의 정산 수요 전체를 충족하면 공급하며 부족하면 그 주기의 신규 공격을 차단하고 잔고를 보존한다. 생산은 계속 저장한다. 공격 쿨다운·조준 회전은 전력 부족 동안 진행하지 않는다.
- 이미 발사된 투사체·연쇄 실행은 전력 부족만으로 사라지거나 멈추지 않는다. 적에게 이미 부여된 상태효과는 기존 수명대로 처리한다.
- 회수 예정 발전기는 확정 전까지 생산한다. 회수/파괴된 기지의 전력은 다른 곳으로 자동 전송하지 않으며 검증 세션에서는 소멸한다. 최종 회수 보존 규칙은 미정이다.
- 수정/시간 정지 시 전력 진행도 정지한다. 전력과 기존 지역 에너지/일반 자원 원장은 별개다.
- 보스 스폰 3×3은 별도 예약 구역으로 건설·토대 배치를 막는다. 안전 영역 예외는 유지하되 지면/건물 충돌은 무시하지 않는다. 유효성이 깨지면 소환을 보류하고 UI에 사유를 표시한다.
- 보스전 일반 소환 지점 수는 기존 **8개**다. 보스의 면적 9칸과 혼동하지 않는다.

## 검증

- C# 컴파일 통과.
- `VerifySharedBasePower`: 공유 레벨·신규 메인 레벨·최고 레벨 병합·잘못된 값 거부·서로 다른 잔고·정산 분할·부분 시간 설치·공격 없는 조합의 소비 0·전력 부족·회수 후 연결·강화 시 무충전 통과.
- `VerifyBasePowerIntegration`: 실제 기지/발전기/포탑 설치, 20 생산/5 소비, 발전기 회수 예정·취소·확정, 고갈 시 건물 유지와 공격 허가 차단, 9칸 전체 구역 및 예약, 저작 UI 통과. 첫 정산 시점 검증에서 발견한 기지 설치 전 시간 누적을 수정하고 재검증했다.
- `VerifyPoweredCombat`: 실제 기존 4종의 전력 없는 공격 차단·전력 있는 발사·고갈 시 쿨다운 유지, 신규 무기 차단, 발사 후 고갈되어도 기존 투사체 명중 통과.
- `VerifyWeaponContracts`: 연사·추적·연쇄·관통·투사체·EMP·공중 필터·과열·기절·화상·슬롯 재사용 회귀 통과.
- `VerifyBasePlanning`: 메인 1개·서브 5/10개·최대 레벨·범위·HP·중첩 가동·메인 파괴 회귀 통과.
- `VerifyLegacyRotation`: 전력과 분리한 회전/정렬/강화 회귀 통과. 전력은 별도 실제 공격 검증에서 확인했다.
- `VerifyMapAssaultIntegration`: 에너지 → 야간 소환 → 실제 보스 → 보상 → 오브 제작 흐름 회귀 통과.

`BenchmarkBasePower`: 건물 수별 3회×120표본, 매 표본 1초 정산 호출, 워밍업 후 측정.

| 소비 건물 수 | CPU 중앙값 범위 | p95 범위 | GC |
|---:|---:|---:|---:|
| 100 | 0.0029~0.0030ms | 0.0050~0.0087ms | 0 B |
| 1,000 | 0.0254~0.0589ms | 0.0641~0.1182ms | 0 B |

위 기능 검증은 Editor 안에서 결정적으로 호출한 통합 검증이다. UI 요소의 저작·현재 텍스트 바인딩은 확인했으며, 이번 마지막 실시간 관찰은 Editor PlayerLoop가 진행하지 않아 자동 프레임 검증의 통과로 기록하지 않았다.

전력 정산만의 비용이며 전체 전투/렌더 프레임 결과가 아니다. 적 배열을 순회하는 전력 처리는 추가하지 않았다. 전체 4천/1만/10만 적의 전후 성능 비교는 이번 결과로 대체하지 않는다.

## 남은 범위

- **5단계:** 강화 자원 비용표 미수신. 현재 강화는 검증용 무상이다. 다중 자원 결제·영구 저장·손상 저장 복구·실제 맵 전환은 미완료다.
- 공통 레벨 객체를 두 컨텍스트에 주입하는 구조/동작은 검증했지만, 씬을 바꿔 실제 다른 맵을 방문하는 캠페인은 아직 없다. 현재 Sandbox는 Play마다 새 캠페인을 생성하며 **Play 종료 시 레벨·전력·에너지 상태는 저장되지 않는다.**
- BaseId는 현재 세션 GUID다. 저장 기반이 들어오기 전에는 재실행 시 같은 ID로 복원되지 않는다.
- 최종 전력 수치, 부족 시 우선 공급, 기지 회수 전력 보존, 보스 구역의 최종 모양/건설 제한은 기획 확정 후 검증 정책을 교체한다.
- 기차·전력 코어 운송·재활성화·비활성 맵 전력 진행은 추가하지 않았다.

게임 빌드·새 프로젝트 생성·GitHub 업로드는 수행하지 않았다.
