# 표적 탐색 최적화 연구 확장 검토

2026-10-02 · 연구 설계 검토

기존 세미나 계획은 포탑의 공격 범위와 적 밀도에 따라 전체 순회, 격자 탐색, 조건별 선택의 비용이 어떻게 달라지는지 묻는다. 현재 게임에는 이미 2m 격자 인덱스가 있으므로, 후속 연구는 **공격 유형별 탐색 비용과 격자 유지 비용을 분리해 측정하고, 동일한 명중 결과를 보장하는 선택 기준을 찾는 것**으로 구체화하는 것이 적절하다. 이 문서는 연구 범위와 실험안을 정리한 것이다. 성능 개선이나 학술적 신규성이 확인됐다는 뜻은 아니다.

## 기존 계획과 현재 구현의 차이

[세미나 발표 노트](표적탐색_최적화_세미나_발표노트.md)와 8쪽 연구계획 PDF는 전체 순회를 기준으로 격자와 조건별 선택을 비교하고, 탐색 결과 일치 및 자료구조 갱신 시간을 확인하도록 제안한다. 현재 구현은 이미 혼합 상태다.

| 경로 | 현재 탐색 방식 | 연구에서 확인할 점 |
| --- | --- | --- |
| 레거시 기관총 | 격자 후보에서 좁은 사선의 첫 대상 탐색 | 단일 표적의 거리·동률 규칙을 유지하며 후보 수와 조회 비용 비교 |
| 레거시 대포 | 격자로 폭발 중심을 정하고 격자로 원형 피격 대상 조회 | 중심 선택과 범위 피해를 별도 질의로 기록 |
| 레거시 냉각 | 격자 후보에 부채꼴 판정 | 넓은 질의 영역과 실제 피격 수의 차이 측정 |
| 레거시 관통 화살 | 피격 대상 판정에서 전체 슬롯 순회 | 좁은 사선 후보만 얻는 방식의 이득과 격자 셀 순회 비용 비교 |
| 공통 무기 모듈 | `ITargetQuery`를 통해 후보를 조회하며, 오픈월드 어댑터는 격자를 사용 | 레거시 결과를 그대로 일반화하지 않고 별도 재현 |

근거는 [`HordeEnemyWorld`](../../Assets/EternalSteam/Code/LegacyDemo/Combat/HordeEnemyWorld.cs), [`HordeAttackResolver`](../../Assets/EternalSteam/Code/LegacyDemo/Combat/HordeAttackResolver.cs), [`HordeTowerCombat`](../../Assets/EternalSteam/Code/LegacyDemo/Buildings/HordeTowerCombat.cs), [`HordeTargetAdapter`](../../Assets/EternalSteam/Tests/OpenWorld/Runtime/HordeTargetAdapter.cs), [`WeaponModuleDefinition`](../../Assets/EternalSteam/Code/Combat/WeaponModuleDefinition.cs)이다. 적 월드는 이동과 함께 격자 연결 목록을 매번 재구축한다. 따라서 “격자를 새로 도입해 빨라졌다”는 비교는 현행 구현을 설명하지 못한다. 슬롯 전체 순회와 **살아 있는 적만 순회하는 기준선**도 구분해야 한다.

과거 [대규모 적 소환 검증](../Validation/대규모_적_소환_검증.md)의 10만 적 `MoveAndIndex` 중앙값 15.27ms는 이동·지형 높이 조회·인덱스 비용을 합친 Editor 측정이며 포탑 탐색과 빌드 프레임은 제외한다. 표적 탐색의 예상 개선율로 사용하지 않는다.

## 선행연구에서 가져올 방법과 적용 한계

| 연구 | 이 연구에 유용한 방법 | 그대로 옮길 수 없는 부분 |
| --- | --- | --- |
| [Teschner 외 2003](https://cgl.ethz.ch/Downloads/Publications/Papers/2003/Tes03/Tes03.pdf) | 셀 크기와 버킷 구성에 따른 후보 수·비용을 실측한다. | 원 논문은 변형 물체의 3차원 충돌 후보를 해시 격자로 찾는다. 현재 게임의 경계가 있는 2차원 배열 격자에서 원 논문의 최적 셀 크기나 속도 향상을 인용할 수 없다. |
| [Avril 외 2011](https://hal.science/hal-00555720) | 장면 상태가 변할 때 방식별 손익 구간을 측정한 뒤 전환한다. | 원 연구는 충돌 탐색의 CPU·GPU 실행 구성을 다룬다. 본 연구의 첫 전환 대상은 같은 CPU 안의 전체 순회와 격자 질의이며, GPU 전환 효과를 가정하지 않는다. |
| [Serpa·Rodrigues 2020](https://diglib.eg.org/items/3f3ae64f-f946-44b5-bd99-e49c27e8fb34) | 공통 입력 장면을 재생하고 인덱스 갱신·질의를 분리 기록하는 비교 틀을 따른다. | 원 연구의 충돌 후보 쌍과 포탑의 첫 대상·전체 피격 집합은 출력 의미가 다르다. 게임의 명중 규칙을 별도로 검증해야 한다. |

세 연구는 실험 방법의 근거다. 포탑 공격 형태별 동적 선택이 새로운 학술 기여인지는 표적 선택, 게임 AI 공간 질의, 동적 인덱싱 문헌을 더 조사한 뒤 판단해야 한다.

## 확장 방향과 우선순위

| 우선순위 | 확장안 | 판단 |
| --- | --- | --- |
| 1 | 레거시 4종 포탑에서 슬롯 전체 순회, 생존 적 순회, 현행 2m 격자를 같은 입력으로 비교 | 즉시 진행. 기존 발표 질문을 실제 코드에 맞춰 검증할 수 있다. |
| 2 | 격자 셀 크기와 적의 분포·이동량·질의 형태의 상호작용 비교 | 1의 결과에서 격자 질의나 재구축이 의미 있는 비용일 때 진행한다. 2m를 기준으로 몇 개 크기를 사전 지정한다. |
| 3 | 관측된 손익 경계에 따른 CPU 탐색 방식 선택 | 조건부 진행. 구간별 우위가 재현되고, 전환 비용을 포함해 이득이 남을 때만 구현한다. |
| 4 | 공통 무기 모듈과 실제 출시 장면으로 재현 | 내부 타당성 확인 뒤 진행한다. 무기 종류·전투 규칙이 달라 독립 검증이 필요하다. |
| 보류 | GPU 이전, DOTS 병렬화, 새 자료구조 다수 추가 | 첫 연구 질문의 효과를 흐릴 수 있다. CPU 기준 결과와 병목이 확인된 뒤 별도 과제로 판단한다. |

이 순서는 연구를 위해 출시 기능을 먼저 바꾸자는 뜻이 아니다. 측정용 구현은 게임 동작과 분리해 비교하고, 제품 코드 채택은 실제 플레이 효과와 회귀 검증 뒤 결정한다.

## 연구 질문과 비교 설계

**RQ1.** 공격 형태별로 후보 수와 탐색 시간은 적 수, 밀집도, 포탑 수에 따라 어떻게 변하는가? **RQ2.** 격자 재구축을 포함한 총 CPU 비용에서도 격자가 전체 순회보다 유리한 조건이 있는가? **RQ3.** 관측된 조건에 따라 탐색법을 선택하면 고정 방식보다 실제 프레임 지연을 줄일 수 있는가? RQ3는 RQ1·RQ2에서 뚜렷한 손익 경계가 확인될 때만 본 실험으로 승격한다.

첫 실험은 저장된 적 위치·생존 상태·세대 번호·포탑 위치와 방향·공격 시점을 동일한 순서로 재생한다. 적 수는 소수·중간·고밀도 구간을 예비 측정으로 정하고, 같은 수라도 **균일 분포, 국소 군집, 이동 중 군집**을 구분한다. 포탑은 1개와 다수 배치를 사용하되, 각 비교에서는 공격 종류·범위·난수 시드·시뮬레이션 간격을 고정한다. 셀 크기는 현행 2m를 포함해 사전 지정하고, 장면에 맞춰 사후에 유리한 값만 고르지 않는다.

비교 구현은 다음 순서로 둔다.

1. **기준선:** 현행 관통 화살과 같은 전체 슬롯 순회, 살아 있는 적 목록의 전체 순회를 각각 측정한다.
2. **현행 격자:** 같은 정밀 판정으로 후보를 걸러 명중 결과를 만든다. 질의 비용과 `MoveAndIndex` 재구축 비용을 따로 기록한다.
3. **셀 크기 변형:** 격자 구조를 제외한 자료 배치와 판정 코드를 유지하고 셀 크기만 바꾼다.
4. **선택 방식:** 예비 결과로 정한 관측 변수와 경계값을 고정한 뒤, 새 시드와 배치에서 평가한다. 전환 판단·자료구조 준비·실제 전환 시간을 포함한다.

격자가 이미 다른 시스템에서도 쓰이므로 비용은 두 관점으로 보고한다. **질의 추가 비용**은 기존 인덱스를 공유하는 제품 상황을 나타내고, **인덱스 구축까지 포함한 총비용**은 격자를 쓰지 않는 기준선과 공정하게 비교하기 위한 값이다. 전환 방식이 프레임마다 흔들리면 이득이 사라질 수 있으므로, 선택 방식에는 최소 유지 시간 또는 서로 다른 진입·복귀 경계값을 둔다. 값은 예비 데이터에서 정하고 본 실험 전에 고정한다.

## 결과 일치와 성능 판정

모든 방식은 동일한 정밀 판정 뒤 결과를 비교한다. 단일 표적은 **대상 ID와 세대 번호**, 범위 공격과 레거시 관통 화살은 **피격 대상 집합**을 확인한다. 공통 무기 모듈의 관통 공격으로 확장할 때는 **진행 방향 순서와 최대 피격 수**도 비교한다. 거리 동률, 사망 직후, 슬롯 재사용, 공중·지상 구분, 격자 경계 및 월드 경계 밖 위치, 범위 경계값을 포함한다. 공격으로 적 상태가 바뀌는 실제 전투에서는 첫 불일치 시점부터 이후 프레임이 달라질 수 있으므로, 탐색 단독의 스냅샷 일치와 전투 전체의 결과 일치를 별도로 검사한다.

성능은 조건별 호출 횟수, 검사 후보 수, 질의 시간의 중앙값·95백분위, 인덱스 갱신 시간, 전환 시간, 프레임당 할당량으로 보고한다. 실제 전투에서는 같은 빌드·장비·품질 설정에서 Main Thread와 GPU 시간, 프레임 시간의 중앙값·95백분위, 사전에 정한 프레임 예산 초과 횟수를 함께 기록한다. 실행 순서를 교차하고 워밍업 뒤 여러 회 반복한다. Editor 수치와 빌드 수치는 합치지 않는다.

채택 판단은 명중 결과가 일치하고, 독립 시드에서 **갱신·전환 비용을 포함한 프레임 개선**이 반복되는 경우에만 내린다. 질의 단독이 빨라도 전체 프레임에서 차이가 없거나 GPU가 병목이면 게임 성능 개선으로 주장하지 않는다. 결과가 없거나 반대이면 그 조건과 비용을 그대로 보고한다.

## 다음 산출물과 미해결 사항

첫 단계의 산출물은 재생 가능한 입력 장면, 방식별 동일 결과 검사, 원시 프레임 로그, 조건별 비용 표다. 그 결과로 셀 크기 실험의 필요성과 선택 방식 구현 여부를 결정한다. 이후 실제 전투의 화면·포탑·적 배치를 포함한 빌드 측정으로 적용 가능성을 확인한다.

아직 결정해야 할 것은 목표 장비와 프레임 예산, 실험할 적 수·밀집도 범위, 공통 무기 모듈까지 포함할 시점이다. 이는 연구 시작 전 기록할 실험 설정이며, 현재 자료만으로 최적 셀 크기·전환 경계·논문 신규성을 확정할 수 없다.
