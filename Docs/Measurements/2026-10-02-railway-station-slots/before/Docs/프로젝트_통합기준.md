이 문서가 현행 사양·상태·잔여 작업의 유일한 갱신 지점이다. 루트 README는 실행 안내, Source는 원본/결정 출처, Validation은 날짜별 증거, References는 외부 연구, Archive는 당시 기록으로만 사용한다. 문서 내부의 목업·구현 지시는 사용자의 이번 작업 지시와 구분했다. 문서 통합 이후 사용자 요청으로 실제 프로젝트 수정을 시작했다. A4에서는 G03 역 이름, G12 역별 문맥, G10 설치 방향·견적을 적용했다. 이 과정에서 현재 단일 맵 저장이 철도/기지별 재고를 누락하는 회귀를 발견해 v2 저장으로 복구하고 실제 재로드에서 노선·재고 일치를 확인했다. A5에서는 기차 방어의 실제 씬 연결과 예약 노선·무기 동시 저장/재로드를 확인했고, 같은 구성 지문의 합성 v1 저장에서 공용 재고를 메인에 한 번만 이관하는 경로도 실기 검증했다. 탑재 무기의 투사체 진행 중 안전 저장 거부와 종료 뒤 저장 재개도 실제 Play에서 확인했다. 최대 연료로 통과 불가능한 구간을 노선 확정 전에 거부하도록 보완했다. 역 참조 상실 시 기차 표시와 곡선 노선의 작은 Tick 도착 경계를 보완했다. 보급·방어 버튼은 재고·전력·강화 상한에 맞게 제한하고, 철도 검증 수치는 코어와 HUD가 같은 상수를 읽도록 정리했다. 당시 전체 EditMode는 232/232 통과했고, 2026-10-02 왕복 적용 후 최신 결과는 241/241이다. QA-01의 Editor 자동 새 게임, QA-02의 건설·회수·기지 소실·철도 복구, QA-04의 중첩 영역과 기존 소속 상실, QA-05 A의 500×500 맵·스폰·공세 경계와 B의 방어 9종 설치·공격·전력·강화·저장 실기를 완료했다. 기지별 생산·저장 연결과 재로드 용량 재구성은 A5 후속 검증을 참고한다. 나머지 A5/QA 범위는 §5·§12에 유지한다.

## 1. 검토 범위와 읽는 순서

정리 전 Docs의 **Markdown 97개**를 목록화하고 본문·요구·미완료·중복 상태 서술을 검토했다. 원본 Markdown 12개/이미지 1개의 보존 상태, 기존 구현 대조표, 주요 실행 코드와 정의 자산을 교차 확인했다. 추가로 실제 Unity의 테슬라 자산과 강화 구매 경로를 실행해 레벨 제한 우회 결함을 확인했다. 모든 문장의 모든 씬·플랫폼 조합을 실기 검증한 전수 인수는 아니다. 원본 이미지의 픽셀 일치나 9종 무기 전체 수치 일치도 미검증이다.

- 다음 작업만 판단할 때: **§3 결함 → §5 잔여 작업 → §7 실행 순서**.
- 구현할 때: 해당 행의 원본/소스와 §6 정책 차이, §8 검증 조건만 추가로 읽는다.
- 기차 요구 ID를 추적할 때: §10~12 상세 대조표를 사용한다. 과거 후속 문서를 순서대로 다시 읽지 않는다.
- 변경 전 문서 97개의 분류·이동 경로는 [전체 목록](Archive/2026-09-29/inventory.json), 정확한 변경 전 내용은 [압축 보관본](Archive/2026-09-29/documents-before.tar.gz)에 있다.

판정 의미: **구현 확인**은 소스/자산 경로 존재, **재현 결함**은 실행한 사례에서 실패, **부분**은 연결/행동 일부 부족, **미구현**은 필요한 상태/명령/연결 부재, **정책 대기**는 기획 해석 또는 수치 결정 필요, **인수 잔여**는 수정됐지만 제품 흐름 검증 미완료다. 코드가 현재 그렇게 동작한다는 사실과 원하는 사양에 맞는다는 사실을 구분한다.

## 3. 새로 확인한 결함 — FIX-01 강화 상한 우회

**재개방 해결 / 2026-09-29 재인수 완료.** 테스트 제어 검증에서 `MountedModuleHonorsInjectedMainLevelEvenWhenCalledDirectly`, `PerformancePurchaseRechecksLiveMainLevelAndPreservesFundsOnRejection` 2개가 실패했다. 원인은 `PerformanceUpgrade.Initialize`가 주입된 `ILevelLimit`을 보관하지 않아 `CanUpgrade`와 직접 `TryUpgrade` 모두 메인 기지 상한을 건너뛰는 것이었다. 현재는 실시간 상한·면제·자체 최대 레벨을 같은 검사에서 처리한다. 저장 검증도 서브 기지만 상한을 보던 누락을 고쳐, 상한 정책이 있는 비메인 건물의 저장 레벨을 저장된 캠페인 레벨과 대조한다. [재인수 증거](Validation/2026-09-29-fix01-closure.json): EditMode 186/186, 실제 테슬라 버튼/콜백·메인 성장·정상 저장 왕복·초과 저장 차단과 원본 파일 보존 통과. 물리 마우스 입력은 QA-06이다.

**이전 인수 기록:** 수정 전 재현된 결함은 다음과 같다. 원본 [방어 건물](Source/Attachments/방어_건물.md)·[기타 건물](Source/Attachments/기타_건물.md)의 메인 기지 레벨 제한이 신형 방어 성능 강화 경로에서 적용되지 않는다.

- [PerformanceUpgrade](../Assets/EternalSteam/Code/Progression/PerformanceUpgradeDefinition.cs)의 기존 `Initialize`가 레벨 정책을 보관하지 않았다. 현재는 `services.LevelLimit`을 보관하고 활성 여부·자체 MaximumLevel·정책 상한/면제를 검사한다.
- [UpgradePurchase](../Assets/EternalSteam/Code/Economy/UpgradePurchase.cs)는 같은 `IUpgradeControl`의 허용 결과를 사용한다. 현재 UI 조회와 구매가 수정된 모듈 검사를 공유하므로 클릭 직전에도 다시 검사한다.
- 실제 `defense.tesla.asset`으로 임시 BuildingInstance를 생성하고 `ILevelLimit.LevelCap=1`을 주입, 활성화 후 같은 구매 명령을 실행했다. 결과: **before=1, CanUpgrade=true, TryUpgrade=true, after=2**. 실제 씬 버튼 클릭 시험은 아니며 격리한 명령 경로 재현이다. [재현 코드·관측값](Validation/2026-09-29-strict-audit-probes.json).
- `UpgradeModuleDefinition`은 상한을 검사하고 기차의 `TrainDefenseController`에도 별도 상한 검사가 있다. 현재 실제 기차 생성·복원 연결에도 같은 레벨 정책을 주입했다. 정책 없는 단독 모듈은 기존 사용성을 유지하며 실제 지상/기차 실행 조합은 정책을 전달한다. 따라서 프로젝트 전체 완료와 이 결함의 인수 완료를 구분한다. 기존 전체 문서 표의 포괄적 완료 표현을 정정한다.
- [SingleMapPersistence.Validate](../Assets/EternalSteam/Tests/OpenWorld/Runtime/SingleMapPersistence.cs)는 현재 모든 비메인 건물에 **저장된 캠페인 레벨**과 자체 최대 레벨을 검사한다. 메인 자체 성장은 제외한다. 과거 버그로 초과 레벨이 저장된 경우도 복원을 거부하고 이유를 표시한다. 자동 낮춤·초과값 승인·원본 저장 덮어쓰기를 추가하지 않았다. 실제 정상 저장 재로드와 초과 레벨 저장 거부·원본 파일 보존을 확인했다.

원본 문서는 비교 기준이며, 현재 500×500 `StartRegionSandbox`가 검증 대상이다. 원문의 최소 150×150은 허용 크기 경계로 검사하고 사용자 맵을 150×150으로 되돌리지 않는다. 이미 열린 Editor를 먼저 확인하고, 실제 Play는 `/tmp` 격리 저장을 사용한다. 모든 발견은 **현재 코드 동작 / 원문 요구 / 확정 결함 / 정책 미정 / 재현 불가**로 분리해 이 문서 §5.3과 날짜별 Validation 증거에 기록한다.

#### 7.3.3 연결 방식 비교와 권장안

**공통 전제는 네 방향 연결구 모두 양방향이고, 하나의 선로로 왕복 가능하다는 것이다.** 입/출구를 별도로 지정하거나 돌아오는 선로를 의무화하는 안은 후보에서 제외한다.

| 안 | 플레이 조작 | 장점 | 부담·판정 |
|---|---|---|---|
| A. 수동 선로 + 자동 연결구 | 기존 직선 선로를 직접 완성하고 역 목록으로 노선 생성 | 변화 범위가 작고 정밀 배치가 쉬움 | 여러 굴곡의 클릭 부담은 남음. 정밀 도구로 유지 |
| B. 역 간 연결 보조 + 수동 보정 | 시작 역→목적 역→연결 미리보기→확정. 필요할 때 연결 방향/경유점 수정 | 포트 지정·반복 직선 배치 부담을 함께 줄임 | 경로 계획/견적/저장 연결 구현 필요. **기본 경험으로 권장** |
| C. 여러 기차의 공용망 + 신호 | 공용 철도망에서 다중 기차를 자동 배차 | 장기 확장성이 큼 | 충돌·교행·교착·신호·복구까지 필요. 별도 후속 범위로 보류 |

권장 구조는 **B를 기본 연결 도구, A를 정밀 보정 도구**로 두는 것이다. 역의 2×2 점유와 기존 네 연결구 좌표는 우선 유지한다. 입구/출구 번호 대신 양방향 연결 표식을 표시하고, 기본 화면에는 포트 선택을 요구하지 않는다. 여러 유효 연결이 있으면 추천 경로를 먼저 보여주되 고급 연결 선택에서 사용자가 바꿀 수 있다. 역 외형 방향은 남기되 필수 두 번째 클릭은 선택 회전(R/회전 버튼)으로 대체하는 안을 권장한다. 설치 방향을 없애면서 연결 좌표나 구형 저장 방향을 조용히 바꾸지는 않는다.

#### 7.3.4 전체 철도 로직 계약

1. **물리 선로와 운행 방향 분리:** 선로 셀/연결은 양방향이다. 이동 방향은 현재 운행 단계의 속성이다. 네 방향 역 연결구에 영구 진입/진출 역할을 저장하지 않는다.
2. **연결과 역 설정 분리:** 역 ID·적재/하역은 `StopSettings`, 역 사이 연결은 양 끝 역 ID·연결구 ID·순서 있는 셀 경로를 가진 `RailConnection`으로 분리한다(명칭은 구현 시 확정). 역 하나에 고정 arrival/departure 한 쌍을 두는 모델은 새 노선에서 사용하지 않는다.
3. **왕복 운행 계획:** 사용자 목록 A,B는 A→B→A로, A,B,C는 A→B→C→B→A로 실행한다. 물리 AB/BC는 한 번씩만 저장하고 운행 단계가 정방향/역방향을 참조한다. 양 끝에서 같은 연결구로 돌아갈 수 있다. 중간 역 통과는 역 내부에서 두 연결구를 잇는 정차 동선으로 표현한다.
4. **역 등록과 방문 횟수 구분:** 편집 목록의 사용자 중복 역은 계속 거부해도 된다. 시스템이 생성한 돌아오는 방문은 정상이다. 연료 최대치는 서로 다른 등록 역 수×50이며 왕복 방문 횟수로 늘리지 않는다. 같은 타일 두 번 이동하더라도 건설 비용은 실제 신규 셀에 한 번만 청구한다.
5. **점유:** 초기에는 한 노선 한 기차와 다른 노선 간 선로 독점을 유지한다. 정상 왕복의 같은 타일 재사용은 허용하되 한 구간 자체의 반복/단절은 거부한다. 점유 등록·해제는 고유 셀 집합으로 처리한다. 이것이 복수 기차의 공용 선로까지 승인됐다는 뜻은 아니다.
6. **연결 관계:** 방향 없는 연결 마스크/간선을 명시해 나란한 셀의 의도하지 않은 합류를 막는다. 역은 네 개의 독립 연결구를 갖되 초기 일반 선로는 직선/모서리의 최대 두 연결만 지원한다. T자·십자 분기와 교행은 후속 범위다. 기존 수동 도구는 유효한 연결만 스냅하며 세 번째 연결이 필요하면 이유와 수정 위치를 표시한다. 외형도 동일 연결 정보를 사용한다.
7. **경로 확정:** 설치된 선로의 연결 탐색과 신규 설치 예정 경로의 계획을 별도 서비스로 둔다. 확정 경로는 고정한다. 단절/역 비활성 시 운행 중 임의 우회·순간이동·다른 기지 재귀속을 하지 않는다. 변경 시 명시적인 재검증/수동 재개를 유지한다.
8. **이동·회차 경계:** 현재 역 ID, 운행 단계 인덱스, 연결 방향, 구간 진행도를 저장한다. 같은 편성이 종착역에서 역방향 주행하며 회차선·별도 기관차를 요구하지 않는다. 이동 방향과 차체/포탑 방향을 구분해 차체의 즉시 180도 회전이나 역 사이 위치 튐을 피한다. 정차 중 방향/포탑 기준도 보존한다. 회차는 기준 첫 역으로 귀환했을 때 완료한다. 왕복/순환 모두 명시적 실행 단계로 계산하고 `stop` 하나를 경로 인덱스로 겸용하지 않는다.
9. **기존 물류·연료 유지:** 화물1칸/자원1종/용량1000, 역에서 하역 후 적재, 기지별 재고, 정차10초, 현행 이동/연료 계산·수동 보급/시작을 재사용한다. 매 실제 방문마다 역 설정을 한 번 적용하고, 종착역 방향 전환/정지·재개/재로드로 이중 처리하지 않는다. 연료는 실제 출발 구간에 한 번 차감하고 이미 지불한 구간 재개 시 재차 차감하지 않는다. 예상 왕복 시간/소모는 양방향 실행 단계를 합산한다.
10. **수정 예약·회수:** 실행 중 편집 예약은 기존 첫 역으로 돌아온 안전 경계에서 전체 재검증 후 원자적으로 교체한다. 왕복 방향과 예약 경로/노선 모드도 포함한다. 현행 DEC-10 의미는 유지하며 새 의미로 자동 확대하지 않는다. 사용 중 선로/역 회수 보호, 실패 시 구노선·화물·연료·점유 보존을 유지한다.
11. **방어·오류:** 이동형 무기의 위치/회전/공격 원점은 새 이동 표현을 사용한다. 연료 대기·정지 요청·오류 복구·역/기지 소실이 양방향 모두 동작해야 한다. 기차 피해/수리·추가 편성·자동 보급은 이번 재구성에 자동 추가하지 않는다(DEC-09).

공유 역은 공용 선로와 구분한다. 서로 다른 연결구의 독립 노선이 한 역을 사용할 때 재고 처리는 각 실제 방문에서 원자적으로 적용한다. 역 내부의 열차 겹침을 방지할 정차 슬롯/진입 대기 정책은 RX-01에서 구체화하고 RX-02에서 다중 노선 동시 도착을 확인한다. 이 정책 때문에 같은 선로 왕복에 수동 신호나 추가 회차선을 요구하지 않는다. 목적 기지 저장 용량이 부족하면 실제 수용량만 하역하고 남은 화물은 보존한다.

#### 7.3.5 연결·노선 편집의 목표 흐름

1. 역 설치: 위치 미리보기에서 점유·가동 기지와 네 연결 위치를 확인하고 예약한다. 회전은 선택 조작으로 제공한다. 확정 결제 규칙은 기존 건설과 동일하다.
2. 선로 연결: 역 상세의 `선로 연결`→목적 역 선택. 도구가 설치 가능한 연결구 쌍과 경로를 추천한다. 맵에는 예정 셀/연결 방향, 패널에는 신규 선로 수·기존 선로 수·소속 지불 기지·비용·왕복 길이를 표시한다.
3. 정밀 보정: 연결구 고정·수동 굴곡/경유점 조정이 가능하다. 4방향 격자의 단순 직선/굴곡 후보부터 검사하고 장애물 우회는 제한된 경로 탐색으로 보완한다. 건물/물/산 등 현행 불가 지형·맵 경계·다른 노선 점유·의도하지 않은 인접 연결은 통과하지 않는다. 기존 건물 자동 철거는 하지 않는다.
4. 건설 확정: 미리보기는 예약이며 실제 건설/결제가 아니다. 현재 `WorldEditSession`의 Quote·예약 기지 유지·전체 재검사·원자적 결제를 재사용한다. 사용 가능한 미점유 기존 선로는 경로 연결만 수행하고 중복 청구하지 않는다. 부족/충돌/기지 소실/도중 콘텐츠 변경 시 전체 실패하며 부분 설치/부분 결제를 남기지 않는다.
5. 노선 생성: 역 상세의 `왕복 노선 만들기`→연결된 목적 역 선택→필요하면 중간 역 추가. 연결된 역만 추천하되 선택 불가 역에는 사유를 표시한다. 기본 포트 버튼·`순환 연결`·별도 복귀 선로 요구를 제거하고 연결 검증은 자동 갱신한다.
6. 운송 설정: 자원 선택→각 역의 적재/하역 수량 입력. 기본 예시는 출발 역 ‘보내기’/목적 역 ‘받기’로 보여주되 숫자 목표량과 하역 우선 규칙은 유지한다. 양방향 방문에서 같은 역 설정이 적용됨을 안내한다. 임의의 새 ‘가득 찰 때까지 대기’ 규칙은 추가하지 않는다.
7. 확인·시작: `A↔B` 또는 `A→B→C→B→A`, 물리 선로 수와 왕복 이동량, 시간·연료·화물·역 상태를 확인하고 노선을 확정한다. 기차는 정지 상태로 생성하고 석탄 수동 보급→운행 시작으로 이어진다.
8. 운행·복구: 상세 카드에서 현재/다음 역, 왕복 진행 방향, 화물/연료, 정지 요청과 오류 이유를 읽는다. 오류 선택 시 해당 역/구간으로 이동하며 선택된 월드 역을 패널이 가리지 않도록 카메라 여백을 반영한다.

500×500 맵에서 경로 탐색은 역/목적지/경유점/지형·점유 버전이 변경됐을 때만 갱신한다. 제한된 탐색량·취소 가능한 요청을 두고 매 프레임 전체 맵을 재탐색하지 않는다. 제한에 도달하면 ‘경로를 찾을 수 없음’과 ‘탐색 제한/계획 중’을 구분한다. 후보 비용은 신규 셀 수를 우선하고 굴곡/길이를 보조 기준으로 삼아 동일 입력에 결정적인 결과를 내도록 한다. 탐색 상한과 지연 목표는 RX-03 실측 후 확정한다.

#### 7.3.6 실제 스프라이트 UI 제작 범위

기존 `Shared/UI/ReferenceHUD`의 패널/카드/선택 상태와 자원 아이콘을 재사용한다. 파일명 기준으로 철도 전용 열차/역/선로/연결 아이콘 묶음은 확인되지 않았다. `railgun`/`rail_aa`는 방어 건물 아이콘이며 열차/역 UI를 대신하지 않는다. **‘스프라이트 UI’는 배경 그림 한 장을 붙이는 방식이 아니라 실제 Image·Button·TMP·InputField·ScrollRect로 조작 가능한 저장 Canvas**를 뜻한다.

| 화면/요소 | 표시 내용·주요 행동 | 필요한 자산/상태 |
|---|---|---|
| 철도 도구 진입 | 역 설치·선로 연결·노선 관리, 도구 해제 | 역/선로/연결/노선 아이콘, 선택·비활성 상태 |
| 역 문맥 카드 | 기지·역 이름·가동 상태·연결된 역·노선, 연결/신규 노선 진입 | 역 썸네일, 양방향 연결 표식, 가동/비가동 배지 |
| 연결 보조 패널 | 목적 역·경로 보정·신규/기존 셀·견적/부족·확정/취소 | 경로 미리보기 키, 정상/오류 연결구 스프라이트 |
| 노선 목록/편집 | 왕복 노선 카드, 역 순서·중간 방문·수량, 추가/제거/순서 변경 | 열차/노선 카드, 역 행, 위/아래·추가·삭제 아이콘 |
| 운송·기차 상세 | 자원·적재/하역·현재/다음 역·석탄·화물·수동 보급·운행/정지·방어 | 기존 자원 아이콘, 화물/연료 게이지, 재생·정지·보급·방어 아이콘 |
| 확인/폐기/오류 | 왕복 요약, 생성 후 정지 안내, 변경 유지/폐기, 오류 위치/복구 | 공통 9-slice 패널·모달·버튼 상태, 경고/오류/연료대기 배지 |
| 지도 연결 표식 | 네 방향 양방향 연결구·추천 연결·현재 왕복 방향·선택 구간 | 연결 링·양방향 화살표·구간 화살표·오류 표식. 월드 선로 메시와 HUD 스프라이트의 역할 구분 |
| 개발용 제어 | 자원 무한·낮밤·검증 출력 | Editor/Development 전용 접이식 패널. 제품 운송 설정과 구분 |

공통 자산 계약: 금속 패널/청록 선택/주황 경고의 기존 방향을 유지하고, 철도 아이콘은 동일 팔레트·선 굵기로 새로 제작한다. 재사용 패널은 9-slice 테두리를 설정한다. 버튼은 normal/hover/pressed/selected/disabled/focus 표현을 갖고 아이콘과 짧은 텍스트를 함께 쓴다. 이름·수량·비용은 TMP/입력 필드로 남겨 그림에 굽지 않는다. 제작 원본과 내보낸 PNG, SpriteAtlas, 실제 프리팹 참조를 분리 관리한다. 다른 게임의 이미지를 제품 자산으로 복사하지 않는다.

스프라이트 제작은 **RX-04에서 화면 크기/아이콘 슬롯을 먼저 정한 뒤** 진행한다. 아이콘의 논리 슬롯은 24/32/48px 계열을 초안으로 삼고, 원본 해상도·PPU·필터링·Atlas 패딩은 해당 슬롯과 실제 1280/1920 렌더를 보고 확정한다. 현재 스타일에 맞춰 부드러운 축소를 우선 검토하며 프로젝트 전체를 임의로 픽셀 아트 필터로 바꾸지 않는다. 공통 버튼 프레임과 상태 색을 재사용해 버튼마다 여섯 PNG를 중복 제작하지 않는다.

화면 배치는 좌/우 도킹 패널 중 한쪽을 철도 작업에 할당하고 중앙 맵을 남긴다. 철도 작업 중 중복 건물 상세는 같은 문맥 카드로 전환하며 미니맵·하단 건설 바·선택 역을 덮지 않는다. 목록은 저장된 행 풀/페이지 또는 가상 스크롤로 표시하고 선택은 역/노선 ID로 유지한다. 사용자 조작의 클릭 영역과 장식 스프라이트의 raycast를 구분한다. 수량 필드는 포커스 중 월드 단축키를 막고 Tab/Enter/Esc 경로를 정의한다. Esc는 경로 지정 취소→초안 유지/폐기→패널 닫기의 순서이며 무단 폐기하지 않는다. 오류·연료 부족은 색 외에도 아이콘/문장으로 전달한다.

`StartRegionSandbox`와 `OpenWorldSandbox`에 공통 프리팹을 연결하고 패널·버튼·목록 행·프리뷰·콜백·재료/스프라이트 참조를 Play 전 저장한다. 런타임은 값/표시/위치와 게임 객체를 갱신한다. 정적 UI를 `OnGUI`, UXML, 런타임 GameObject 생성으로 우회하지 않는다. 기존 UI를 통째로 삭제하기보다 공통 컴포넌트로 단계적으로 교체해 명령 조건·저장 참조를 보존한다.

#### 7.3.7 저장·호환성·구조 변경 경계

- 새 모델은 철도 스키마 버전, 노선 모드, 연결구/물리 경로, 실행 단계/역방향, 현재 역, 처리 완료/구간 연료 지불, 수정 예약을 함께 저장한다. 선로 연결 정보는 노선 미배정 셀까지 포함해 선로 건물 ID/셀과 대조할 수 있어야 한다. **필드 하나로 방향만 추가하는 수정은 부족하다.** 검사·복원·점유·표시를 함께 이행한다.
- 구형 저장에서 모드가 누락되면 기존 순환으로 읽도록 명시적 버전 분기를 둔다(예: `LegacyCycle=0`, `Shuttle=1`). 신규 생성의 기본은 왕복이다. 구형 모드 누락을 왕복으로 해석해 이동 중 위치/노선을 변형하지 않는다.
- 기존 순환 노선은 레거시 모드로 위치·기차 ID·화물·연료·무기·예약을 보존한다. 사용자 명시 전환은 정차/검증 상태에서 수행하고 선로 자동 철거나 환급을 하지 않는다. 구형 노선의 존재 때문에 신규 왕복에 폐회로 버튼을 다시 강제하지 않는다.
- 단일 맵 저장 v3를 적용했고 v1/v2 읽기와 기존 v1 재고 이관을 유지한다(§7.3.9). 구버전 Payload를 먼저 해당 구버전 규칙으로 검증하고 안전하게 새 모델로 변환한다. 콘텐츠 구성 지문 변경으로 정상 구저장이 차단되지 않도록 명시적 호환 구성 판단을 함께 설계한다. 모든 과거 콘텐츠 지문을 무조건 수용하지 않는다.
- 구형 연결 마스크가 없는 선로는 저장된 확정 경로의 연속 셀/연결구에서 관계를 복원한다. 노선 미배정 셀의 관계는 단순한 경우만 이행하고 모호한 분기는 수정 필요로 표시한다. 모든 인접 셀을 자동 접속해 새 노선에 오연결을 만들지 않는다.
- 코어 경계는 물리 연결 조회, 경로 계획/검증, 노선 초안/명령, 운행/물류 상태, HUD 표시로 나눈다. 기존 `IRailInventory`, 방어·건설 구매·저장 계약은 재사용한다. HUD가 직접 점유/연료/재고를 변경하지 않도록 한다. 검증된 전체 경제·전투 구조를 이 작업을 이유로 다시 만들지 않는다.

핵심 인수 시나리오:

- **왕복:** 역2개·한 연결선만으로 A→B→A를 최소3회 반복한다. 같은 연결구로 귀환하며 별도 복귀 선로/입출구 지정은 없다. 철30의 실제 적재/하역과 기지별 재고 합계, 출발별 연료 감소가 정상이다.
- **중간 역:** A,B,C 등록으로 A→B→C→B→A 실행. B의 실제 두 방문을 각각 한 번 처리하고, C의 방향 전환을 추가 방문/추가 급탄 용량으로 계산하지 않는다. 시간은 실제 양방향 이동+정차 합과 일치한다.
- **연결 보조:** 네 방향과 회전 역, 장애물 우회/연결 불가, 가까운 평행 선로, 기지 소실, 부족 자원, 기존 선로 재사용을 확인한다. 미리보기와 확정 경로/비용이 같고 취소는 실제 상태를 바꾸지 않는다.
- **수정·경계:** 왕복 도중 정지 요청→다음 역 정차→재개, 석탄 부족 대기, 역 비활성/소실과 복구, 회수 보호, 예약 노선 선로를 다른 노선이 선점한 경우 전체 교체 실패/구노선 보존을 확인한다.
- **저장:** 정방향/역방향 이동·종착 정차·FuelWait·RouteError·예약/무기 상태가 복원된다. 구형 v2 순환, 기존 v1 이관, 손상/미지원 저장 거부도 확인한다. 실제 저장 안전 조건을 우회하지 않고 코어 Snapshot 검증과 안전 시점 Play 저장을 구분한다.
- **화면:** 기본 2역 생성에서 필수 수동 포트 선택/순환 닫기 조작은 각각0회다. 연결3행동(시작 역/목적 역/확정)을 기본 목표로 삼되 수량 설정·급탄/시작은 별도다. 전체 조작 수/잘못된 클릭/되돌리기는 RX-07에서 실제 측정하고 현재 달성 수치로 기록하지 않는다. 아이콘만 교체해 완료 처리하지 않는다.

완료 증거는 `Docs/Validation`에 단계별 코어 검사·실제 Play·저장 왕복·화면/포인터 결과로 남기고 이 대장에 링크한다. 원본은 `Docs/Source/Attachments`에서 보존하고, 연구·작업 계획의 단일 갱신 지점은 이 절이다. **바로 다음 작업은 RX-01/02의 공유 역 정차 슬롯·진입 대기와 역방향 방어/예약 실기 잔여를 마무리하는 것이다. 그 뒤 RX-03 연결 정보·건설 보조→RX-04 화면 계약→RX-05/06 스프라이트·두 씬 연결→RX-07 실제 한 회차 순으로 진행한다. 통과한 단일 선로 왕복 코어와 저장 이행은 다시 구현하지 않는다.**
