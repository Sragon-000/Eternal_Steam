## 유지 주기와 범위

주 1회 공식 상점·뉴스를 확인하는 주기를 기본으로 한다. 새 시스템 설명, 데모·출시, 밸런스·UI 변경 등 분석에 영향을 주는 근거가 있으면 관련 절과 검증대장을 갱신한다. 내용이 같으면 본문 버전을 올리지 않고 점검 기록만 남긴다. 자동 점검의 실제 활성 상태는 Codex 자동화 설정을 기준으로 한다.

2026-09-29 이 대화에 연결된 자동화 **BELTFED 역기획서 주간 갱신**(ID: `beltfed`)을 활성화했다. 매주 화요일 오전 10시(사용자 시간대 Asia/Seoul) 점검 일정이며, 등록 성공은 첫 예약 실행 완료를 뜻하지 않는다.

변화가 없거나 조치할 내용이 없으면 알림을 생략한다. 의미 있는 변경, 문서 갱신 완료, 점검 실패 또는 사용자 조치가 필요할 때만 알린다. 자동 점검에서 구매·설치·커뮤니티 메시지·게임 코드 변경을 수행하지 않는다.

## 한 번의 갱신 절차

1. 이 문서와 검증대장을 읽고 마지막 확인 날짜·미확정 항목을 확인한다.
2. 공식 상점, 개발 소식, 개발자 FAQ, 프레스킷, 실제 공식 채널의 변경을 조회한다. 프레스킷에 일부 공개로 연결된 영상도 확인하되 동일 장면 재사용은 중복 증거로 세지 않는다.
3. 출처 날짜·대상 빌드·직접 확인 범위를 기록한다. 조회 실패는 내용 변화로 간주하지 않는다.
4. 영향을 받는 사실 카드·O/U ID를 연결하고 분석의 전제가 바뀌었는지 확인한다.
5. 본문을 수정하되 과거 빌드 차이와 취소된 가설을 변경 이력에 남긴다.
6. 내부 링크, 사실/해석 구분, 미확인 수치의 임의 채움 여부를 점검한다. 영상 표본·전체 시청·실기 관찰을 구분하고, 본문과 공개자료 부록의 수치·관찰 ID를 함께 맞춘다.
7. 버전·변경 이력·점검 기록을 함께 갱신한다. 실제 변경이 있을 때만 간결하게 알린다.

게임 코드·씬·에셋의 변경 요청이 뒤따르면 별도 작업으로 처리한다. 레퍼런스 업데이트로 프로젝트 기능이 자동 채택되었다고 기록하지 않는다.
