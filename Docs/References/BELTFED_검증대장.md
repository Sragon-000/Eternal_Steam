P0도 근거 없이 값을 넣는 우선순위가 아니다. 공개 빌드가 없으면 대기를 유지한다. 실제 플레이를 위해 별도 구매·설치가 필요하면 그 조건을 먼저 확인한다.

새 관찰은 아래 양식을 복제하고 OBS-001부터 번호를 붙인다. 현재 플레이 관찰은 **0건**이다.

```text
관찰 ID:
연결 U ID:
관찰일 / 플레이어:
제품: 데모 / 정식 / 기타
빌드 / 플랫폼 / 언어:
행성 / 난이도 / 시드(노출 시):
영구 해금 / 코어 / 모듈 / 카드:
배속 / 게임 시간 / 실제 시간:
사전 상태:
수행 행동:
UI 표기:
실제 결과:
반복 횟수 / 차이:
증거 파일 또는 URL / 영상 시간코드:
확정 가능한 주장:
여전히 모르는 것:
수정할 본문 절:
```

## 5. 영상 관찰 양식

장면이 편집되어 있다면 연속 플레이로 취급하지 않는다. 컷 전후 재고 차이를 생산률로 계산하지 않는다.

구체적인 시간코드는 [공개자료·영상 분석 부록 2–4절](BELTFED_공개자료_영상분석.md)에 모았다. 새 기록은 아래 열을 유지한다.

| 영상 ID·시점 | 직접 보인 행동·화면 | 분석 가설 | 검증할 U ID | 확인 수준 |
|---|---|---|---|---|
| 예시: V03 ~1:07 | Salvager 생산·전력 표시 | 품목당 전력과 생산률 관계 | U01·U04 | UI 표시 관찰, 실측 아님 |

## 6. 충돌 해결 규칙

동일 빌드의 반복 관찰과 공식 패치 설명을 우선 검토하고, 서로 다른 빌드의 결과는 병기한다. 최신 날짜만으로 모든 이전 관찰을 무효화하지 않는다. 공식 설명과 실제 동작이 다르면 ‘설명/관찰 불일치’로 남긴다. 제3자 기사 하나로 F 등급을 부여하지 않는다.

미확인 값은 `미확인`, 접근 실패는 `조회 실패`, 관찰 부재는 `미관찰`로 구분한다. 새 증거가 생기면 U ID를 삭제하지 않고 해결일과 관찰 ID를 추가한다.

### 이번 판의 출처 충돌

Steam의 배급사와 프레스킷의 TBC, 출시 연도와 봄 목표, 프레스킷의 영상 공개 예정 문구와 실제 V02 공개, MG/HMG 표기는 덮어쓰지 않고 [부록 10절](BELTFED_공개자료_영상분석.md)에 병기했다. ‘미니맵 시험 계획’, ‘캠페인 목표’, ‘오디오 미들웨어 도입 계획’은 이미 제공되는 기능으로 승격하지 않는다.
