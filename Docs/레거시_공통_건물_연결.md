# 기존 데모의 공통 건물 연결

기존 데모의 포탑 설치·점유·제거를 `BuildingWorld`와 `PlacementSession`에 연결했다. 두 번 클릭하는 기존 조작과 4종 포탑 공격은 유지한다. 새로운 일괄 배치·회수 UI를 기존 데모에 추가한 것은 아니다.

## 책임

| 구현 | 역할 |
|---|---|
| HordeBuildingPlacement | 기존 설치 시점·종류별 한도·맵 영역을 공통 배치 작업에 연결 |
| BuildingWorld / BuildGrid | 실제 건물 식별자·점유·수명·생성 실패 롤백 |
| HordeTowerFactory | 비활성 상태의 포탑 외형 생성, 확정 후 기존 포탑 목록에 등록, 제거 시 외형·목록 정리 |
| HordeTower | 기존 연사·공격 효과 상태와 표현 참조, 대응하는 BuildingInstance 보유 |
| HordeSimulation | 호환 API 제공, 설치 가능 시점·진행 한도 전달, 기존 전투 루프 실행 |

어댑터와 팩터리는 `Code/LegacyDemo/Buildings`의 `EternalSteam.LegacyBuildings` 어셈블리에 있다. Runtime과 레거시 정의·배치·표현만 참조하며 HordeSimulation 구현을 참조하지 않는다. 설치 가능 여부·수량·한도·현재 맵은 구성 지점에서 전달한다. 공통 Runtime에는 Horde 타입을 추가하지 않았다.

## 격자 호환

`BuildGrid`에 선택적 `Origin`을 추가했다. 기본값은 `(0,0,0)`이라 기존 검증 씬의 좌표는 그대로다. 데모 어댑터는 셀 크기 2와 원점 `(-1,0,-1)`을 사용해 기존 짝수 좌표 중심과 일치시킨다. 맵별 설치 영역은 기존 전체 footprint 판정을 통해 설치 가능 셀로 변환한다.

기존 초기 배치와 각 포탑의 중심·방향·사거리·외형 높이·크기를 보존한다. 격자 점유 중복 검사는 공통 Grid가 담당하므로 기존 포탑 목록을 순회해 위치를 비교하던 코드는 제거했다.

## 생성·수명 계약

1. 기존 입력은 위치와 방향·사거리를 전달한다.
2. 어댑터가 공통 PlacementSession에 단일 요청을 예약한다.
3. 설치 시점과 전체·종류별 한도를 확정 직전에 다시 검사한다.
4. 팩터리가 비활성 템플릿을 복제하고 기존 절차적 포탑 외형을 생성한다.
5. 공통 월드의 등록·점유 성공 후 외형을 활성화하고 기존 전투 목록에 넣는다.
6. 실패 시 월드·포탑 목록·외형을 정리한다. 이 단일 클릭 호환 API는 실패한 요청의 숨은 예약도 해제한다. 배치 제어기의 방향 편집 상태는 남아 다시 확정할 수 있다.

공통 월드에서 건물을 제거하면 기존 포탑 목록과 외형도 제거된다. `ClearTowers`는 `BuildingWorld.Clear`를 호출한다. 재도전·다음 단계에서는 월드와 기존 포탑 인스턴스를 유지하고 전투 상태만 초기화한다. 씬 종료 때 월드, 절차적 템플릿, 임시 정의를 정리한다.

사거리 같은 요청별 외형 설정은 요청 ID에 연결해 보관하고 완료·실패 후 해제한다. 공유 건물 정의의 값을 설치 요청마다 변경하지 않는다.

## 정의와 남은 범위

기존 포탑은 명시적 ID `legacy.machine-gun`, `legacy.cannon`, `legacy.frost`, `legacy.arrow`로 변환한다. 정의는 기존 절차적 생성과 호환되는 실행 중 에셋이며 빈 Modules 목록을 가진다. 실제 공격은 여전히 기존 HordeTower 상태와 전투 루프가 담당한다. 새 공통 공격 모듈로 바꾸어 타겟·연사 규칙을 변경하지 않았다.

이번 단계는 ID 기반 영구 저장 이전이 아니다. 기존 enum 순서·저장 키·보상·설치 한도는 유지한다. 콘텐츠 카탈로그와 UI의 고정 개수 제거, 전투 실행·적 관리·적 렌더링 분리, 저장 마이그레이션은 후속이다.
