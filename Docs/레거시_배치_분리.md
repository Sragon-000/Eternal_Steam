# 레거시 배치·입력·표현 분리

기존 `HordeSimulation`의 외부 API와 직렬화 필드는 유지하면서 입력·카메라·배치 편집 상태·미리보기 렌더링을 분리했다. 기존 씬의 컴포넌트를 교체하거나 다시 생성할 필요가 없다.

## 개발 책임과 의존성

| 구현 | 책임 | 의존성 |
|---|---|---|
| HordePlacementController | 위치 선택·방향/거리 편집·확정·취소·입력 차단 판단 | 배치 가능 검사와 설치 명령을 생성자 함수로 전달받음 |
| HordePlacementInput | 월드 포인터 위치와 확정·취소 입력값 | 입력 장치 없음 |
| HordePointerInput | 마우스·키보드를 읽고 카메라 광선을 월드 좌표로 변환 | Input System, Camera |
| HordePlacementView | 미리보기·부채꼴·방향 화살표·선택 격자 표시와 정리 | 제어기의 읽기용 상태와 머티리얼 |
| HordeCameraFraming | 전투 뷰포트와 맵에 맞는 카메라 크기 | Camera, 맵 정의 |
| HordeVisualPrimitives | 기존 큐브·선 생성 방식 | Unity 표현 API |
| HordeSimulation | 기존 배치 규칙과 설치 명령 제공, 각 구현 연결, 전투 실행 | 공개 메서드 유지 |

`EternalSteam.LegacyDefinitions`는 기존 맵·포탑 정의를 담는다. `LegacyDeployment`는 Definitions만 참조하며 Simulation·Input System을 참조하지 않는다. `LegacyPresentation`은 Definitions·Deployment·Input System을 참조하며 Simulation을 참조하지 않는다. `LegacyDemo`가 이 구현들을 연결한다. 역방향 의존성은 독립 테스트로 검사한다.

새 폴더는 `Code/LegacyDemo/Definitions`, `Deployment`, `Presentation`이다. 기존 맵·포탑 정의 파일 이동 시 `.meta`를 보존했으며 enum 순서와 수치는 변경하지 않았다.

## 호환 동작

- 위치 클릭 → 방향과 사거리 지정 → 클릭 확정.
- 우클릭/Esc 취소, 잘못된 확정 요청은 편집 상태 유지.
- HUD 위와 전투 중에는 포인터 설치 차단.
- 기존 격자 스냅·점유 검사·포탑별 설치 한도 유지.
- 사거리 6~26과 사거리별 퍼짐 계산 유지.
- 초기 포탑, 재도전 시 설치 유지, 카메라 뷰포트 API 유지.

HordeSimulation에서 Mouse·Keyboard·ScreenPointToRay 직접 사용을 제거했다. 배치 제어기는 장치 입력을 직접 읽지 않으므로 합성 입력으로 검사하거나 다른 입력 어댑터에 연결할 수 있다.

## 검증과 남은 이전

`EternalSteam.LegacyDeploymentTests`에 독립 EditMode 테스트 8개를 두었다. `Tools/VerifyLegacyDeployment.cs`는 임시 Play 세션에서 기존 공개 메서드를 통해 3개 맵의 설치 흐름을 검사한다. 별도 저장 키를 사용해 사용자 진행을 보존한다. 최신 결과는 [배치 분리 검증](Validation/레거시_배치_분리_검증.md)에 기록한다.

이번 단계는 공통 BuildingWorld로 기존 배치를 이전한 것이 아니다. 기존 배치 규칙과 포탑 생성은 호환 어댑터 역할로 HordeSimulation에 남아 있다. 적 배열·공간 인덱스·공격 실행·인스턴싱도 그대로이며, 해당 메서드 12개의 본문이 변경 전과 일치함을 확인했다.

다음 단계는 기존 배치 규칙·포탑 생성과 공통 건물 월드의 연결, 이후 전투 상태·공격 실행·적 렌더링의 분리다. 전투 루프를 바꾸기 전 동일 배치·시드의 성능 기준을 확보한다.

## 후속 연결 완료

이후 기존 배치 규칙과 포탑 생성을 공통 BuildingWorld에 연결했다. 현재 동작은 [공통 건물 연결](레거시_공통_건물_연결.md)을 따른다. 전투·적 관리·적 렌더링의 분리는 다음 단계다.
