# 단일 맵 안전 저장·복원

2026-09-24 적용. 대상은 원본 StartRegionSandbox. 게임 빌드는 수행하지 않는다.

## 사용

기존 접이식 테스트 패널에 **안전 저장 / 마지막 저장 이어하기 / 새 게임**을 추가했다. 정상 저장이 있으면 시작할 때 자동 복원하고 일시정지한다. `계속 진행`으로 재개한다. 새 게임은 패널의 확인 후 이전 기록을 조사용 archive로 보관하고 새 진행 ID를 발급한다. 상단·하단 패널 접기, 고정 메인 모델, 정면 11×11, 45° 맵은 유지한다.

낮이고 적·보스·투사체·연쇄 피해·개발자 소환 대기·편집/예약이 없을 때 저장한다. 일시정지만으로 전투 중 저장이 허용되지 않는다. 저장 불가 사유와 마지막 저장 시각을 표시한다. 초기 상태, 안전한 배치/회수/강화 확정, 안전한 오브 제작 직후 저장하며, 상태가 변경된 경우 30초 간격으로 안전 여부를 확인한다. 안전하지 않으면 다음 안전 시점까지 보류한다. 종료 시 전투를 지우거나 억지로 저장하지 않는다. 오프라인 생산/시간 진행은 없다.

메인 파괴는 즉시 별도 패배 파일에 기록한다. 실패 시 표시하고 1초 간격으로 재시도하며, 기록 성공 전 새 게임 전환을 보류한다. 패배한 진행의 정상 파일과 백업 모두 이어하기가 차단된다. 새 게임만 가능하다.

## 모듈 경계

- `Code/Persistence/SavedState.cs`: 명시적으로 `[Saved]`를 붙인 모듈 필드의 수집·검증·복원. 파일이나 콘텐츠별 분기를 공통 건물에 넣지 않는다. 리플렉션은 저장/복원 경계에서만 사용한다. 부동소수점은 왕복 가능한 R 형식이다.
- `ISaveEligibility`: 저장 허용 여부와 이유. `ISaveStore` / `JsonSaveStore`: 파일, 버전, 무결성, 백업, 패배 기록.
- `Tests/OpenWorld/Runtime/SingleMapSnapshot.cs`: 캠페인/맵/건물 DTO와 구성 지문.
- `SingleMapPersistence`: 오픈월드 조합의 어댑터 및 새 게임/복원/패배 연결. 기존 4종 포탑은 명시적 고정 콘텐츠 ID로 매핑한다.
- `Code/Economy/UpgradePurchase.cs`: 강화 명령과 주입 가능한 비용 정책. `ResourceBank.TryPurchase`는 전체 비용과 조건을 검사한 뒤 성공한 강화만 전체 차감한다.

건물 PersistentId와 기지 BaseId는 런타임 슬롯 ID와 별도다. 상실된 기지 소속도 기록해 영역 상실 상태를 보존한다. 공유 레벨, 자원 재고/용량, 기지 전력 잔고/미정산량/연결, 모듈별 체력·레벨·생산/공격/추출 타이머, 포탑 회전, 시간, 야간 예산·지급일·난수, 보스/오브 상태를 보존한다. 적·투사체·편집 상태는 저장하지 않는다.

전체 데이터를 먼저 검증하고 입력/시뮬레이션이 정지된 초기화 과정에서 복원한다. 모듈 복원은 강화·피해 명령을 호출하지 않는다. 배치 방향 초기화가 끝난 뒤 실행 상태를 다시 적용해 조준 방향과 공격 상태가 리셋되지 않게 한다. 최종 자원 용량은 저장값을 적용해 저장 건물 활성화에 따른 이중 증가를 방지한다. 실패하면 생성한 건물/토대를 정리하고 로드를 차단한다.

## 파일 정책

전용 경로: `Application.persistentDataPath/EternalSteam/SingleMap`.

- `current.json`: 버전 1, 진행 ID, JSON payload와 SHA-256 무결성 값.
- `previous.json`: 직전 정상 저장.
- `failures/<진행 ID>.failed`: 패배 기록. 새 게임에서도 보존.
- `archive/<시각-ID>/`: 새 게임 이전 저장 조사용 보관.
- `new-game.pending`: 새 게임 전환 도중 중단됐을 때 이전 슬롯 재사용 방지.

임시 파일에 작성·Flush·검증 후 교체한다. 현재 파일 손상 시 백업을 확인하고 복구 사실을 표시한다. 버전/콘텐츠 구성 불일치, 중복 ID, 점유 겹침, 잘못된 참조는 자동으로 부분 적용하거나 덮어쓰지 않는다. 구성 변경은 현재 버전에서 마이그레이션하지 않고 이어하기를 차단한다. 체크섬은 손상 감지이며 보안/치트 방지 서명은 아니다.

기존 데모의 PlayerPrefs 키 `EternalSteam.Prototype.Progress.v1`은 읽거나 변경하지 않는다. 테스트는 Editor 전용 환경 변수 `ETERNAL_STEAM_SAVE_TEST_ROOT`로 `/tmp`의 별도 경로를 사용한다.

## 강화

현재 정책은 `VerificationFreeUpgrade`이며 UI에 **검증용 무료**로 명시한다. 최종 비용표와 실제 재고 차감은 적용하지 않았다. `UpgradeCostTable`은 콘텐츠 ID, 목표 레벨, 자원 목록을 정의할 수 있으며 누락/중복 비용은 오류다. 향후 비용 정책만 주입해 연결한다. 복원에서는 결제나 강화 보상을 실행하지 않는다.
