> 클리어 판정: 처치한 적과 출구를 통과한 적을 합쳐 처리 수로 계산합니다. 모든 적이 처리되고 체력이 남아 있으면 클리어입니다. 체력 0은 패배가 우선합니다. 통과한 적은 기존처럼 체력을 1씩 깎습니다.

> 최신 변경: 적 수는 1,500 / 3,000 / 5,000마리입니다. 포탑은 종류별 기본 4개(기본 배치 포함), 로비에서 부품으로 1개씩 늘려 최대 16개까지 설치할 수 있습니다. 첫 강화 비용 100, 같은 종류를 강화할 때마다 50씩 증가합니다. 기존 부품·클리어 기록은 유지되며 설치 한도도 저장됩니다. 철거하면 설치 가능 수가 돌아옵니다. 공격력·기지 강화는 아직 없습니다. 검증 도구: `Tools/VerifyCapacityUpgrade.cs`.

## 로비·재화 업데이트

시작 화면은 로비입니다. 맵과 Stage 1을 선택하고 설치 후 Start stage를 누르세요. Arrow / Pierce는 관통 화살이며, 적 체력 20에 총 10 / 대포·화살 20 피해를 적용합니다. 클리어 시 부품 지급과 다음 스테이지 해금을 자동 저장합니다. 실패·중도 이탈은 무보상입니다. 로비의 기지 Lv.1은 표시만 하며 강화는 아직 없습니다. 자세한 현재 범위와 검증 방법은 README의 로비·재화 프로토타입 항목을 참고하세요. 아래의 이전 검증 도구 중 즉사·무한 생성·로비 없는 흐름을 전제한 것은 현재 버전과 호환되지 않습니다.

# 도형 기반 물량 처리 데모

## 실행

복제한 저장소의 루트가 Unity 프로젝트입니다. Unity 6000.3.14f1에서 `Assets/EternalSteam/Scene/Demo/`의 데모 씬을 열고 Play를 누르세요. 기본 포탑만 배치되고 적이 없는 설치 단계로 시작합니다.

## 조작

설치가 끝난 포탑은 준비 단계에도 종류별 색상의 부채꼴로 방향·사거리·퍼짐 범위를 표시합니다. 기본 배치와 새로 설치한 포탑 모두 표시되며, Retry stage로 돌아오면 다시 나타납니다. 첫 클릭 전의 마우스 미리보기는 포탑만 표시하는 방식을 유지합니다.

설치 단계에는 파란 배치 구역 위에 2×2유닛 그리드가 표시됩니다. 포탑은 기존보다 30% 확대했으며, 세 종류 모두 한 칸만 점유합니다. 빈 옆 칸에도 바로 설치할 수 있고 같은 칸에만 중복 설치가 제한됩니다. 칸 중심에 포탑이 맞춰지며, 선택 칸은 설치 가능 시 초록색, 겹침·구역 밖 등 설치 불가 시 빨간색입니다. Start stage를 누르면 전체 그리드가 숨겨지고 Retry stage로 설치 단계로 돌아오면 다시 표시됩니다. 전투 중 방향을 지정할 때도 그리드가 표시됩니다.

세 맵의 배치 후보 544칸을 실제 씬의 바닥 경계와 대조하여 그리드와 포탑 받침 전체가 지지되는지 검사했습니다. 포탑 밑면 높이도 각 배치 바닥의 윗면에 맞췄습니다. 바닥을 편집한 뒤에는 Edit 모드에서 `Tools/VerifyBuildSurfaces.cs`의 `VerifyBuildSurfaces.Main`을 Unity CLI로 실행해 다시 검사할 수 있습니다.

Game 뷰를 작은 창에서 볼 때는 해상도를 **Free Aspect**, Scale을 **1×**로 설정하세요. Retina 디스플레이에서는 **Low Resolution Aspect Ratios**를 끄면 선명하게 표시됩니다. 1920×1080 같은 고정 해상도가 창보다 크면 1×에서 화면 일부가 잘릴 수 있으므로 Free Aspect 또는 Fit 배율을 사용합니다. HUD 버튼과 안내문은 화면 폭에 맞춰 줄바꿈됩니다.

- 첫 클릭 전에는 그리드 위 마우스 위치에 포탑 미리보기만 표시됩니다. 왼쪽 클릭으로 위치를 고정하면 선택 칸·방향 화살표·부채꼴 사격 범위가 나타납니다. 마우스 방향으로 조준 방향을, 포탑과 마우스 사이 거리로 사거리를 정하고 다시 클릭하면 설치가 확정됩니다.
- 우클릭 또는 Esc로 미확정 설치를 취소합니다. 첫 클릭만으로 포탑이 추가되지는 않습니다. 겹치는 위치나 구역 밖에는 설치할 수 없습니다.
- 배치를 마친 뒤 **Start stage**를 눌러 적 생성을 시작합니다. 이 버튼을 누르면 미확정 설치는 취소됩니다. 전투 중에도 추가 설치할 수 있습니다.
- `50/s`, `100/s`, `300/s`: 초당 적 생성 수를 변경합니다.
- `Pause spawns`: 새 적 생성을 일시 정지합니다. 기존 적과 포탑은 계속 움직입니다.
- `Retry stage`: 적과 카운터를 초기화하고 설치 단계로 돌아갑니다. 설치한 포탑은 유지하며, 다시 Start stage를 눌러야 적이 생성됩니다.
- `Clear turrets`: 설치한 포탑을 모두 제거합니다.

## 구현 범위

### 포탑 종류와 플레이어 체력

HUD의 포탑 버튼을 선택한 뒤 기존과 동일하게 위치 → 방향·거리 순서로 설치합니다. 종류를 바꾸면 미확정 설치는 취소됩니다. 이미 설치한 포탑의 종류는 바뀌지 않습니다. 기본 배치에도 세 종류가 섞여 있습니다.

| 종류 | 구분 | 역할 |
| --- | --- | --- |
| MG / Rapid | 청록색, 가는 총열 | 0.055초마다 단일 연사. 사선에서 가장 가까운 적 하나 처치 |
| Cannon / Blast | 주황색, 굵은 포신 | 0.7초마다 발사. 명중 지점 주변 반경 3유닛의 적을 처치 |
| Frost / Slow | 보라색, 넓은 방출구 | 0.18초마다 전방 부채꼴 전체에 관통 방사. 범위 안의 모든 적을 2.5초간 60% 감속. 직접 피해 없음 |

세 종류 모두 지정 방향·거리·퍼짐을 유지하며, 전투 중 적이 없어도 발사합니다. 포는 사선에 적이 없으면 최대 사거리 지점에 폭발 효과를 냅니다. 냉각 포탑은 첫 적에게 막히지 않고 설치 때 표시한 부채꼴 전체에 효과를 적용합니다. 앞쪽 적 뒤에 있는 적도 감속되며, 포탑 뒤쪽·부채꼴 바깥·사거리 밖에는 적용되지 않습니다. 보라색 부채꼴 선으로 실제 방사 범위를 표시합니다. 느려진 적은 파란색으로 표시되며, 범위 안에 있는 동안 감속 시간이 갱신됩니다.

플레이어 체력은 1,000이며 적 한 마리가 출구를 통과할 때마다 1씩 감소합니다. 체력이 0이면 생성·이동·발사·설치가 중단되고 HUD에 DEFEATED가 표시됩니다. **Retry stage**를 누르면 포탑 배치를 유지한 채 체력·적·카운터를 초기화하고 설치 단계로 돌아갑니다. 일반 **Retry stage**도 체력을 회복합니다. 맵 전환은 해당 맵의 기본 배치와 최대 체력으로 시작합니다.

캡슐 적이 출발선에서 출구로 이동합니다. 포탑은 설치 방향을 유지하며 적을 따라 회전하지 않습니다. 사거리는 6~26유닛입니다. 가까이 설정할수록 탄이 넓게 퍼지고, 멀리 설정할수록 좁게 모입니다. 부채꼴 끝부분의 폭은 단거리에서 약 9.2유닛, 장거리에서 약 3.6유닛으로 줄어듭니다.

Start stage 이후에는 적 유무와 관계없이 기관총처럼 0.055초 간격으로 한 발씩 연사합니다. 매 발의 방향이 설정한 부채꼴 안에서 달라지며 노란 예광선은 설정한 사거리까지 뻗습니다. 한 발의 사선에 들어온 가장 가까운 적만 처치합니다. 여러 발을 동시에 발사하는 산탄 방식은 아닙니다. 설치 단계에서는 발사하지 않으며 Retry stage를 누르면 발사가 멈춥니다. Pause spawns는 적 생성만 멈추므로 포탑 연사는 계속됩니다.

## 맵

| 상단 버튼 | 씬 | 구성 |
| --- | --- | --- |
| 01 / Lane | HordeDemo | 54×26 통로, 기본 포탑 4개 |
| 02 / Wide front | HordeWideFront | 86×64 평원, 40 유닛 폭의 정면에서 진격, 기본 포탑 6개 |
| 03 / Pincer | HordePincer | 86×64 협공 전장, 위아래 두 출발선에서 우측으로 합류, 기본 포탑 6개 |

맵 전환 시 적·카운터·포탑 배치는 새로 시작하고 설치 단계로 돌아갑니다. 추가 맵의 기본 생성 속도는 초당 300마리이며 시작 버튼을 누르기 전에는 생성되지 않습니다. 세 씬 모두 빌드 씬 목록에 등록되어 있습니다.

동시 적 상한은 4,000마리, 포탑 상한은 64개입니다. 적은 고정 배열과 재사용 슬롯으로 관리하며, 공간 격자로 표적을 찾고 인스턴싱으로 렌더링합니다. 적끼리 충돌하거나 길을 찾지는 않습니다. 경제·강화는 이번 데모에 포함하지 않습니다.

HUD에서 현재 적 수, 처치 수, 통과 수, 포탑 수, 생성 속도, FPS를 확인할 수 있습니다. FPS는 에디터 창의 활성 상태와 장비에 영향을 받으므로 빌드 성능 측정값으로 해석하지 않습니다.

## 검증

`Tools/VerifyDirectionalHorde.cs`는 2단계 설치와 취소, 전방 최근접 공격, 후방·측면·사거리 밖 제외, 설치 방향 유지, 시작·초기화 상태와 세 맵의 이동 경로·상한을 검사합니다. `Tools/VerifyHordeHud.cs`는 생성 속도, 시작, 일시 정지와 초기화 버튼을 검사합니다. 마우스 입력을 통한 위치 선택·방향 확정도 확인했습니다.

검증 스크립트는 Play 중 Unity CLI `run_script` 명령으로 실행합니다. 실행하면 현재 데모 상태가 초기화됩니다. 기존 `VerifyHordeDemo.cs`는 Lane 맵에서 실행하는 회귀 검증이며, `ProbeHordeFlow.cs`는 맵 전환과 시작 버튼을 한 단계씩 시험하는 도구입니다.

```sh
unity command run_script --file Tools/VerifyDirectionalHorde.cs --entry VerifyDirectionalHorde.Main --project-path . --format json
unity command run_script --file Tools/VerifyHordeHud.cs --entry VerifyHordeHud.Main --project-path . --format json
unity command run_script --file Tools/VerifyAutomaticFire.cs --entry VerifyAutomaticFire.Main --project-path . --format json
unity command run_script --file Tools/VerifyTowerRoles.cs --entry VerifyTowerRoles.Main --project-path . --format json
```

`Tools/CreateHordeDemo.cs`와 `Tools/CreateHordeMaps.cs`는 최초 씬 생성용입니다. 기존 데모 씬이 있으면 덮어쓰지 않고 중단합니다.

## 스테이지 클리어

각 맵에서 1,500 → 3,000 → 5,000마리의 3개 스테이지를 진행합니다. 수량은 데모용 임시 값이며 HordeSimulation의 StageCounts에서 변경할 수 있습니다. 생성 속도를 바꿔도 총수량은 유지됩니다. 처치와 출구 통과를 합쳐 모든 적이 처리되고 체력이 남아 있으면 클리어됩니다. 통과한 적은 체력을 1씩 감소시키며, 체력 0은 즉시 패배로 우선 판정합니다.

Next stage는 포탑을 유지하고 체력을 회복한 다음 스테이지 설치 단계로 이동합니다. Start stage를 눌러야 다음 전투가 시작됩니다. Retry stage는 현재 스테이지를 다시 준비하며, 마지막 클리어 후 Play again은 1스테이지로 돌아갑니다. 맵을 변경하면 해당 맵의 1스테이지부터 시작합니다.

검증: Tools/VerifyStages.cs에서 고정 수량 제한, 마지막 적 처치 판정, 다음 스테이지 준비, 포탑 유지, 최종 클리어와 재시작, 통과 적 처리 및 재도전을 검사합니다. 기존 무한 생성 기준의 4,000마리 부하 검증 스크립트는 현재 스테이지 수량 제한과 호환되지 않습니다.
