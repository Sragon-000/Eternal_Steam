# HUD-08 원형 미니맵과 Esc 메뉴 및 건설 화면 축소 적용계획

상태: HUD-08A~E 적용·로컬 Unity Editor 통합 인수 완료. Esc 입력 보존 수정, 최종 297개 회귀, 두 씬 × 7해상도, 실제 macOS 한글/Tab/Esc 및 저장 재로드 결과는 [HUD-08E 통합 기록](../../Validation/2026-10-03-hud-08e-integration.md)을 참조한다. 다른 OS/배포 빌드는 이 완료 범위에 포함하지 않는다.

## 1. 목적과 현재 원인

전투 화면은 체력·통합 시계·원형 미니맵을 중심으로 유지한다. 일시정지와 저장은 Esc 메뉴로 모으고, 건설 화면은 지도 위에 배치할 공간을 확보한다. 기존 스타일, Tab 그룹 전환과 이징, 철도 18px 글자, 테스트 UI ON, 사용자 저장 보호를 유지한다. 연구 실험은 시작하지 않는다.

현재 `CanvasHudLayout`과 씬 저작 도구의 `ExpandedHeight=320` 때문에 하단 메뉴가 화면 높이의 약 44.4%를 차지한다. 800×600에서는 약 267px이며 여백·목표 안내·알림까지 위로 쌓인다. 화면 안에 들어오는 것과 지도 조작 공간이 충분한 것은 별도의 기준이다. 이전 7해상도 경계 검증만으로 이 문제를 해결했다고 판단하지 않는다.

미니맵은 `CanvasWorldMinimap`의 사각형 메시/좌표 판정이고, 카메라 입력 차단도 사각 RectTransform 범위를 사용한다. 원형 그림만 덮으면 투명 모서리가 입력을 막거나 원 밖 클릭이 카메라를 이동시킬 수 있다.

Esc는 `OpenWorldInput.Update`의 건설 취소/철도 초안 닫기와 `CanvasWorldHud.Update`의 입력 종료가 각각 읽는다. 일시정지·저장 메뉴 추가 전에 키 처리 소유권을 통합해야 한다.

근거: 현재 런타임 코드, `Tools/AuthorHud05.cs`, `Docs/Measurements/2026-10-02-hud-07/StartRegionSandbox-800x600-construction.png`. 이번 계획을 위해 Unity Play나 테스트를 새로 실행하지 않았다.

## 2. 목표 화면

| 화면 | 상시 표시 | 필요할 때 표시 |
|---|---|---|
| 전투 | 왼쪽 위 체력·시계, 오른쪽 위 원형 미니맵, Tab/Esc 작은 안내, 기존 테스트 조작 | Esc 메뉴 |
| 건설 탐색 | 왼쪽 기지 자원 목록, 아래 단일 행 건물 목록과 분류 | 선택 건물 상세, 비용 상세, 전력 상세 |
| 건물 배치 | 아래 선택 건물·누적 비용·확정/취소의 작은 작업 바 | 건물 목록 다시 열기, 상세 |
| 철도 관리 | 기존 전용 화면과 작은 건설/철도 전환 바 | 기존 화물·방어·노선 편집 |

중앙의 다중 행 목표문은 건설 화면에서 항상 펼치지 않고 상단의 1줄 요약 + ‘목표 보기’로 바꾼다. 단기 알림은 비상호작용 안내로 제한하며 작업 바 위에서 건물 미리보기를 가리지 않게 배치한다. 비용 부족·실패 사유는 작업 바에 남겨 사라지는 알림에만 의존하지 않는다.

## 3. 원형 미니맵

- 오른쪽 위 앵커를 유지한다. 2026-10-03 후속 요청에 따라 프레임 RectTransform을 화면 상단/우측 끝에 정렬하며, 스프라이트 자체의 투명 패딩은 보존한다. Esc 안내는 전투 화면에서 미니맵 아래로 배치한다. 정사각형 사각 프레임과 별도 제목 바를 원형 테두리로 교체한다.
- 기존 짙은 패널·금속 테두리·청록 포인트와 맞는 전용 원형 프레임 및 원형 마스크를 준비한다. 프레임에는 지도 픽셀을 그려 넣지 않는다. 생성한 프레임은 시각 검토 후 별도 저장된 uGUI Image로 적용한다.
- 시야 중심을 유지한다. 기존 150×150 투영의 내접원을 표시하므로 원의 동서/남북 지름이 월드 150, 반지름이 75이다. 사각 영역의 네 모서리는 더 이상 표시하지 않는다. 범위를 넓히는 변경은 하지 않는다.
- 지도 내부 지름 제안: `clamp(화면높이×0.24, 144, 256)` 물리 px. 작은 화면 144px부터 시작하고 프레임 두께는 별도 예산으로 둔다. 1:1 비율을 강제하고 해상도 변경 시 타원으로 늘어나지 않는다.
- 기존 지형 텍스처와 UV 갱신을 재사용한다. 저장된 원형 `Image + Mask` 아래에 기존 `MaskableGraphic`을 배치해 지형·마커·시야 윤곽을 함께 클리핑한다. 프레임은 raycast를 받지 않는다.
- 단일 원 내부 판정 함수를 raycast 필터, PointerDown/Drag, HUD의 카메라 입력 차단에 공통 사용한다. 정규화 중심에서 거리 제곱 <= 0.25인 점만 지도 입력으로 인정한다.
- 원 밖의 투명 모서리는 일반 월드 조작이 가능하다. 드래그를 원 안에서 시작한 경우에는 밖으로 나가도 월드 드래그로 넘기지 않고 지도 이동만 보류한다. 다시 안으로 들어오면 시작 시 투영으로 재개하고, PointerUp/그룹 변경/메뉴 열기로 종료한다.
- 원 밖 마커를 가장자리로 강제 이동시키지 않는다. 현재 `Pixel`의 좌표 clamp가 시야 윤곽을 가짜 가장자리 선으로 만들 수 있으므로 시야 선분의 정상 클리핑도 함께 검토한다.
- 맵 끝의 빈 공간, 지면 광선 실패 fallback, 중심·150 범위와 기존 방향 표현은 유지한다.

완료 기준: 원형 클리핑 일치, 원 밖 이동 0, 투명 모서리의 불필요한 차단 0, 원 경계 드래그 중 점프 0, 지형 텍스처 반복 생성 0. 각 기준을 좌표/입력 테스트와 실제 화면에서 확인한다.

## 4. Esc 일시정지·저장 메뉴

기본 동작은 ‘Esc를 누르면 즉시 정지 메뉴가 열리고, 다시 누르면 이전 상태로 돌아가기’로 제안한다. 기존 상단 일시정지/진행·저장 버튼은 상시 HUD에서 제거하고 작은 `Esc · 메뉴` 안내만 남긴다.

메뉴 구성: ‘돌아가기’, ‘게임 진행/일시정지 상태’, ‘저장’, ‘불러오기’, 기존 진행 정보와 개발 도구 진입. 기존 새 게임 기능은 보조 항목으로 유지하며 현재 확인 절차를 보존한다. 설정·종료처럼 요청하지 않은 신규 기능은 추가하지 않는다. 저장 가능 여부, 마지막 저장 시각, 불가 사유를 메뉴 안에서 보여 준다.

- 메뉴를 화면 중앙에 저장된 modal 계층으로 구성한다. 예시 너비 420~480px, 최대 높이는 화면 높이-48px. 작은 창에서는 내부만 스크롤한다.
- 어두운 배경은 전체 화면을 덮고 입력을 차단한다. UI 애니메이션은 unscaled 시간으로 짧게 실행한다. 열림 시작부터 닫힘 종료까지 아래 UI, 카메라, 월드, Tab, 테스트 버튼 실행을 막는다. 테스트 버튼 자체는 제거하지 않는다.
- `Clock.Paused`를 단순 반전하지 않는다. 메뉴가 열린 동안의 별도 정지 이유를 `SimulationPaused`에 포함하고, 기존 수동 일시정지·편집 정지·패배 상태를 유지한다. 돌아가기만으로 원래 정지 상태가 풀리지 않아야 한다. 기존 진행/일시정지 동작은 메뉴 내부에서 명시적으로만 변경한다.
- Esc 처리기는 한 곳에서 결정하고 그 프레임의 입력을 소비한다. 기존 건설 취소/철도 닫기에서 Esc를 분리한다. 명시적 취소 버튼과 기존 우클릭 취소는 유지한다.
- 메뉴를 열어도 건설 대기 항목·철도 초안·수량 입력·선택·스크롤은 보존한다. 진행 중 포인터 제스처만 중단하고 미확정 작업 전체를 취소하거나 확정하지 않는다.
- 한글 조합 중 Esc는 우선 조합 해제에 사용하고 메뉴를 동시에 열지 않는다. 조합이 끝난 후 다음 Esc로 메뉴를 연다. 조합 중이 아닌 입력은 값을 보존한 채 포커스를 잠시 해제하고 메뉴를 닫으면 유효한 입력에만 복원한다.
- 확인 대화상자가 메뉴 위에 있으면 Esc는 최상위 확인창만 닫는다. UI 그룹 이징 중 열렸다면 배경 상태 전환은 안정적으로 완료하되 입력을 차단한다.
- 저장은 기존 낮/전투/편집/투사체 등의 `CanSave` 제한을 유지한다. 정지 메뉴를 열었다는 이유로 야간 저장이나 초안 저장을 허용하지 않는다. 기존 검사에 포함되지 않은 철도 초안은 명시적으로 검사한다.
- 미확정 작업이 있는 불러오기/새 게임에는 폐기 확인이 필요하다. 취소하면 초안 그대로 메뉴로 돌아간다. 저장·불러오기 실패 시 메뉴와 정지 상태를 유지한다. 저장 데이터 구조는 이 작업으로 변경하지 않는다.

완료 기준: Esc 한 번당 한 동작, 메뉴 열기만으로 초안 유실/추가 결제/저장 0, 복귀 시 정지 이유 유지, modal 뒤 클릭·Tab·카메라·테스트 실행 0, 저장 금지 상태의 사유 표시.

## 5. 건설 하단 UI 재구성

### 상태별 구조

1. **목록 탐색:** 건설/철도 전환 + 건물 분류를 가능한 한 같은 줄로 묶고, 건물 카드는 아이콘·이름 중심의 단일 가로 행으로 표시한다. 넘치는 분류/목록은 가로 스크롤한다. 상세 설명은 카드마다 계속 표시하지 않는다.
2. **배치 중:** 카드를 고르면 목록은 아래로 접히고 작은 작업 바만 남는다. 선택 건물, 누적 대기 수, 지불 기지/핵심 비용, ‘확정’, ‘취소’, ‘목록’을 표시한다. 필요한 비용은 상세 버튼으로 전체 확인할 수 있고 부족 여부는 항상 보인다.
3. **기존 건물 선택:** 설명·업그레이드·회수는 오른쪽 상세 패널을 필요할 때 연다. 목록 카드 상세와 선택 건물 상세는 동시에 중첩하지 않는다. 좁은 화면에서는 사용자가 펼친 상세가 목록을 대체하며 둘 다 크게 쌓이지 않는다.
4. **철도 관리:** 건물 목록과 비용 상세는 접고 기존 철도 화면을 사용한다. 철도 초안의 확인·폐기·그룹 왕복 보존 규칙은 유지한다.

### 크기와 우선순위

- 탐색 dock는 바닥 여백 포함 화면 높이의 **30% 이하**, 배치 중 작업 바는 **18% 이하**를 인수 기준으로 제안한다.
- 800×600: 탐색 최대 180px, 배치 최대 96px. 1280×720: 탐색 최대 192px, 배치 최대 104px. 1920×1080: 탐색 최대 216px, 배치 최대 112px. 고해상도에서도 콘텐츠 길이를 이유로 높이를 계속 늘리지 않는다.
- 하단 중앙 앵커, 너비 `min(화면너비-32px, 1280px)`. 초광폭에서 빈 배경을 화면 양끝까지 늘리지 않는다. 안전 여백을 적용한다.
- 중요한 본문/버튼 글자는 실효 18px, 보조 정보는 최소 14px, 주요 버튼 높이는 최소 36px를 목표로 한다. 공간이 부족하면 설명/상세를 접거나 스크롤하고 글자를 줄여 맞추지 않는다.
- ‘확정/취소’는 상세 스크롤 밖의 고정 영역에 둔다. 작은 창에서는 2줄 작업 바를 허용하되 위 높이 상한을 지킨다.
- 자원 목록은 기존 기지 클릭 방식 유지. 좁은 화면에서는 세로 길이를 제한하고 내부 스크롤한다. 사용자가 펼친 기지/스크롤을 모드 변경 후 복원한다.
- 확정/취소 시 목록 탐색으로 복귀하며 마지막 분류·목록 위치를 유지한다. Tab 왕복으로 배치 상태를 몰래 종료하지 않는다.
- 접기/펼치기는 기존 0.24초 이징과 일관된 움직임을 사용한다. 전환 중 중복 입력을 차단하고 화면 가장자리 밖에 남은 투명 패널이 입력을 잡지 않도록 한다.

완료 기준: 하단 점유율 상한, 배치 중 중앙 화면 40% 폭 × 40% 높이에 고정 패널 없음, 필수 버튼 접근 가능, 긴 비용/설명에도 dock 높이 증가 없음, 카드 선택과 비용 확정의 기존 동작 보존. 중앙 공간 기준은 일반 배치 상태에 적용하고 사용자가 직접 연 modal/상세 화면은 별도로 검증한다.

| HUD-08D 건설 dock 축소 | 탐색/배치/상세 상태, 고정 액션 바, 목표/알림 위치 정리 | 점유율과 지도 조작 공간 충족 |
| HUD-08E 통합 인수 | 2씬×7해상도, 복합 입력/저장/철도 회귀 | 증거와 미검증 범위 기록 후 완료 판정 |

주요 대상: `CanvasHudLayout`, `CanvasWorldHud`, `CanvasWorldMinimap`, `OpenWorldInput`, `OpenWorldSandbox.SimulationPaused`, `HudModeGroups`, `GameplayHudWorkspace`, 저장 진입 제어 및 두 Sandbox 씬. 새 메뉴/상태 컴포넌트는 기존 소유권과 중복되지 않게 최소 구성한다. 기차 규칙·결제·저장 포맷은 보존한다.

각 단계는 저장된 기존 계층과 persistent callback을 재사용한다. 정적 UI는 Editor API로 씬에 저장하고 런타임 생성하지 않는다. 스프라이트 제작·적용은 구현 단계에서 수행한다. 변경 전 사본과 단계별 검증 기록은 프로젝트의 별도 HUD-08 증거 디렉터리에 남긴다.

## 7. 검증과 완료 판정

- 두 씬 × 800×600, 1024×768, 1280×720, 1920×1080, 2560×1080, 3840×1080, 3840×2160.
- 전투/건설 탐색/배치/선택 상세/철도/Esc 메뉴 각각 캡처하고 경계뿐 아니라 점유율·겹침·raycast·실효 글자 크기도 검사한다.
- 원 내부·정확한 경계·투명 모서리·맵 밖·원 밖 드래그·복귀·크기 변경 중 드래그·Tab/Esc 중단을 확인한다.
- 실행 중/수동 정지/건설 편집/철도 초안/전환 중/저장 오류/전투·야간에서 Esc를 검증한다. OS 한글 IME는 이벤트 주입 결과와 따로 기록한다.
- 긴 건물명·긴 역명·최대 수량·부족한 비용·기지 소실·확정/취소·정확한 1회 결제를 회귀 검증한다.
- 일반 저장과 분리된 프로젝트 내부 저장으로 Save/ContinueSaved를 실행한다. 기존 283개 통과 기록을 새 구현의 통과 수로 재사용하지 않는다.
- OpenWorldSandbox의 BaseRules 미사용은 제한으로 기록하고 캠페인 철도 검증을 통과했다고 표시하지 않는다.
- HUD-07의 남은 경계/IME/밀집 상태 인수는 이 변경 이후 최종 형상에서 수행한다. 이전 결과는 이력으로 보존한다.

별도의 외부 승인 작업은 없다. HUD-08A/B 결과와 남은 범위는 [적용 기록](../../Validation/2026-10-03-hud-08ab-escape-menu.md)에서 관리한다. 건설 dock·최종 통합 인수를 완료하기 전 HUD-08 전체를 완료 처리하지 않는다.
