# 회의록 정리와 다중 기지 운영 체계 적용 계획

작성: 2026-09-17. 근거: 사용자가 전달한 회의록과 현재 저장소의 정적 코드 검토. 이 문서는 구현 계획이며 이번 작업에서 게임 코드·에셋을 변경하거나 실행 검증하지 않았다. 아래 제안과 검증값은 회의에서 확정된 제품 규칙으로 취급하지 않는다.

## 1. 회의 내용 정리

| 항목 | 회의에서 제시한 방향 | 확정 수준 |
|---|---|---|
| 전력 / 에너지 | 서로 다른 체계로 구성하는 방안 | 검토안. 역할·단위·소비 방식 미정 |
| 포탑 공격 인식 | 원형 사거리 안의 적을 자동 인식하고 공격 | 적용 방향. 기존 방향 지정 중심 조작 변경 |
| 적의 건물 공격 | 넥서스 외에 포탑도 공격하는 적, 포탑 체력 추가 | 후속 기능. 대상 우선순위·수치 미정 |
| 다중 기지 | 지역별로 넥서스를 확장하고 기지마다 독립적인 Day/라운드 진행 | 적용 방향 |
| 지역 자원 | 넥서스에서 자원을 생산하며 지역에 따라 산출 자원이 다름 | 적용 방향. 기존 자원 건물 역할은 별도 정리 필요 |
| 스타트 지역 | 이번 주 임시 맵 제작 | 이번 주 작업 목표. 완성 맵·전체 월드 제작은 아님 |
| 기지 설치 구역 | 원형에서 정사각형으로 변경 | 적용 방향. 한 변 길이는 미정 |
| 월드 격자 | 시각적으로 표현 | 적용 방향. 현재 넥서스별 격자에서 확장 필요 |
| 외부 건설 / 가동 | 특수 건물로 기지 밖 배치를 지원. 어느 유효 범위에도 속하지 않으면 비작동 | 두 문장의 설치 허용 조건이 모호하여 아래 임시 해석 필요 |

**외부 건설의 권장 해석:** 일반 건물도 월드의 허용 지면에는 설치할 수 있으나 기지 또는 특수 건물의 유효 작동 구역 밖에서는 공격·생산하지 않는다. 특수 건물은 외부에 작동 구역을 제공한다. 만약 의도가 ‘특수 건물 범위가 있어야 외부에 설치 자체가 가능’이라면 설치 규칙만 교체한다. 이 차이를 확정하기 전에는 두 정책을 분리한 구조와 검증을 준비한다.

## 2. 현재 구현과 충돌하는 지점

| 현재 코드 / 상태 | 충돌 또는 재사용 가능 부분 | 조치 |
|---|---|---|
| `BuildAreaModuleDefinition`, `IBuildArea.Radius`, `NexusGridView` | 원형 판정·원형 격자에 결합 | 영역 형상 데이터를 분리하고 정사각형과 시각화가 동일 데이터를 사용 |
| `BuildingPlacementDefinition.RequiresBuildArea`, `GroundRule`, `CoverageRule`, 팩토리 검사 | 범위 밖이면 설치 자체를 거절 | 설치 조건과 가동 조건을 분리. 정의·실행 상태의 기존 bool도 명시적으로 이전 |
| `CanRecoverGround` | 범위 의존 건물이 남으면 넥서스 회수를 거절 | 범위 상실 시 비작동으로 전환하는 정책으로 이전. 기지 회수 자체의 허용 시점은 별도 규칙 |
| `NexusDestinationQuery` | `IBuildArea` 제공자를 넥서스로 간주 | `BaseId`와 기지 레지스트리를 참조. 특수 구역 제공자는 자동으로 적 목적지가 되지 않음 |
| `OpenWorldSandbox.Running`, `OpenWorldContent.LevelCap`, 공유 `ResourceBank` | 월드 하나의 진행 상태·해금 설정·재화 창고 | 기지별 진행/레벨과 지역 생산을 분리. 저장소 공유 여부는 정책으로 결정 |
| `BuildingServices`의 단일 `Nexus`, `Resources`, `LevelLimit` | 모든 건물에 같은 서비스가 전달됨 | 소속 기지 문맥과 월드 공용 서비스를 명시적으로 주입 |
| `NexusState`, `NexusModuleDefinition` | 기존 선택 모듈은 단일 목표 패배·회수 불가를 전제로 함 | 그대로 다중 기지에 재사용하지 않음. 기존 검증 씬에는 호환 동작 유지 |
| `WeaponRuntime.Valid`, 배치 입력의 방향 클릭 | 사거리 외에 부채꼴·사용자 지정 방향이 필요 | 원형 탐색과 자동 조준으로 변경. 특수 공격 전달 방식은 보존 |
| 기존 포탑 4종의 별도 공격 경로 | 신규 무기와 달리 무조건 연사 등 호환 동작 존재 | 오픈월드용 자동 표적 어댑터 추가. 기존 3개 맵은 기존 규칙 유지 |
| `HealthModuleDefinition`, `IDamageReceiver` | 공통 체력·피해·파괴 기능 존재 | 재사용하되 실제 오픈월드 넥서스/포탑 구성에 연결 |
| `HordeEnemyWorld.MoveAndIndex` | 목표 도착 즉시 제거 | 건물 공격 모드에서는 접근 → 공격 → 재선정. 기존 데모 도착 규칙은 별도 유지 |
| 지상 적 최초 생성의 직선 경로 검사 | 장애물 우회 기능 아님 | 공격 중 재목표 시 경로 정책 별도 검증. 막힌 길 통과를 경로 해결로 간주하지 않음 |
| 자원 생산 건물 7종 | 현재 건물별 직접 생산이 중심 | 넥서스 지역 생산을 먼저 도입하고 기존 건물은 검증 카탈로그로 보존. 삭제/중복 생산 전환을 임의로 하지 않음 |

토대 8×8m, 넥서스 8×8m, 2m 셀, Y축 45° 월드 격자, 임시 예약·확정·취소, 지면/토대 배치, 기존 적 배열·세대 번호·공간 조회는 유지할 수 있다. 이번 회의는 토대 필수화를 요구하지 않았으므로 토대 없는 포탑 설치도 유지한다.

## 3. 목표 구조와 계약

아래 이름은 제안이며 같은 책임의 기존 코드가 있으면 확장한다. 모든 기능을 하나의 매니저나 전역 이벤트 버스에 합치지 않는다.

| 모듈 | 책임 | 주요 입력 / 출력 |
|---|---|---|
| 월드 격자 | 좌표 변환, 셀 크기·회전, 지면/토대 점유 연결 | 기존 `BuildGrid`·`WorldGridGeometry` 재사용 |
| 영역 | 영역 형상, 포함 검사, 제공자 생명주기 | `AreaDefinition`, `IAreaQuery`; 제공자 ID·기지 ID·형상·유효 상태 |
| 설치 규칙 | 지형·경사·점유·예약·표면·설치 정책 | 기존 `IPlacementRule` 재사용 |
| 가동 상태 | 범위·전력·기지 상태 등 필요한 조건 평가 | `BuildingOperationalState`, 이유 플래그와 상태 변경 통지 |
| 기지 문맥 | 기지 식별·소속·레벨·지역·수명 | `BaseContext`, `BaseRegistry`, 안정적인 `BaseId` |
| 라운드 | 한 기지의 Day·단계·대기/전투/결과·스폰 요청 | `BaseRoundController`; 타 기지의 라운드를 변경하지 않음 |
| 지역 생산 | 넥서스 위치의 지역 판정과 생산 레시피 | `RegionDefinition`, `IRegionQuery`, 기존 생산·재화 계약 재사용 |
| 포탑 전투 | 원형 표적 탐색·유지·조준·공격 실행 | 기존 `ITargetQuery`, `TargetHandle`, 무기 전달 방식 재사용 |
| 적 전투 | 건물 표적·접근·사거리·공격 간격·재선정 | 건물 타겟 레지스트리, `IDamageReceiver`, 배열 기반 상태 |
| 전력 | 공급량과 수요, 연결 또는 서비스 구역, 가동 배분 | 선택 기능으로 설계. 구체 배분 정책은 미정 |
| 에너지 | 저장·획득·행동별 소비 | 재화 계약과 연동 가능한 별도 자원. 전력 용량과 혼용 금지 |
| 표현/UI | 월드 격자, 영역 테두리, 소속 기지, 가동 불가 이유 | 읽기용 상태를 표시하고 명령만 전달 |

### 설치 상태와 가동 상태

- 임시 배치: 예약과 미리보기만 존재. 생산·공격·영역 제공 없음.
- 확정 배치: 점유·체력·선택·회수 기능이 유지됨. 가동 조건을 별도로 평가.
- 비작동: 건물은 남고 공격·생산·지원 효과만 정지. 피격·선택·회수·상태 표시와 조건 재평가는 계속 가능.
- 파괴/회수: 등록·구독·점유·영역·표적 핸들을 해제.

`GameObject.SetActive(false)`나 전체 `BuildingInstance.Tick` 중단으로 비작동을 구현하지 않는다. 그러면 피격·조건 복원·UI까지 멈출 수 있다. 모듈별 가동 필요 여부를 명시하고 공격/생산에만 공통 가동 조건을 연결한다. 기존 `TickProduction`의 특정 무기 런타임 타입 검사도 이 단계에서 제거한다.

가동 불가 이유는 `범위 밖`, `전력 부족`, `기지 상실`, `단계 제한` 등을 독립적으로 표시한다. 에너지 부족은 특정 행동 실패 조건으로 분리할 수 있으며 모든 건물의 전역 가동 중지 사유로 고정하지 않는다.

### 영역과 격자

- 정사각형 영역은 월드 건설 격자와 같은 45° 방향을 사용하도록 제안한다. 건물 네 모서리 전체 포함, 경계 포함, XZ 기준 판정은 유지한다.
- 넥서스 외형 8×8m와 서비스 구역 크기는 별개다. 기존 반경 40m를 한 변 80m로 단순 전환하면 면적이 약 27% 늘어난다. 길이를 확정하기 전 비교용 설정으로만 사용한다.
- 영역 판정 데이터가 설치·가동·테두리·격자 강조를 모두 구동해야 한다. 시각화만 정사각형으로 바꾸지 않는다.
- 월드 격자는 카메라 주변 청크에만 생성/재사용하고 원거리 청크는 숨긴다. 오픈월드 전체를 셀별 GameObject로 생성하지 않는다.
- 넥서스별 격자 메시 중복을 월드 격자 하나로 대체한다. 기지/특수 구역의 유효 범위는 별도 테두리 또는 강조로 표시한다.
- 표시된 격자가 건설 가능 지형을 의미하지는 않는다. 강·산지·경사·충돌은 실패 이유로 표시한다.

### 기지 소속과 특수 건물

소속 기지와 현재 범위를 제공하는 건물은 별개다. 겹치는 영역에 있다고 가까운 넥서스로 매 프레임 소속을 바꾸면 생산·라운드·전력 계산이 흔들린다. 배치 확정 시 `OwnerBaseId`를 명시적으로 결정하고, 넥서스 소실 시 이전/고립 정책을 적용한다.

특수 건물은 새로운 기지가 아니며 기본적으로 별도 Day를 만들지 않는다. 영역만 제공하는 모듈과 기지 역할 모듈을 분리한다. 특수 건물이 범위 밖에서 스스로 가동될 수 있는지, 기존 기지 연결이 필요한지, 연쇄 확장을 허용하는지는 정책으로 둔다. 첫 검증은 **기지 소속을 가진 외부 전초 건물 1개가 독립적으로 주변 구역을 제공**하는 방식으로 제안한다. 최종 비용·전력 조건은 확정하지 않는다. 상호 의존하는 건물끼리 서로를 가동시키는 순환은 허용하지 않거나 명시적으로 판정해야 한다.

### 자동 공격과 적 공격

포탑 탐색은 XZ 원형 사거리 + 지상/공중 필터로 바꾸며 유효한 기존 타겟 유지, 같은 거리 ID 순 선택, 타겟 교체 시 쿨다운 보존을 유지한다. 방향 클릭은 제거하고 선택한 적을 향해 포신을 조준한다. 회전 속도와 조준 완료 후 발사 여부는 별도 검증값이다.

`Angle=360` 변경만으로 완료하지 않는다. 관통의 방향, 연사/레이저 추적, 투사체 발사점, 범위 표시, 기존 4종 어댑터, 입력 단계를 함께 수정한다. 광역·연쇄·관통·EMP는 각 전달 방식으로 유지한다.

적 공격은 먼저 넥서스 공격과 포탑 공격 적 각 1종으로 검증한다. 건물 표적 핸들은 기지/월드와 세대까지 구분하여 월드마다 같은 건물 ID를 쓰는 충돌을 피한다. 건물 파괴 후 타겟 재선정, 사거리 이탈 시 재접근, 기절 중 공격 차단, 비작동 포탑의 피격, 회수와 공격이 같은 프레임에 발생하는 경우를 처리한다. 적마다 MonoBehaviour를 추가하거나 이 작업을 이유로 DOTS/NavMesh로 전환하지 않는다.

### 기지별 Day와 지역 생산

`BaseId`별로 `DayIndex`, 단계, 타이머, 웨이브 진행, 지역 ID, 넥서스 레벨을 관리한다. A 기지가 Day 5여도 새 B 기지는 설정된 시작 Day(검증값 1)에서 시작한다. 한 기지의 결과가 다른 기지 타이머를 초기화하지 않는다.

스폰 요청과 적에 `OriginBaseId`를 기록한다. 라운드 소속과 현재 공격 대상은 별개로 두어 적이 다른 기지로 이동해도 원래 웨이브 집계가 깨지지 않게 한다. 여러 기지의 스폰 요청은 공용 활성 적 한도 안에서 공정하게 분배한다. 기지별 10만 배열을 따로 생성하지 않는다.

전역 월드 시간과 기지별 라운드 난이도는 분리한다. 밤이 월드 공통인지 기지별 전투 시간인지 회의에서 확정되지 않았다. 이전의 낮/밤 구상과도 여기서 조정한다. 화면 밖 기지의 진행, 전투 중 편집/일시정지, 패배의 영향 범위도 정책으로 분리한다.

넥서스 설치 지점에서 지역을 결정하고 `RegionDefinition`의 자원 레시피를 기지 생산에 연결한다. 지역 경계를 걸친 넥서스는 중심 셀 기준으로 판정하는 검증안을 사용한다. 저장소가 공용이어도 생산 출처 기지는 기록한다. 기존 자원 건물은 채굴 보조·정제·가공 등의 역할이 확정될 때 이전하고 그 전에는 제품용 자동 중복 생산에 연결하지 않는다.

## 5. 이번 주 권장 완료 범위

스타트 지역 임시 맵과 그 안에서 확인할 수 있는 최소 흐름에 집중한다.

1. 넥서스 설치 → 정사각형 구역과 월드 격자 표시.
2. 범위 안 포탑 설치 → 방향 클릭 없이 자동 공격.
3. 범위 밖 포탑 설치 → 비작동 사유 표시.
4. 외부 전초 건물 설치 → 포함된 포탑 가동, 전초 회수 → 비작동 복귀.
5. 두 번째 지역에는 다른 자원 데이터를 지정해 다음 단계의 다중 기지 검증 준비.

이 범위의 핵심 완료 조건은 ‘외부 설치 → 범위 제공 → 가동 전환’을 실제 게임 안에서 확인하는 것이다. 건물 공격 적·기지별 완전한 라운드·전력 경제는 후속 완료 범위로 남긴다.

## 7. 검증 계획

**영역·가동:** 정사각형 모서리·경계·음수 좌표·45° 정렬, 지면/토대 다중 셀, 미확정 제공자 제외, 여러 기지/전초 겹침, 전초 의존 순환, 비작동 건물 피격, 소유 기지 소실과 범위 복원, 공격/생산만 중지되는지 확인한다.

**설치·회수:** 외부 설치 허용 정책별 결과, 점유·예약 충돌, 일괄 실패 시 무반영, 공급자 회수 시 잔존 건물 비작동, 취소 시 원래 상태 보존, 재확정 전 조건 변경, 기존 넥서스 회수 거절 테스트의 기대값을 새 정책에 맞춰 이전한다.

**공격:** 원형 경계·뒤쪽 적·지상/공중 필터·유효 타겟 유지·쿨다운·슬롯 재사용, 포신 조준과 실제 관통 방향 일치, 기존 13종의 공격 의미 유지, 준비/비작동 상태에서 공격 금지를 검증한다.

**기지/적:** A/B 라운드 독립, 신규 기지 시작값, 지역 생산 레시피, 소속 기지와 현재 적 타겟 분리, 기절 중 적 공격 금지, 사망/회수 타겟 재선정, 화면 밖 정책, 여러 기지 스폰 공정성, 기지 파괴가 다른 기지를 즉시 패배시키지 않는지를 검증한다.

**저장:** 안정적인 기지 ID·지역·Day·진행·소속 건물·재화·에너지 저장, 삭제된 기지 참조 복원 정책, 기존 데모 키 보존. 새 형식 마이그레이션 성공 전에 이전 데이터를 지우지 않는다.

**성능:** 격자는 카메라 이동/청크 변경 시, 영역 의존성은 공급자·기지·위치 변경 시 갱신한다. 적 전체 × 건물 전체 탐색을 매 프레임 수행하지 않는다. 동일 환경/시드/배치에서 변경 전후 3회 CPU 중앙값·p95·최대값·할당·기지별 작업량을 비교한다. 4천/1만/10만 적을 공용 상한 내에서 측정하며 실제 렌더링 포함 프레임과 CPU 전용 수치를 구분한다. 기존 Editor의 할당 카운터 한계가 있으므로 지원되는 Profiler 계측을 검증하고 무할당을 추정하지 않는다. 사용자 지시에 따라 게임 빌드는 실행하지 않는다.

## 8. 문서·폴더 적용

공통 코드는 기존 `Assets/EternalSteam/Code` 아래 역할별 폴더에 배치하고 오픈월드 씬 조립만 `Tests/OpenWorld`에 둔다. 공통 코드가 `HordeTowerKind`나 특정 테스트 씬을 참조하지 않게 한다. 월드/지역/기지 정의는 `Content` 아래에 두고 씬은 `Assets/EternalSteam/Scene` 아래에서 관리한다. 기존 `OpenWorldSandbox`를 일괄 덮어쓰지 않고 새 스타트 지역 검증 씬과 이전 어댑터를 통해 단계적으로 연결한다.

## 후속 실행 상태

사용자 요청에 따라 원형 사거리 자동 공격과 포탑 방향 입력 제거를 먼저 적용했다. 다른 단계(정사각형 구역·외부 비작동·다중 기지 라운드 등)는 이 변경으로 구현된 것이 아니다. [현재 동작과 검증](오픈월드_테스트_공간.md#원형-사거리-자동-공격)을 참고한다.

### 2026-09-17 건설 기반 적용 작업

사용자가 외부 설치 허용·범위 밖 비작동을 선택했고, 전력·에너지를 이번 작업에서 제외했다. 기지 역할·정사각형 영역·가동 조건·월드 격자·전초 및 스타트 씬 적용 도구를 작성했다. 컴파일 검사는 통과했으나 원본 Editor 명령 연결 정보 누락으로 씬/에셋 생성과 플레이 검증은 아직 실행하지 못했다. 단계 완료로 간주하지 않는다. [구현 및 미완료 항목](회의_건설기반_적용상태.md)을 기준으로 이어서 검증한다.

### 원본 Editor 연결 복구 후 검증

스타트 지역 씬과 별도 카탈로그/전초/지역 에셋 생성을 완료했다. 건설 가동 회귀, 실제 클릭 배치와 회수, 선택 시 사거리 표시, 신규 9종·기존 4종 원형 공격, 수정 모드 전용 월드 격자, 씬 재시작 상태 검증을 통과했다. 사용자의 추가 지시에 따라 월드 격자는 수정 중에만 표시한다. 기지별 라운드·지역 생산·건물 공격 적·저장은 후속 범위이며, 전력·에너지는 제외 상태다. 상세 결과는 위 적용 상태 문서를 참조한다.
