# Eternal Steam

**3D 탑뷰 기지 건설·방어 게임의 Unity 프로토타입**입니다. 플레이어 캐릭터 없이 카메라를 이동하며 건물을 배치하고, 자원과 전력을 생산해 밤의 공세를 방어합니다.

현재 개발 기준은 **`StartRegionSandbox`의 단일 맵 플레이 루프**입니다. 고정 메인 기지에서 시작해 생산·방어 → 맵 에너지 확보 → 보스 → 오브 제작으로 진행하며, 안전 저장·복원과 메인 기지 파괴 후 새 게임을 지원합니다. 오픈월드 전체, 맵 이동과 최종 콘텐츠가 완성된 상태는 아닙니다.

최신화: **2026-09-25**. 아래 구현 상태와 이후 기획을 구분합니다. 콘텐츠 수치는 별도 언급이 없으면 검증용입니다.

## 바로 실행하기

1. 저장소를 복제합니다.

   ```sh
   git clone https://github.com/Sragon-000/Eternal_Steam.git
   ```

2. Unity Hub에서 `Assets`, `Packages`, `ProjectSettings`가 있는 프로젝트 폴더를 등록합니다.
3. **Unity 6000.3.14f1**로 열고 패키지 복원과 에셋 임포트가 끝날 때까지 기다립니다.
4. `Assets/EternalSteam/Scene/Tests/StartRegionSandbox.unity`를 엽니다.
5. **Play**를 누릅니다. 저장이 없으면 메인 기지가 자동 설치되고 시작합니다. 정상 저장이 있으면 복원 후 일시정지하며, 테스트 패널의 **계속 진행**으로 재개합니다.

시작 씬은 맵·메인 기지 모델·UI를 씬/프리팹/UXML로 저작해 두었습니다. 플레이 중 건설한 건물은 공통 배치 시스템에서 생성합니다. 적용 도구를 매번 실행해 씬을 다시 만들 필요는 없습니다.

### 개발 환경

| 항목 | 저장소 설정 |
|---|---|
| Unity Editor | 6000.3.14f1 |
| 렌더링 | URP 17.3.0 |
| 입력 | Input System 1.19.0 |
| 게임 UI | UI Toolkit, UXML/USS |
| 테스트 | Unity Test Framework 1.6.0 + `Tools` 검증 스크립트 |
| Editor 자동화 | Unity Pipeline 0.6.0-exp.1 / Unity CLI |

정확한 버전은 [ProjectVersion.txt](ProjectSettings/ProjectVersion.txt), [manifest.json](Packages/manifest.json), [packages-lock.json](Packages/packages-lock.json)을 따릅니다. Unity CLI는 검증·저작 자동화용이며 일반적인 Editor 실행에는 필요하지 않습니다. 이번 적용에서는 게임 빌드를 만들지 않았습니다.

## 플레이 방법

| 조작 | 동작 |
|---|---|
| WASD | 탑뷰 카메라 이동 |
| 마우스 휠 | 확대·축소. UI 위나 드래그 중에는 월드 줌 차단 |
| 수정 | 배치·회수 편집 시작. 다시 누르면 임시 설치와 회수 예정을 취소 |
| 인벤토리 항목 → 지면/격자 클릭 | 건물 임시 배치 |
| 확정 | 전체 작업을 재검증한 뒤 설치 또는 회수 |
| 수정 중 기존 건물 클릭 | 회수 예정 선택/해제. 확정 전에는 건물 유지 |
| 수정 중 빈 공간 사각 드래그 | 범위 안 회수 가능한 건물을 회수 예정으로 선택 |
| 방벽 선택 → 첫 클릭 → 두 번째 클릭 | 시작점과 끝점 사이를 격자 축에 맞춰 직선 임시 배치 |
| 방벽 도구 중 Shift + 드래그 | 사각형 회수 선택 |
| 일반 상태에서 포탑 클릭 | 선택 정보와 해당 포탑의 사거리 표시 |
| 미니맵 클릭·드래그 | 해당 위치로 카메라 이동, 기존 줌 유지 |
| 패널 접기/펼치기 | 상단은 위로, 인벤토리는 아래로 접기. 작업 상태 유지 |

- 월드 격자는 **수정 중에만** 표시합니다. 수정/시간 정지 중에는 시간·생산·추출·전투가 함께 멈춥니다.
- 방벽은 길게 누르는 방식이 아니라 **두 번 클릭**하는 방식입니다. 설치 불가 칸은 건너뛰고 실패 이유를 표시합니다.
- 임시 설치와 회수는 한 작업에 섞지 않습니다. 먼저 확정하거나 취소합니다.
- 입력창에 수량을 입력할 때 WASD 카메라 이동을 차단하며, UI 클릭은 월드 배치로 전달하지 않습니다.

### 첫 플레이 루프

1. 고정 위치의 메인 기지로 시작합니다. 메인 기지는 인벤토리에서 선택해 설치하지 않습니다.
2. **수정 → 자원 → 전력 발전기**를 메인 정면 구역에 배치하고 확정합니다.
3. 생산 건물과 방어 건물을 배치합니다. 포탑에는 전력 공급이 필요합니다.
4. 낮에 준비하고 밤의 자동 공세를 방어합니다. 날짜가 증가하면 일반 소환 예산이 증가합니다.
5. 추출과 처치로 맵 에너지를 90% 확보하면 밤에 보스가 출현합니다.
6. 보스 처치로 나머지 10%와 불완전 오브를 얻고, 상단 패널에서 완벽 오브를 제작합니다.
7. 안전한 낮에 저장하고 이후 이어서 진행합니다. 메인 기지가 파괴되면 해당 진행은 패배 처리됩니다.

## 현재 구현

### 기지·지형·건설

- 실제 시작 맵 인스턴스는 Y축 **45°** 방향이며, 2m XZ 정사각형 논리 격자를 사용합니다.
- 메인 기지는 기존 씬 모델 1개를 재사용합니다. 설치 영역은 **정면 가장자리에서 앞쪽 11×11칸**입니다. 지형 제한은 별도로 적용합니다.
- 토대는 8×8m / 4×4칸입니다. 토대 없이 유효한 지면에도 방어 건물을 설치할 수 있습니다.
- 외부 지면 설치를 허용하지만 기지/지원 영역 밖 건물은 비작동 상태가 됩니다. 피격·회수·물리적 차단은 유지합니다.
- 메인 공유 레벨과 서브 기지 개별 상태를 분리했습니다. 현 검증 설정의 서브 한도는 `min(메인 레벨 × 5, 10)`입니다.
- 예약·실제 점유를 구분하고 배치/회수를 일괄 확정 또는 취소합니다. 파괴 시 외형·점유·표적 등록을 해제하며 토대는 남습니다.

### 생산·전력·맵 에너지

| 상태 | 용도 |
|---|---|
| 일반 자원 | 자원 건물의 생산·변환 결과와 보유량/용량 |
| 기지 전력 | 발전기의 생산과 기지별 저장·연결·방어 건물 소비 |
| 맵 에너지 | 칸별 유한 추출과 처치 보상, 보스/오브 진행 |

세 상태를 별도 모듈로 관리합니다. 전력 부족은 건물을 파괴하지 않고 공격을 중단합니다. 칸별 에너지 잔량은 기지를 다시 설치하거나 저장을 다시 불러와도 복구되지 않습니다.

현재 시작 구성은 낮 300초/밤 180초, 첫 밤 100마리와 날짜당 +25의 일반 소환 예산을 사용합니다. 개발자 낮/밤 전환은 날짜를 유지하고 같은 날 예산을 중복 지급하지 않습니다. 낮에는 신규 일반 소환을 보류하며 남은 적은 계속 싸우고, 미소환 예산은 다음 밤으로 이어집니다. 날짜별 적 능력치 강화는 적용하지 않았습니다.

### 전투

- 포탑은 원형 사거리 안에서 자동 탐색·조준합니다. 회전 속도는 별도 모듈로 구성하며 무기별 공격 방식·필터·강화를 분리합니다.
- 냉각 포탑은 둔화시킨 적을 계속 붙잡지 않고 다른 대상을 탐색합니다.
- 지상 적은 주변 방어 건물을 우선하고 진로의 방벽/건물을 공격합니다. 공중 적은 방벽을 통과하며 방어 → 일반 건물 → 기지를 우선합니다.
- 적은 기지에 닿아도 사라지지 않습니다. 공격 거리 진입 뒤 1초를 기다린 후 **1초마다 피해 1**을 줍니다. 기절은 이동·공격을, 냉각은 이동만 제한합니다.
- 체력과 전투 역할은 건물 모듈로 지정합니다. 토대 자체는 공격 대상에서 제외합니다. 선택 정보에 체력을 표시하고 피격 효과를 제공합니다.
- 개발자 소환은 누적 요청 최대 **1억**, 동시 활성 최대 **10만**입니다. 최소 간격을 지키며 빈 슬롯으로 유입시키는 검증 기능입니다. 1억 동시 생성 또는 10만에서의 목표 FPS를 보장한다는 뜻은 아닙니다.
- 적은 배열/슬롯·세대 번호·공간 조회·인스턴싱을 사용하며 적마다 GameObject를 만들지 않습니다. 지형 우회 길찾기는 후속 범위입니다.

### 미니맵

우측 테스트 패널에 접이식 미니맵을 제공합니다. 지형 개요, 기지·건물·적 밀집도·보스와 카메라 화면 범위를 표시하며 클릭·드래그로 이동합니다. 월드 +Z가 위쪽이고 45° 맵의 실제 외곽을 반영합니다. 별도 렌더링 카메라 없이 제한된 주기로 갱신합니다. [구현·검증 상세](Docs/미니맵_적용결과.md)

### 안전 저장·복원·패배

기존 접이식 테스트 패널에서 **안전 저장 / 마지막 저장 이어하기 / 새 게임**을 사용합니다. 새 게임은 확인 후 실행합니다.

저장 조건은 낮, 편집/예약 없음, 살아 있는 적·보스 없음, 투사체·연쇄 공격 없음, 개발자 소환 대기 없음입니다. 전투 중 일시정지만으로는 저장할 수 없습니다.

- 초기 상태와 안전한 배치/회수/강화 확정 시 자동 저장합니다. 변경이 있으면 30초마다 안전 여부를 확인해 저장합니다.
- 건물 식별자·소속·위치·체력·레벨, 자원, 전력과 부분 정산, 생산/공격/추출 타이머, 시간, 야간 예산/난수, 보스/오브를 보존합니다.
- 전체 데이터를 검증한 후 복원하며 메인 모델을 중복 생성하지 않습니다. 완료 후 정지 상태에서 사용자가 재개합니다.
- 현재 슬롯 1개와 직전 정상 백업 1개를 사용합니다. 손상 복구 사실과 저장 실패 이유를 UI에 표시합니다.
- 미지원 버전/콘텐츠 구성과 잘못된 ID·점유·참조는 이어하기를 차단합니다. 자동 버전 마이그레이션은 아직 없습니다.
- 메인 파괴는 별도로 즉시 영구 기록합니다. **패배한 진행은 백업으로도 이어갈 수 없고 새 게임만 가능합니다.** 이전 파일은 조사용으로 보관합니다.
- 종료 시 안전 조건을 우회하지 않으며, 오프라인 생산이나 날짜 진행은 하지 않습니다.

파일 경로는 `Application.persistentDataPath/EternalSteam/SingleMap`입니다. `current.json`, `previous.json`, `failures`, `archive`를 기존 데모 저장과 분리합니다. 임시 파일을 작성·검증한 뒤 교체하며, 체크섬은 손상 감지용입니다.

강화 명령은 비용 정책을 주입할 수 있습니다. **현재 실제 콘텐츠는 검증용 무료**이며 임의 비용표/실제 재고 차감은 적용하지 않았습니다. 비용 미설정은 무료 정책과 구분합니다.

자세한 계약: [단일 맵 저장·복원](Docs/단일_맵_저장_복원.md).

### 모듈 개발 원칙

`BuildingDefinition`과 기능 정의 에셋은 공유 설정, `BuildingInstance`와 모듈 실행 객체는 개별 상태를 가집니다. UI 분류만으로 공격이나 차단 기능을 부여하지 않습니다. 카탈로그 등록으로 목록을 구성하고, 입력/UI는 배치·회수·강화 명령을 전달합니다.

배치, 대상 조회/피해, 내구도, 회전, 자원, 전력, 시간, 맵 진행, 저장을 계약과 모듈로 나눕니다. 공통 기반에는 기존 맵 enum·전역 진행 저장 의존성을 넣지 않고 어댑터에서 연결합니다. 새 상태 있는 모듈은 저장 상태와 검증 경로도 함께 정의해야 합니다. 소스 폴더 삭제나 실행 중 모듈 교체를 보장하는 구조는 아닙니다.

| `Scene/Tests/FoundationSandbox.unity` / `ModuleSandbox.unity` | 기반·모듈 검증 |
| `Scene/Demo/HordeDemo.unity` / `HordeWideFront.unity` / `HordePincer.unity` | 기존 3개 맵 데모 |

기존 데모는 별도 호환 흐름입니다. 로비 → 스테이지 → 배치 → 전투 → 보상으로 진행하고, 적의 처치와 출구 통과를 합쳐 모두 처리한 뒤 체력이 남으면 클리어합니다. 출구 통과는 체력을 깎고 체력 0이면 패배가 우선합니다. 오픈월드의 기지 타격·야간 공세·안전 저장과 혼동하지 않습니다.

기존 데모 진행은 PlayerPrefs `EternalSteam.Prototype.Progress.v1`을 사용하며, 새 단일 맵 저장이 이 키를 덮어쓰지 않습니다. 세부 구현은 `Code/LegacyDemo`, 검증 도구는 `VerifyPrototypeLoop.cs`와 `VerifyStages.cs`를 참고합니다.

## 검증과 측정

가장 최근 [안전 저장 검증 기록](Docs/Validation/2026-09-24-single-map-save.md)에서 실제 씬 재로드/Play 재진입, 건물 상태 왕복, 손상·미지원 파일, 패배 후 재시작, 비용 원자성과 자동 저장을 확인했습니다. [시작 루프 검증](Docs/Validation/2026-09-24-start-loop.md)은 고정 메인과 생산/방어/보스 연결을 다룹니다.

| 도구 | 주요 범위 |
|---|---|
| `VerifyMinimap.cs` | 지도 좌표·표식·클릭/드래그·입력 차단 |
| `VerifySingleMapSave.cs` | 안전 저장·복원·오류·패배·결제. 여러 진입점과 격리 저장 경로 필요 |
| `VerifyStartLoop.cs` | 고정 메인 121칸, 발전/생산/방어, 야간 보스/오브 |
| `VerifyHudFolds.cs` | 패널 콜백과 접기 중 임시 작업 보존 |
| `VerifyBasePowerIntegration.cs` | 전력 생산/부족, 회수 취소·확정 |
| `VerifyBuildingCombat.cs` | 공격 주기·표적·방벽·슬롯 재사용 |
| `VerifyDragConstruction.cs` / `VerifyDragMouseInput.cs` | 두 클릭 방벽과 사각 회수 선택 |

Editor가 원본 프로젝트에 연결된 상태에서 도구의 전제 조건을 확인하고 실행합니다.

```sh
unity command run_script --file Tools/VerifyStartLoop.cs \
  --entry VerifyStartLoop.Main --project-path /absolute/path/to/Eternal_Steam --format json
```

저장 검증은 Play 전에 Editor 환경 변수 `ETERNAL_STEAM_SAVE_TEST_ROOT`를 고유한 임시 폴더로 지정합니다. 제품 저장으로 검증 도구를 실행하지 않습니다. 순서와 정리는 [검증 문서](Docs/Validation/2026-09-24-single-map-save.md)를 따릅니다. `Tools/Apply*.cs`는 씬/에셋 변경 도구이므로 검증 스크립트와 구분합니다.

과거 결과를 현재 전체 테스트 통과로 간주하지 않습니다. 최근 검증은 Editor 컴파일·Play/씬 재로딩 기준이며, 게임 빌드와 OS 강제 종료 시험, 기존 데모 3개 맵 전체 플레이를 새로 수행한 것은 아닙니다.

성능은 [적 전투 최적화 결과](Docs/적전투_최적화_결과.md)와 [측정 원시 자료](Docs/Measurements)를 참고합니다. 전투 코어·소환 보조 경로·전체 Editor 프레임은 서로 다른 측정입니다. 코어 무할당 결과를 게임 전체 무할당이나 10만 적 목표 FPS 달성으로 해석하지 않습니다.
